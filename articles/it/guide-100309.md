# Claude API per principianti: guida pratica per iniziare

> Guida per principianti all'API Claude: configurazione, prima richiesta, scelta del modello, funzioni principali e pratiche per la produzione.



Tutto ciò che serve a uno sviluppatore per effettuare la prima chiamata all'API Claude: chiavi, Messages API, scelta del modello e concetti fondamentali per passare dalla prima richiesta alla produzione.

## Che cos'è l'API Claude

L'API Claude è la piattaforma per sviluppatori di Anthropic. Offre accesso programmatico ai modelli Claude tramite la Messages API, con prompt di sistema, uso di strumenti, trasmissione in streaming, visione e output strutturati.

La Messages API è un endpoint HTTP senza stato. Inviate un elenco di messaggi dell'utente e dell'assistente, un ID modello e un limite di token; Claude restituisce una risposta strutturata. Tra gli endpoint di supporto ci sono elaborazioni in batch, file e conteggio dei token.

- **Senza stato:** l'API non conserva memoria. Inviate di nuovo la cronologia della conversazione a ogni chiamata.
- **Scelta del modello:** cambiare modello significa in genere modificare l'ID del modello.
- **SDK:** le librerie ufficiali Python (anthropic) e TypeScript (@anthropic-ai/sdk) usano formati di richiesta corrispondenti.

Capire questa architettura aiuta a evitare un errore comune dei principianti: aspettarsi che l'API ricordi una richiesta precedente.

## Passaggio 1: ottieni una chiave e configura la Console

Vai su **console.anthropic.com**, crea un account o un'organizzazione per il tuo team e genera una chiave API nell'area delle impostazioni. Tratta la chiave come una password: conservala in una variabile d'ambiente e non inserirla mai nel controllo del codice sorgente.

Le richieste HTTP dirette usano l'header **x-api-key** e l'header **anthropic-version**. Gli SDK leggono automaticamente **ANTHROPIC_API_KEY** dall'ambiente, quindi la maggior parte del codice non gestisce direttamente la chiave.

- Crea chiavi separate per sviluppo, collaudo e produzione.
- Usa gli spazi di lavoro per isolare i progetti del team e la spesa.
- Imposta i limiti di utilizzo nella Console prima di distribuire le chiavi a un team più ampio.

## Passaggio 2: effettua la prima chiamata alla Messages API

Installa l'SDK con **pip install anthropic**, esporta la chiave ed esegui:

```
import anthropic

client = anthropic.Anthropic()
msg = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Explain REST in one paragraph."}],
)
for block in msg.content:
    if block.type == "text":
        print(block.text)
```

Sono obbligatori tre parametri: **model**, **max_tokens** (il limite massimo dell'output) e **messages**. La risposta contiene un elenco di blocchi di contenuto. Controlla il tipo di ogni blocco, invece di dare per scontato che sia testo semplice, perché l'uso degli strumenti e il ragionamento possono aggiungere altri tipi di blocco. L'oggetto **usage** riporta i token di input e output, che possono fungere da dati per monitorare i costi.

## I cinque concetti da approfondire

Dopo aver completato la prima richiesta, queste funzionalità coprono molte esigenze applicative:

- **Prompt di sistema** — un parametro di primo livello **system** che definisce ruolo, tono e regole, separato dai messaggi dell'utente.
- **Conversazioni a più turni** — aggiungi ogni risposta dell'assistente all'array dei messaggi e invialo di nuovo; il primo messaggio deve provenire dall'utente.
- **Streaming** — gli eventi inviati dal server trasmettono i token man mano che vengono generati, una funzione utile per interfacce di chat e output lunghi.
- **Visione** — passa immagini come blocchi di contenuto base64 o URL insieme al testo.
- **Uso degli strumenti** — definisci funzioni con schemi JSON; Claude può decidere quando chiamarle, mentre il tuo codice le esegue e restituisce i risultati.

Quando i costi contano, considera **memorizzazione nella cache dei prompt** e **elaborazione in batch**; usa gli **output strutturati** quando il codice a valle deve analizzare una risposta.

## Dal tutorial alla produzione

Passare da uno script funzionante a un'integrazione di produzione richiede disciplina ingegneristica:

- **Gestione degli errori:** distingui gli errori di limite di frequenza (429) dagli errori del server. La fonte afferma che gli SDK ritentano automaticamente con ritardo progressivo; consulta la documentazione pertinente dell'SDK per il comportamento attuale.
- **Visibilità dei costi:** registra **usage** di ogni risposta nel sistema di metriche.
- **Versionamento dei prompt:** tratta i prompt come codice: revisiona e versiona, quindi esegui test su un piccolo insieme di valutazione.
- **Blocco del modello:** richiama gli ID dei modelli dalla configurazione, così gli aggiornamenti sono deliberati e testati.

### Punti chiave

- La Messages API non conserva lo stato: invia di nuovo la cronologia della conversazione a ogni chiamata.
- L'autenticazione HTTP diretta usa l'header x-api-key; gli SDK possono leggere ANTHROPIC_API_KEY dall'ambiente.
- I tre parametri obbligatori della richiesta sono model, max_tokens e messages.
- Comincia con Opus 5.5 e confronta le alternative sui tuoi dati.
- Prompt di sistema, trasmissione in streaming, visione, uso degli strumenti e cronologia a più turni supportano molti schemi applicativi.
- Registra l'utilizzo dei token per monitorare i costi e pianificare la capacità.

## FAQ

### Devo conoscere il apprendimento automatico per usare l'API Claude?

No. L'API Claude è un'API REST con SDK ufficiali per Python e TypeScript. Se sai chiamare un endpoint HTTP e analizzare JSON, puoi sviluppare con Claude. Progettazione dei prompt, gestione degli errori e controllo dei costi sono competenze ingegneristiche utili; non serve la teoria dell’apprendimento automatico per effettuare la prima chiamata API.

### Quale modello Claude dovrebbe scegliere un principiante?

Anthropic consiglia di cominciare con Claude Opus 5.5 (ID API `claude-opus-5-5`) per la maggior parte dei carichi di lavoro. Quando i tuoi prompt sono stabili, confronta gli altri modelli sui tuoi dati.

### L'API Claude ricorda le conversazioni precedenti?

No. La Messages API non conserva lo stato. La tua applicazione conserva la conversazione e invia di nuovo l'intera cronologia dei messaggi a ogni richiesta. In questo modo controlli il contesto, puoi ridurre o riassumere i turni più vecchi e puoi combinare la cronologia con il memorizzazione nella cache dei prompt.
