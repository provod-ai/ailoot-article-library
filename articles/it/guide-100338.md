# Progettare strumenti per agenti IA: lezioni per i flussi di lavoro Claude Code

> Una guida pratica per definire e testare strumenti per agenti IA, con esempi di flussi di sviluppo.



A un agente IA serve più di un buon modello: servono strumenti che possa scegliere, comprendere e usare entro i confini di un compito. Questa guida mostra come progettare tali interfacce, usando i flussi di sviluppo come esempio pratico.

## Parti da un compito osservabile

Descrivi ciò che l'agente deve realizzare prima di decidere quali strumenti rendere disponibili. Per una domanda su un repository, il compito potrebbe essere trovare dove viene letta un'impostazione e citare i file pertinenti. Un insieme adatto potrebbe consentire all'agente di elencare i file, cercare testo e leggere file selezionati; per rispondere non ha bisogno del permesso di distribuire nulla.

Annota il risultato atteso e le azioni fuori ambito. Uno strumento è utile quando input e output aiutano l'agente a prendere la decisione successiva e l'applicazione può verificare che l'azione sia consentita.

## Definisci un contratto chiaro per ogni strumento

La descrizione di uno strumento deve indicare cosa fa, gli input richiesti e la struttura del risultato. Usa nomi e descrizioni dei parametri distinti per strumenti con scopi simili. Se un'operazione ha un limite significativo, descrivilo: per esempio, uno strumento di ricerca potrebbe restituire un elenco limitato di percorsi corrispondenti anziché il contenuto di ogni file.

Per uno strumento di ricerca testuale, una richiesta illustrativa potrebbe contenere una query e una directory. Il risultato potrebbe includere percorsi e numeri di riga corrispondenti. L'applicazione deve convalidare la directory e gestire esplicitamente percorsi mancanti o ricerche fallite. Una richiesta ben formata non dimostra che la risposta trovata sia corretta.

## Bilancia flessibilità e controllo

Una shell generica può supportare molti compiti, ma espone anche un ampio insieme di azioni. Uno strumento più circoscritto può rendere più comprensibile un'operazione comune e limitarne l'azione. La scelta dipende dal compito, dall'ambiente e dalle autorizzazioni disponibili; più strumenti non producono automaticamente risultati migliori.

Mantieni l'insieme iniziale abbastanza piccolo da poterlo esplorare. Aggiungi uno strumento specializzato quando errori osservati o lavoro ripetuto lo giustificano. Se uno strumento può modificare dati o contattare un servizio esterno, rendi visibile questo effetto nella descrizione e applica nell'applicazione le autorizzazioni necessarie.

## Chiedi le informazioni mancanti al momento giusto

Un agente non dovrebbe inventare una decisione mancante. Se un compito dipende davvero da informazioni che non riesce a trovare, una domanda strutturata può presentare le scelte pertinenti e spiegarne le conseguenze. Se c'è lavoro indipendente pronto, il processo può continuarlo mentre attende la risposta.

Formula domande specifiche. Per esempio, se un rapporto richiede un intervallo di date non fornito, chiedi l'intervallo invece di far ripetere l'intero incarico. Non usare una domanda al posto della verifica del contesto disponibile.

## Testa insieme strumento e agente

Crea un piccolo insieme di compiti rappresentativi: richieste ordinarie, input ambigui, file non disponibili e tentativi di usare uno strumento fuori dall'ambito previsto. Esamina lo strumento scelto, gli argomenti passati, il risultato restituito e la risposta finale. Una chiamata API riuscita può comunque restituire dati incompleti: verifica quindi la risposta rispetto alle prove sottostanti.

Per diagnosticare un errore ricorrente, modifica una parte dell'interfaccia alla volta. Registra la versione della descrizione dello strumento e ripeti il test pertinente. Per azioni con effetti esterni, verifica un risultato incerto prima di riprovare: un nuovo tentativo può ripetere un'azione già riuscita.

## Applica le idee a un flusso di sviluppo

Claude Code supporta flussi di lavoro che combinano strumenti e istruzioni riutilizzabili. Consulta la [documentazione aggiornata sull'uso degli strumenti Claude](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview) per il contratto API e la [documentazione delle skill di Claude Code](https://code.claude.com/docs/en/skills) per l'organizzazione delle istruzioni riutilizzabili. Disponibilità e interfacce esatte possono cambiare: verifica la documentazione della versione in uso.

Le stesse domande di progettazione valgono per i vari framework di agenti: cosa richiede il compito, cosa può osservare l'agente, cosa può modificare ciascuno strumento e come verificherai il risultato?
