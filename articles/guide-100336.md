# Introducing Managed Agents in the Gemini API

> A practical guide to Gemini API managed agents: choose tasks, review results, and plan for cost, privacy and failures.



A request to a language model usually produces an answer; an agent can also take intermediate steps towards an outcome. For example, it might inspect data, write code, run that code and return a report. Google’s managed agents provide a hosted workspace for this kind of task through the Gemini API. The feature is a preview, so check the current documentation and availability before building it into a production workflow.

This guide explains how to choose a first task, assess the result and plan for the operational work around a managed agent. Google’s [Gemini API documentation](https://ai.google.dev/gemini-api/docs) provides the current request examples and supported agent identifiers.

## What is managed by the provider?

In the managed-agent approach, the provider runs the agent environment and supplies tools the agent can use. Google describes a remote sandbox in which its Antigravity agent can work with files, execute code and use the web. Your application still needs to define the objective, provide appropriate inputs and decide whether the returned result is acceptable.

A hosted environment is useful when a task needs several steps and an intermediate workspace. It is not a substitute for an application’s authorization, review or data-handling decisions. Check which tools and environment settings are available to your project and version before relying on them.

## Pick a bounded first task

Start with a task whose result can be checked without trusting the agent’s explanation. A small CSV summary is a good example: provide a non-sensitive sample, ask for a table of totals and specify the output format. Calculate a few totals independently and compare them with the result.

A useful task description includes:

- The input and what each field means.
- The intended output, such as a summary and a CSV file.
- Rules for missing or invalid values.
- A boundary on the data and tools the agent may use.
- Checks the recipient can perform before using the result.

For example: “Summarize this sample sales CSV by month and currency. Do not combine currencies. List rows with missing dates separately and provide the calculations used for each total.” Avoid asking it to send messages, change production data or take other external actions in the initial test.

## Run and inspect an interaction

Use Google’s [getting-started guide](https://ai.google.dev/gemini-api/docs/get-started) to configure the SDK and credentials, then follow its managed-agent example. The example supplies an agent identifier, an input and a remote environment. Use the identifier currently documented by Google rather than assuming an old preview identifier remains available.

Inspect more than the final paragraph. Check the returned status, the output and any files you intend to use. For a data task, compare the numbers with the source; for a generated script, review and test it in a controlled environment. If the task depends on information from the web, open the cited sources and check that they support the claims. A polished result can still contain an error.

If you continue work across interactions, follow Google’s documented environment and interaction lifecycle. Keep the relevant identifiers with your application’s job record and handle expiry or failure explicitly; do not assume a workspace will persist indefinitely.

## Give a custom agent clear instructions

Google also documents ways to supply custom instructions, skills and data to managed agents. Use those facilities to describe the job and output requirements, not to embed secrets in a document. For a reporting task, instructions might define how to group data, how to label uncertainty and what to do when a calculation cannot be completed.

Keep instruction files under version control and review changes like application code. Test a new version against a small set of representative inputs, including empty files, unexpected values and a request outside its intended scope. Record the version and input used for each evaluation so that a changed output can be investigated.

## Plan for cost, privacy and failure

A multi-step agent may make several model calls or use tools before returning a result. Review Google’s [pricing page](https://ai.google.dev/gemini-api/docs/pricing) and the limits for your project before a trial; charges and preview terms can change. Measure usage on representative tasks and set an application-level budget appropriate to your workload.

Send only data that the workflow is permitted to process. Treat retrieved pages and uploaded files as untrusted input, and review generated code before running it outside the sandbox. Define what happens when a task times out, a tool fails or the agent returns an incomplete result. Retrying a task with side effects can repeat those effects, so reconcile the original operation before attempting it again.

## When should you use a managed agent?

A managed agent is worth evaluating for bounded research, analysis or file-generation tasks where several tool steps are helpful and a person or automated check can verify the output. A direct model request or ordinary application code may be easier to operate for a single predictable transformation. Compare the approaches on quality, latency, cost and the amount of review your use case needs.
