# Textklassifizierung mit einem LLM

> Ein praktischer Leitfaden zur Textklassifizierung mit einem Sprachmodell, zur Auswahl von Labels, zur Prüfung vorgeschlagener Änderungen und zur Kontrolle der Ergebnisse.



Ein Sprachmodell kann Texte klassifizieren, indem es jedem Eintrag Labels zuweist. Dieser Leitfaden erklärt, wie Sie Labels definieren, mit unsicheren Fällen umgehen und messen, ob die Ergebnisse nützlich sind.

## Die Entscheidung festlegen

Beginnen Sie mit einer Frage, die praktische Folgen hat. Ein Supportteam könnte Nachrichten zum Beispiel in `billing`, `technical` und `other` einteilen, um sie an die richtige Warteschlange zu leiten. Entscheiden Sie, ob jede Nachricht ein Label oder mehrere erhalten kann. Erklären Sie jedes Label anhand von Beispielen, darunter ähnlich aussehende Fälle, die in verschiedene Gruppen gehören.

Behalten Sie eine Option `other` oder eine manuelle Prüfung für Einträge vor, die nicht passen. Eine erzwungene Auswahl kann einen übersichtlichen Bericht erzeugen und zugleich eine schlechte Taxonomie verdecken. Bei Entscheidungen mit Auswirkungen auf Menschen oder erheblichen Folgen sollte ein Mensch beteiligt bleiben.

## Ein vorhersehbares Ergebnis anfordern

Geben Sie dem Modell den Text, die Labeldefinitionen und das gewünschte Ausgabeformat. Behandeln Sie den zu klassifizierenden Text als Daten, nicht als Anweisung an das Modell. Eine Nachricht wie „Ignoriere die Labels“ bleibt beispielsweise der zu klassifizierende Eintrag; sie darf die Aufgabe nicht ändern.

Ein Ergebnis könnte so aussehen:

```json
{"label":"billing","reason":"Die Nachricht fragt nach einer Rechnung."}
```

Dies ist ein illustratives Ergebnis und keine tatsächliche Modellantwort. Prüfen Sie vor der Verwendung, ob sich die Ausgabe syntaktisch analysieren lässt, die erwarteten Felder enthält und ein erlaubtes Label nutzt. Ein gültiges Format allein bedeutet nicht, dass die Klassifizierung korrekt ist. Die Unterstützung für schemafestgelegte Ausgaben unterscheidet sich je nach Modell; prüfen Sie die Dokumentation des verwendeten Modells und der API.

## Das Labelset verbessern

Beginnen Sie mit einer überschaubaren Zahl von Kategorien und prüfen Sie Beispiele, die unter `other` fallen oder wiederholt zu Meinungsverschiedenheiten führen. Sie können eine fehlende Kategorie, eine unklare Definition oder zwei überlappende Labels aufdecken. Schlagen Sie Änderungen anhand repräsentativer Beispiele vor und lassen Sie neue Definitionen vor breiter Anwendung von einer prüfenden Person freigeben.

Ein Modell kann außerdem versuchsweise neue Labels und Zusammenlegungen vorschlagen. Kennzeichnen Sie geschützte Kategorien, die getrennt bleiben müssen, und prüfen Sie jede vorgeschlagene Änderung anhand dieser Vorgaben, bevor Sie die Taxonomie aktualisieren.

Wenn zwei Kategorien ähnlich erscheinen, vergleichen Sie vor einer Zusammenlegung, welche Entscheidungen sie unterstützen. Fehlgeschlagene Zahlungen und Erstattungsanfragen betreffen etwa beide Geld, können aber unterschiedliche Maßnahmen erfordern. Bewahren Sie für den Arbeitsablauf wichtige Unterscheidungen und dokumentieren Sie für jede Änderung der Taxonomie eine Version.

## Leistung vor der Skalierung prüfen

Erstellen Sie eine Stichprobe, die die tatsächliche Mischung der Nachrichten einschließlich seltener und mehrdeutiger Fälle abbildet. Lassen Sie Menschen sie anhand derselben Definitionen mit Labels versehen, Unstimmigkeiten klären und die vereinbarten Labels als Referenz aufbewahren. Vergleichen Sie die Modellergebnisse damit und untersuchen Sie Fehler je Kategorie; eine Gesamtgenauigkeit kann eine schwache Kategorie verdecken.

Testen Sie Änderungen an Prompt, Modell oder Taxonomie auf einem separaten Evaluierungsdatensatz. Überwachen Sie die Ergebnisse über die Zeit, da sich Sprache und Zusammensetzung eingehender Texte ändern können. Geben Sie unsichere oder ungültige Ergebnisse zur Prüfung weiter, statt unbemerkt ein Label zuzuweisen.

## Eingaben schützen und den Ablauf planen

Senden Sie nur die für die Aufgabe benötigten Informationen und behandeln Sie sensible Datensätze gemäß den Regeln Ihrer Organisation. Testen Sie bei einer großen Sammlung zuerst eine kleine repräsentative Charge, dokumentieren Sie Fehler und legen Sie fest, wie sich die Verarbeitung ohne Verlust oder Duplikate fortsetzen lässt. Messen Sie Zeit und Kosten des tatsächlichen Ablaufs, bevor Sie das Volumen erhöhen.

Das Ziel ist nicht allein die Vergabe von Labels. Es geht um einen wiederholbaren Entscheidungsprozess, dessen Definitionen, Ausnahmen und Fehler geprüft werden können.
