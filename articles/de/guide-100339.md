# Gemini: Zwischen App und API wählen

> Ein praktischer Leitfaden zur Wahl zwischen Gemini-App und API, zur Bewertung von Modellen und zur Schätzung der Nutzungskosten.



Gemini lässt sich über Googles App für Verbraucher nutzen oder über eine API in Software integrieren. Der passende Einstieg hängt davon ab, ob Sie eine Aufgabe selbst erledigen oder einen wiederholbaren Ablauf für andere entwickeln möchten.

## Mit der Aufgabe beginnen

Für eine einmalige Aufgabe, etwa den Entwurf einer Nachricht oder die Entwicklung einer Idee, bietet eine interaktive App Raum für Fragen und die Verfeinerung der Antwort. Prüfen Sie das Ergebnis, bevor Sie sich darauf verlassen: Eine flüssige Antwort kann Fehler enthalten, Kontext auslassen oder eine Quelle falsch zitieren.

Eine API ist nützlich, wenn eine Anwendung im Rahmen eines Ablaufs Eingaben senden und Ausgaben verarbeiten muss. Eine Supportanwendung könnte beispielsweise ein Ticket für eine prüfende Person zusammenfassen. Der Entwickler muss Anweisungen, Datenzugriff, Fehler und die Anzeige oder Speicherung der Ergebnisse behandeln.

App und API sind unterschiedliche Produkte. Gehen Sie nicht davon aus, dass eine Funktion, Grenze, ein Abonnement oder eine Dateneinstellung des einen automatisch im anderen verfügbar ist. Prüfen Sie Dokumentation und Einstellungen des Produkts und Kontos, das Sie tatsächlich nutzen.

## Ein Modell für die Aufgabe wählen

Beginnen Sie mit einigen repräsentativen Beispielen, statt ein Modell allein nach seinem Namen auszuwählen. Nehmen Sie für eine Zusammenfassung eine kurze und eine lange Nachricht sowie einen Fall mit fehlenden Informationen auf. Legen Sie fest, was eine gute Antwort bewahren muss, was sie nicht erfinden darf und wie lang sie sein soll.

Umfasst eine Aufgabe Bilder, Audio oder andere Eingaben, prüfen Sie, ob das konkrete Modell und der Endpunkt das benötigte Format unterstützen. Unterstützte Modalitäten, Kontextgrenzen und Verfügbarkeit können sich je nach Modell unterscheiden und ändern. Aktuelle Optionen und Anfrageformate finden Sie in Googles [Gemini-API-Dokumentation](https://ai.google.dev/gemini-api/docs).

## Kosten anhand einer realistischen Stichprobe schätzen

Erfassen Sie für einen API-Ablauf die Ein- und Ausgabemenge einer kleinen repräsentativen Auswahl von Anfragen. Multiplizieren Sie die gemessene Nutzung mit den jeweiligen veröffentlichten Preisen und berücksichtigen Sie alle zutreffenden Ein- und Ausgabetypen. Schätzen Sie dann, wie häufig der Ablauf ausgeführt wird, und planen Sie Spielraum für Wiederholungen und unterschiedliche Antwortlängen ein.

Betrachten Sie das Ergebnis als Schätzung, nicht als garantierten Rechnungsbetrag. Prüfen Sie die aktuellen [Gemini-API-Preise](https://ai.google.dev/gemini-api/docs/pricing), Kontingente und Abrechnungseinstellungen Ihres Kontos. Für ein App-Abonnement und die API-Nutzung können unterschiedliche Bedingungen gelten.

## Vor der Skalierung evaluieren

Vergleichen Sie Ergebnisse mit Beispielen, die Menschen geprüft haben. Prüfen Sie bei jeder Antwort die Fakten anhand der Eingabe, das gewünschte Format und aufgabenspezifische Regeln. Beziehen Sie schwierige Fälle sowie solche ein, die das Modell ablehnen oder an einen Menschen weitergeben sollte. Eine gültig aussehende Antwort ist nicht unbedingt richtig.

Dokumentieren Sie Fehler und ändern Sie jeweils einen Teil des Ablaufs: Anweisungen, Eingabevorbereitung, Modell oder Ausgabevalidierung. Wiederholen Sie nach einer Änderung denselben Testsatz. Ändern sich das Modell oder die Art der Eingangsdaten, bewerten Sie das Ergebnis erneut, statt die vorherige Evaluierung unverändert vorauszusetzen.

## Daten und Fehler bewusst behandeln

Senden Sie nur die für die Aufgabe nötigen Daten und prüfen Sie vor der Nutzung sensibler Informationen die Datenverarbeitungseinstellungen des jeweiligen Produkts. Validieren Sie Ausgaben, bevor eine Anwendung danach handelt. Planen Sie Ratenbegrenzungen, Timeouts und unvollständige Ergebnisse ein; zeigen Sie eine handlungsfähige Fehlermeldung oder leiten Sie den Fall zur Prüfung weiter, statt einen Fehler stillschweigend als erledigte Aufgabe zu behandeln.

Halten Sie bei Anfragen, die externe Aktionen auslösen können, den Vorgang fest und prüfen Sie seinen Status vor einem erneuten Versuch. Eine auf dem Übertragungsweg verlorene Antwort beweist nicht, dass die Aktion fehlgeschlagen ist.
