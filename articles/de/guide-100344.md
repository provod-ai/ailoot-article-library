# Einen LLM-Judge auf Verzerrungen testen

> Ein praktischer Leitfaden zum Testen von LLM-Judges auf Reihenfolge-, Stil- und Selbstbevorzugung sowie zur Interpretation der Ergebnisse.



Ein LLM-Judge kann helfen, offene KI-Ausgaben zu bewerten. Sein Urteil kann sich aber aus Gründen ändern, die nichts mit der zu messenden Qualität zu tun haben. Kontrollierte Vergleiche können einige dieser Schwächen aufdecken, bevor Sie den Judge in einem Evaluierungsablauf einsetzen.

## Festlegen, was der Judge bewerten soll

Wählen Sie ein Kriterium und definieren Sie es so, dass eine prüfende Person es kontrollieren kann. Zum Beispiel: Nennt eine Antwort die in der vorgelegten Richtlinie belegte Kündigungsfrist? Geben Sie dem Judge und den menschlichen Prüfenden dieselbe Frage, dasselbe Quellenmaterial und Kriterium. Halten Sie fest, was als bestanden, nicht bestanden und unsicher gilt.

Sammeln Sie Beispiele, die die tatsächliche Aufgabe abbilden, einschließlich schwieriger und mehrdeutiger Fälle. Lassen Sie Menschen eine repräsentative Stichprobe kennzeichnen und Abweichungen klären. Ein menschliches Label ist eine Referenz für den Test und keine Garantie, dass jeder Fall eine einzige offensichtliche Antwort hat.

## Prüfen, ob die Reihenfolge das Ergebnis verändert

Legen Sie einem paarweise vergleichenden Judge dieselben zwei Antworten in beiden Reihenfolgen vor, während Frage, Quelle und Kriterien unverändert bleiben. Ordnen Sie das Urteil der jeweiligen Antwort zu, nicht ihrer Bildschirmposition. Zählen Sie, wie oft die bevorzugte Antwort bei geänderter Reihenfolge wechselt, und untersuchen Sie diese Fälle.

Eine zufällige Reihenfolge kann die systematische Häufung einer Position über einen Datensatz verringern, beweist aber nicht, dass Positionsverzerrung verschwunden ist. Ändert die Reihenfolge das Ergebnis, können Sie das Paar zur Prüfung weitergeben oder die Instabilität neben dem Vergleich berichten.

## Stil und Inhalt trennen

Erstellen Sie Testpaare mit unterschiedlicher Darstellung, die die für das Kriterium relevanten Fakten bewahren. Vergleichen Sie zum Beispiel eine knappe belegte Antwort mit einer längeren Version ohne zusätzliche relevante Belege. Lassen Sie vor der Verwendung prüfen, ob die beabsichtigte Qualität tatsächlich gleichwertig ist.

Bevorzugt der Judge einen Stil, untersuchen Sie seine Erklärung und das konkrete Bewertungsschema. Ergänzen Sie gegebenenfalls Beispiele und klarere Kriterien und testen Sie erneut mit Beispielen, die nicht zur Überarbeitung des Prompts verwendet wurden. Eine bei einer Aufgabe oder einem Modell beobachtete Präferenz gilt nicht automatisch für jeden Judge.

## Auswirkungen von Modell und Prompt prüfen

Entfernen Sie beim Vergleich von Ausgaben verschiedener Modelle unnötige Kennzeichnungen aus dem zu bewertenden Material. Testen Sie eine Stichprobe mit mehreren Judges oder menschlichen Prüfenden, wenn die Entscheidung es erfordert. Ein Modell, das seine eigene Ausgabe bewertet, kann diese bevorzugen; ein anderes Modell kann eigene Verzerrungen aufweisen. Keine der beiden Optionen ersetzt die Validierung des tatsächlichen Ablaufs.

Versionieren Sie Bewertungsmodell, Prompt, Beispiele und Ausgabeformat. Ändern Sie bei der Diagnose einer Verschiebung jeweils eine Komponente und vergleichen Sie Ergebnisse auf einem zurückgehaltenen Datensatz. Eine kurze Begründung kann helfen zu erkennen, warum sich ein Urteil geändert hat; sie ist selbst eine Modellausgabe und muss anhand der Belege geprüft werden.

## Über die Nutzung des Ergebnisses entscheiden

Messen Sie Fehler und Abweichungen anhand von Menschen geprüfter Beispiele, darunter Fälle, in denen eine falsche Freigabe oder Ablehnung kostspielig wäre. Nutzen Sie deterministische Prüfungen für Eigenschaften, die ein Programm direkt verifizieren kann, und geben Sie unsichere oder folgenreiche Fälle an qualifizierte Prüfende weiter. Ein LLM-Judge kann die Belegung anhand bereitgestellter Materialien oder Tools bewerten; nehmen Sie nicht an, dass er eine Aussage darüber hinaus unabhängig verifiziert hat.

Prüfen Sie den Judge erneut, wenn sich Aufgabe, Modell, Prompt oder Eingabeverteilung ändern. Eine stabile Punktzahl allein beweist keine Richtigkeit. Hinweise zum Aufbau von Evaluierungen bieten die [Best Practices von OpenAI](https://platform.openai.com/docs/guides/evaluation-best-practices).
