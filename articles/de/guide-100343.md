# LLM-Merkmale in einer Pipeline zur Textklassifizierung nutzen

> Ein praktischer Leitfaden zur Nutzung LLM-generierter Merkmale in einer Klassifizierungspipeline und zur Bewertung von Schwellenwerten und Kalibrierung.



Ein Sprachmodell kann Text direkt klassifizieren oder Signale erzeugen, die ein anderes Modell zusammen mit weiteren Daten nutzt. Keiner der Ansätze ist automatisch besser. Die sinnvolle Wahl hängt von der Aufgabe, verfügbaren Labels und den Kosten von Fehlern ab.

## Mit einer Baseline beginnen

Definieren Sie das Ergebnis und sammeln Sie Beispiele, die die erforderlichen Entscheidungen abbilden. Im Support könnte die Aufgabe sein, Tickets zu erkennen, die eine dringende menschliche Prüfung benötigen. Einigen Sie sich darauf, was als dringend gilt, beziehen Sie mehrdeutige Fälle ein und dokumentieren Sie deren menschliche Kennzeichnung.

Testen Sie eine einfache Baseline, bevor Sie Komplexität hinzufügen. Das kann eine Regel, ein zur Ausgabe eines Labels aufgefordertes Modell oder ein überwachter Klassifikator sein, der mit vorhandenen gelabelten Daten trainiert wurde. Vergleichen Sie die Ansätze auf denselben zurückgehaltenen Beispielen. Ein direkter LLM-Klassifikator kann nützlich sein und sollte nicht allein deshalb verworfen werden, weil ein anderer Ansatz existiert.

## Modellausgaben in Merkmale umwandeln

Fordern Sie ein Sprachmodell statt nur einer endgültigen Entscheidung zur Ausgabe einer kleinen Menge aufgabenspezifischer Signale auf. Im Supportbeispiel könnten diese anzeigen, ob eine Nachricht einen Dienstausfall oder eine Rechnungsfrage beschreibt. Ein nachgelagerter Klassifikator kann diese Signale zusammen mit erlaubten strukturierten Feldern wie der Produktkategorie nutzen.

Definieren Sie jedes Signal genau und validieren Sie das Ausgabeformat. Ein generiertes Signal kann falsch sein oder fehlen, und ein nachgelagertes Modell kann aus diesen Fehlern lernen. Beziehen Sie keine Informationen ein, die zum Zeitpunkt der tatsächlichen Entscheidung nicht verfügbar wären.

## Daten vor dem Training aufteilen

Trennen Sie Trainingsdaten von Validierungs- und Testdaten, bevor Sie Merkmale auswählen oder Schwellenwerte abstimmen. Hängen Nachrichten desselben Kunden oder aus einem späteren Zeitraum zusammen, wählen Sie eine Aufteilung, die die spätere Nutzung des Systems widerspiegelt. Andernfalls können Informationen aus dem Testdatensatz ins Training gelangen und die Ergebnisse besser erscheinen lassen, als sie sind.

Trainieren Sie das nachgelagerte Modell mit dem Trainingsdatensatz. Wählen Sie Merkmale und Entscheidungsschwelle anhand der Validierungsdaten und evaluieren Sie anschließend den gewählten Ablauf auf einem separaten Testdatensatz. Prüfen Sie die gesamte Pipeline einschließlich Fehlern beim Abrufen oder syntaktischen Analysieren einer LLM-Ausgabe; evaluieren Sie nicht nur erfolgreiche Aufrufe.

## Den Schwellenwert nach den Folgen wählen

Ein Klassifikator kann jedem Eintrag einen Score oder eine Wahrscheinlichkeit zuweisen. Ein Schwellenwert übersetzt diesen Wert in eine Aktion, etwa die Weiterleitung eines Tickets zur Prüfung. Eine Verschiebung kann Precision und Recall verändern; der passende Kompromiss hängt jedoch von den Kosten übersehener Fälle und unnötiger Prüfungen ab.

Wenn Sie Scores als Wahrscheinlichkeiten interpretieren möchten, bewerten Sie ihre Kalibrierung anhand geeigneter zurückgehaltener Daten. Weder das Trainieren einer logistischen Regression noch die Abfrage der Modellsicherheit garantiert kalibrierte Wahrscheinlichkeiten. Vergleichen Sie neben Klassifikationsmetriken auch die Kalibrierung und untersuchen Sie die Leistung für wichtige Gruppen und seltene Fälle.

## Den gesamten Ablauf messen

Vergleichen Sie Baseline und merkmalsbasiertes System auf demselben Evaluierungsdatensatz. Erfassen Sie falsch positive und falsch negative Ergebnisse, Latenz, Kosten sowie den Anteil fehlgeschlagener oder menschliche Prüfung erfordernder Aufrufe. Ein komplexerer Ablauf sollte seine zusätzlichen Betriebskosten durch einen messbaren Nutzen für die Aufgabe rechtfertigen.

Halten Sie Versionen von Prompt, Modell, Merkmalen und Schwellenwert fest. Evaluieren Sie erneut, wenn sich diese oder die eingehenden Daten ändern. Hinweise zum Erstellen und Pflegen von Evaluierungen bieten die [Best Practices von OpenAI](https://platform.openai.com/docs/guides/evaluation-best-practices).
