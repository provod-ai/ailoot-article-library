# Einführung verwalteter Agents in der Gemini API

> Ein praktischer Leitfaden zu verwalteten Agents in der Gemini API: Aufgaben auswählen, Ergebnisse prüfen und Kosten, Datenschutz und Fehler einplanen.



Eine Anfrage an ein Sprachmodell liefert gewöhnlich eine Antwort; ein Agent kann außerdem Zwischenschritte auf dem Weg zu einem Ergebnis ausführen. Er kann beispielsweise Daten untersuchen, Code schreiben und ausführen und einen Bericht zurückgeben. Googles verwaltete Agents stellen über die Gemini API einen gehosteten Arbeitsbereich für solche Aufgaben bereit. Die Funktion befindet sich in der Vorschau. Prüfen Sie daher die aktuelle Dokumentation und Verfügbarkeit, bevor Sie sie in einen Produktionsablauf einbauen.

Dieser Leitfaden erklärt, wie Sie eine erste Aufgabe wählen, das Ergebnis beurteilen und den Betrieb rund um einen verwalteten Agent planen. Die [Dokumentation der Gemini API](https://ai.google.dev/gemini-api/docs) von Google enthält aktuelle Anfragebeispiele und unterstützte Agent-IDs.

## Was verwaltet der Anbieter?

Bei verwalteten Agents betreibt der Anbieter die Agentenumgebung und stellt nutzbare Werkzeuge bereit. Google beschreibt eine entfernte Sandbox, in der sein Agent Antigravity mit Dateien arbeiten, Code ausführen und das Web nutzen kann. Ihre Anwendung muss weiterhin das Ziel definieren, geeignete Eingaben bereitstellen und entscheiden, ob das Ergebnis akzeptabel ist.

Eine gehostete Umgebung ist nützlich, wenn eine Aufgabe mehrere Schritte und einen zwischenzeitlichen Arbeitsbereich erfordert. Sie ersetzt keine Entscheidungen der Anwendung über Berechtigungen, Prüfung oder Datenverarbeitung. Prüfen Sie vor der Nutzung, welche Werkzeuge und Umgebungseinstellungen für Ihr Projekt und Ihre Version verfügbar sind.

## Eine abgegrenzte erste Aufgabe wählen

Beginnen Sie mit einer Aufgabe, deren Ergebnis sich prüfen lässt, ohne der Erklärung des Agents vertrauen zu müssen. Ein kleines CSV-Resümee ist ein gutes Beispiel: Stellen Sie eine nicht sensible Beispieldatei bereit, fordern Sie eine Tabelle mit Summen an und legen Sie das Ausgabeformat fest. Berechnen Sie einige Summen unabhängig und vergleichen Sie sie mit dem Ergebnis.

Eine hilfreiche Aufgabenbeschreibung enthält:

- Die Eingabe und die Bedeutung jedes Feldes.
- Die gewünschte Ausgabe, etwa eine Zusammenfassung und eine CSV-Datei.
- Regeln für fehlende oder ungültige Werte.
- Eine Grenze für Daten und Werkzeuge, die der Agent nutzen darf.
- Prüfungen, die der Empfänger vor der Nutzung des Ergebnisses ausführen kann.

Zum Beispiel: „Fasse diese Beispiel-CSV mit Verkäufen nach Monat und Währung zusammen. Führe Währungen nicht zusammen. Liste Zeilen ohne Datum separat auf und gib die Berechnungen für jede Summe an.“ Vermeiden Sie beim ersten Test Aufforderungen, Nachrichten zu senden, Produktionsdaten zu ändern oder andere externe Aktionen auszuführen.

## Eine Interaktion ausführen und prüfen

Richten Sie SDK und Zugangsdaten anhand von Googles [Einstiegsanleitung](https://ai.google.dev/gemini-api/docs/get-started) ein und folgen Sie dann dem Beispiel für verwaltete Agents. Das Beispiel übergibt eine Agent-ID, eine Eingabe und eine entfernte Umgebung. Verwenden Sie die aktuell von Google dokumentierte ID, statt anzunehmen, dass eine alte Vorschau-ID weiterhin verfügbar ist.

Prüfen Sie mehr als den letzten Absatz. Kontrollieren Sie den zurückgegebenen Status, die Ausgabe und alle Dateien, die Sie verwenden möchten. Vergleichen Sie bei Datenaufgaben die Zahlen mit der Quelle; prüfen und testen Sie ein erzeugtes Skript in einer kontrollierten Umgebung. Hängt die Aufgabe von Informationen aus dem Web ab, öffnen Sie die angegebenen Quellen und prüfen Sie, ob sie die Aussagen stützen. Auch ein überzeugend formuliertes Ergebnis kann Fehler enthalten.

Wenn Sie die Arbeit über mehrere Interaktionen fortsetzen, folgen Sie dem von Google dokumentierten Lebenszyklus von Umgebung und Interaktion. Bewahren Sie relevante Kennungen beim Jobdatensatz Ihrer Anwendung auf und behandeln Sie Ablauf oder Fehler ausdrücklich; gehen Sie nicht davon aus, dass ein Arbeitsbereich unbegrenzt bestehen bleibt.

## Einem eigenen Agent klare Anweisungen geben

Google dokumentiert auch Möglichkeiten, verwalteten Agents eigene Anweisungen, Fähigkeiten und Daten bereitzustellen. Beschreiben Sie damit Aufgabe und Ausgabeanforderungen, statt Geheimnisse in ein Dokument einzubetten. Bei einer Berichtsaufgabe könnten Anweisungen festlegen, wie Daten gruppiert und Unsicherheiten gekennzeichnet werden und was geschieht, wenn eine Berechnung nicht abgeschlossen werden kann.

Verwalten Sie Anweisungsdateien unter Versionskontrolle und prüfen Sie Änderungen wie Anwendungscode. Testen Sie eine neue Version mit einer kleinen Menge repräsentativer Eingaben, darunter leere Dateien, unerwartete Werte und eine Anfrage außerhalb des vorgesehenen Bereichs. Erfassen Sie Version und Eingabe jeder Evaluierung, damit sich eine veränderte Ausgabe untersuchen lässt.

## Kosten, Datenschutz und Fehler einplanen

Ein mehrstufiger Agent kann vor der Rückgabe mehrere Modellaufrufe tätigen oder Werkzeuge nutzen. Prüfen Sie vor einem Versuch Googles [Preisseite](https://ai.google.dev/gemini-api/docs/pricing) und die Grenzen Ihres Projekts; Preise und Vorschaubedingungen können sich ändern. Messen Sie die Nutzung anhand repräsentativer Aufgaben und legen Sie ein zur Arbeitslast passendes Budget auf Anwendungsebene fest.

Senden Sie nur Daten, deren Verarbeitung im Ablauf erlaubt ist. Behandeln Sie abgerufene Seiten und hochgeladene Dateien als nicht vertrauenswürdige Eingaben und prüfen Sie erzeugten Code, bevor Sie ihn außerhalb der Sandbox ausführen. Legen Sie fest, was bei einem Timeout, Werkzeugfehler oder unvollständigen Ergebnis geschieht. Eine erneute Ausführung kann Nebenwirkungen wiederholen; klären Sie deshalb den ursprünglichen Vorgang, bevor Sie es erneut versuchen.

## Wann ist ein verwalteter Agent sinnvoll?

Ein verwalteter Agent ist eine Prüfung wert für abgegrenzte Recherche-, Analyse- oder Dateierstellungsaufgaben, bei denen mehrere Werkzeugschritte helfen und eine Person oder automatische Prüfung die Ausgabe verifizieren kann. Für eine einzelne vorhersehbare Transformation kann eine direkte Modellanfrage oder gewöhnlicher Anwendungscode einfacher zu betreiben sein. Vergleichen Sie Qualität, Latenz, Kosten und den erforderlichen Prüfaufwand für Ihren Anwendungsfall.
