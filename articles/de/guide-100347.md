Wie Gateways, Routing, Caching und Model Serving zusammenspielen und wie der Anfragekontext durch diese Ebenen weitergegeben werden kann.

Ein Anfragekontext kann über ein Gateway und einen Router bis zum Model Serving weitergegeben werden. Dieser Kontext verknüpft die Modellauswahl, die Wiederverwendung von Cache-Inhalten und die Ausführung mit der Identität des Aufrufers und den Kosten jedes Versuchs. Ein Router, der den Cache-Zustand ignoriert, kann die Einsparungen aufzehren, die eine benachbarte Ebene erzielt hat.

Das Teilen von Kontext erfordert Integrationsarbeit, und ein Router, der den Cache-Zustand ausliest, lässt sich schwerer austauschen. Wenn der Kontext mit der Anfrage gesendet wird, während die Produkte getrennt bleiben, kann ein Team ein Gateway und einen Router mit der Laufzeitumgebung eines anderen Anbieters verwenden. Der Router trifft seine Entscheidungen dann anhand der Informationen, die dieser Anbieter offenlegt.

## Eine günstigere Route kann mehr kosten

Betrachten wir einen beispielhaften Dienst zur Dokumentenextraktion mit langen, festen Anweisungen und einem kurzen Dokument pro Anfrage. Präfix-Caching und Routing wirken beide attraktiv, können sich aber gegenseitig aushebeln. Ein gecachtes Präfix ist ein von einem Modell berechneter Schlüssel-Wert-Zustand. Wird eine Anfrage an ein anderes Modell weitergeleitet, muss dieses die Anweisungen daher erneut einlesen.

Die von Anthropic veröffentlichten Preise für fünfminütiges Caching betragen beim Schreiben das 1.25-Fache des Basispreises für Eingaben und beim Lesen das 0.1-Fache, wobei es Ausnahmen für einzelne Modelle gibt ([Ankündigung](https://www.anthropic.com/news/prompt-caching), [Dokumentation](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)). Gegenüber diesem warmen Cache muss eine Alternative ohne Cache weniger als ein Zehntel des bisherigen Eingabepreises verlangen, damit sie sich beim gemeinsamen Präfix lohnt. Ein Schreibvorgang und ein Cache-Treffer kosten für den gecachten Teil 1.35 Eingabedurchläufe, ohne Caching sind es zwei. Ein Schreibvorgang, auf den keine spätere Anfrage zugreift, kostet 1.25.

Ein Router, der Listenpreise vergleicht, könnte ein Modell mit halb so hohem Eingabepreis sehen und wechseln. Für das Präfix würde er dann mindestens fünfmal so viel bezahlen. Deklariertes Routing legt fest, welche Modelle einander ersetzen dürfen; der gemeinsame Kontext zeigt, was jeder Austausch gekostet hat.

## Für die Wiederverwendung von Antworten braucht es die Identität des Aufrufers

<figure>
<ol>
<li><strong>Exakte Antwort</strong> — Eine Antwort für eine passende Anfrage wiederverwenden</li>
<li><strong>Präfix</strong> — Eingabeverarbeitung wiederverwenden und eine neue Antwort generieren</li>
<li><strong>Semantisch</strong> — Entscheiden, wann verschiedene Anfragen gleichwertig sind</li>
</ol>
Bei der Wiederverwendung müssen Modell, Prompt, Schema und Aktualitätsanforderungen berücksichtigt werden.
<figcaption>Drei verschiedene Arten der Wiederverwendung · Ein Antwort-Cache ist kein Präfix-Cache.</figcaption>
</figure>

Ein Antwort-Cache gibt eine gespeicherte Ausgabe zurück; ein semantischer Cache entscheidet zusätzlich, wann zwei verschiedene Anfragen dieselbe Antwort erhalten sollten. [GPTCache](https://github.com/zilliztech/GPTCache) entscheidet anhand der Ähnlichkeit von Embeddings über Cache-Treffer. In der README wird vor „false positives during cache hits“ gewarnt.

Bei der Extraktion könnte ein falsch positiver Treffer eine falsche Kontonummer zurückgeben: Zwei Rechnungen aus derselben Lieferantenvorlage können im Embedding-Raum nahe beieinanderliegen, und der Cache könnte der zweiten Rechnung die Kontonummer der ersten zuordnen. Ein semantischer Cache ohne Anwendungsidentität kann einen Korrektheitsfehler verursachen, während sein Dashboard für die Trefferquote jede falsche Antwort als Einsparung zählt.

Anthropic isoliert Prompt-Caches zwischen Organisationen und bei seiner eigenen API auch nach Arbeitsbereich, obwohl ein Präfix-Cache keine gespeicherte Antwort zurückgibt. Ein Antwort-Cache braucht mindestens dieselbe Abgrenzung. Eine Anwendung kann festlegen, ob eine Aufgabe die Wiederverwendung über ähnliche Eingaben hinweg toleriert. Dabei kann der Cache-Schlüssel den Aufrufer, die Daten, auf die dieser zugreifen darf, und die Aufgabenversion berücksichtigen.

Bei der Extraktion kann man exakte Übereinstimmungen wiederverwenden oder gar nichts wiederverwenden; bei einem unbekannten Schlüssel wird neu gerechnet. Diese Regel senkt die Trefferquote und verursacht Kosten für Arbeit, die ein weniger strenger Cache überspringen würde. Die Standardeinstellung kann zu streng sein: Bei einer großen öffentlichen FAQ kann die Neuberechnung für unbekannte Schlüssel mehr kosten als die seltene falsche Antwort, die sie verhindert.

## Verfolge den Fehler, bevor du die Lösung auswählst

Angenommen, ein günstigeres Modell gibt ungültige Felder zurück, und ein größeres Modell korrigiert sie, wodurch Rechnung und Verzögerung für dieses Dokument steigen. Die Kosten lassen sich pro korrekter Extraktion bei der geforderten Latenz berechnen; der Tokenpreis des ersten Aufrufs ist ein Faktor.

Berkeleys Analyse zusammengesetzter KI-Systeme plädiert dafür, zusammenwirkende Komponenten gemeinsam zu optimieren. Ein Trace muss einen Modellfehler von veralteter Wiederverwendung, einem langsamen Tool oder einer schlechten Route unterscheiden, da jeder dieser Fälle auf eine Lösung in einer anderen Ebene hindeutet. Kontrolle über die Ausführung kann helfen, die Kostenursachen zu erkennen, während eine schnellere Laufzeitumgebung Verschwendung in die Entscheidungen rundherum verlagern kann. Durch die Verknüpfung von Traces mit der Auswertung des Produktionsverkehrs lässt sich prüfen, ob eine Änderung die Aufgabe verbessert, einschließlich des Wiederherstellungspfads.

Ein Betreiber kann anhand dieses Traces die Ebene ändern, in der der Fehler auftrat. Wenn Anfrageverlauf, Evaluierungsfälle und die Wahl der Bereitstellung in der Anwendung des Kunden bleiben, können Verbesserungen auf den eigenen Erfahrungen dieser Anwendung aufbauen.
