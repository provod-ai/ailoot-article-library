# Tools für KI-Agenten entwerfen: Erkenntnisse für Claude-Code-Workflows

> Ein praktischer Leitfaden zum Definieren und Testen von Tools für KI-Agenten mit Beispielen aus Entwicklungsabläufen.



Ein KI-Agent braucht mehr als ein gutes Modell: Er benötigt Tools, die er auswählen, verstehen und innerhalb der Aufgabengrenzen nutzen kann. Dieser Leitfaden zeigt anhand von Entwicklungsabläufen, wie solche Schnittstellen gestaltet werden.

## Mit einer beobachtbaren Aufgabe beginnen

Beschreiben Sie das Ziel des Agenten, bevor Sie die verfügbaren Tools auswählen. Bei einer Frage zu einem Repository könnte die Aufgabe sein, die Stelle zu finden, an der eine Einstellung gelesen wird, und die relevanten Dateien zu nennen. Eine geeignete Toolauswahl könnte Dateien auflisten, Text durchsuchen und ausgewählte Dateien lesen; für die Antwort braucht der Agent keine Berechtigung zum Deployment.

Halten Sie das erwartete Ergebnis und nicht zum Auftrag gehörende Aktionen fest. Ein Tool ist nützlich, wenn Ein- und Ausgabe dem Agenten bei der nächsten Entscheidung helfen und die Anwendung prüfen kann, ob die Aktion erlaubt ist.

## Jedem Tool einen klaren Vertrag geben

Eine Toolbeschreibung sollte Funktion, erforderliche Eingaben und Form des Ergebnisses nennen. Verwenden Sie unterschiedliche Namen und Parameterbeschreibungen für Tools mit ähnlichem Zweck. Beschreiben Sie wichtige Grenzen: Eine Suche könnte beispielsweise eine begrenzte Liste passender Pfade statt des Inhalts aller Dateien zurückgeben.

Eine beispielhafte Anfrage an ein Textsuchtool könnte Suchbegriff und Verzeichnis enthalten. Das Ergebnis könnte Pfade und passende Zeilennummern nennen. Die Anwendung sollte das Verzeichnis validieren und fehlende Pfade oder fehlgeschlagene Suchen ausdrücklich behandeln. Eine wohlgeformte Anfrage beweist nicht, dass die gefundene Antwort richtig ist.

## Flexibilität und Kontrolle abwägen

Eine allgemeine Shell unterstützt viele Aufgaben, eröffnet aber auch zahlreiche Aktionen. Ein enger gefasstes Tool kann einen häufigen Vorgang verständlicher machen und die ausgeführte Aktion begrenzen. Die Wahl hängt von Aufgabe, Umgebung und verfügbaren Berechtigungen ab; mehr Tools führen nicht automatisch zu besseren Ergebnissen.

Halten Sie die anfängliche Auswahl überschaubar. Ergänzen Sie ein spezialisiertes Tool, wenn beobachtete Fehler oder wiederholte Arbeit es rechtfertigen. Kann ein Tool Daten ändern oder einen externen Dienst kontaktieren, machen Sie dies in seiner Beschreibung sichtbar und setzen Sie die entsprechenden Berechtigungen in der Anwendung durch.

## Fehlende Informationen zum richtigen Zeitpunkt erfragen

Ein Agent sollte eine fehlende Entscheidung nicht erfinden. Hängt eine Aufgabe tatsächlich von Informationen ab, die er nicht finden kann, kann eine strukturierte Frage die Optionen und ihre Folgen darstellen. Ist unabhängige Arbeit bereit, kann der Ablauf während des Wartens darauf fortgesetzt werden.

Fragen Sie konkret. Benötigt ein Bericht beispielsweise einen nicht angegebenen Zeitraum, fragen Sie danach, statt den gesamten Auftrag erneut anzufordern. Eine Frage ersetzt nicht die Prüfung des verfügbaren Kontexts.

## Tool und Agent gemeinsam testen

Erstellen Sie eine kleine Auswahl repräsentativer Aufgaben: gewöhnliche Anfragen, mehrdeutige Eingaben, nicht verfügbare Dateien und Versuche, ein Tool außerhalb seines vorgesehenen Bereichs zu nutzen. Prüfen Sie die Toolauswahl, übergebene Argumente, das Ergebnis und die endgültige Antwort. Auch ein erfolgreicher API-Aufruf kann unvollständige Daten liefern; gleichen Sie die Antwort daher mit den zugrunde liegenden Belegen ab.

Ändern Sie bei der Diagnose wiederkehrender Fehler jeweils einen Teil der Schnittstelle. Erfassen Sie die Version der Toolbeschreibung und wiederholen Sie den relevanten Test. Klären Sie bei Aktionen mit Nebenwirkungen ein ungewisses Ergebnis vor einem erneuten Versuch; dieser könnte eine bereits erfolgreiche Aktion wiederholen.

## Die Ideen im Entwicklungsablauf anwenden

Claude Code unterstützt Abläufe, die Tools und wiederverwendbare Anweisungen verbinden. Den API-Vertrag finden Sie in der aktuellen [Dokumentation zur Toolnutzung von Claude](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview), die Organisation wiederverwendbarer Anweisungen in der [Claude-Code-Skills-Dokumentation](https://code.claude.com/docs/en/skills). Verfügbarkeit und genaue Schnittstellen können sich ändern; prüfen Sie daher die Dokumentation der verwendeten Version.

Dieselben Fragen gelten für verschiedene Agent-Frameworks: Was verlangt die Aufgabe, was kann der Agent beobachten, was kann jedes Tool ändern und wie prüfen Sie das Ergebnis?
