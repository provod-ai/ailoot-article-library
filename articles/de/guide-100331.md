# LLM als Richter: KI zur Bewertung von KI einsetzen (zuverlässig)

> So verwendest du Sprachmodelle zur Bewertung von KI-Ausgaben, berücksichtigst Verzerrungen des Richters, entwirfst Bewertungsrubriken und kalibrierst automatisierte Bewertungen anhand menschlicher Urteile.



Ein LLM als Bewerter wendet einen schriftlichen Kriterienkatalog auf die Antwort einer anderen KI an. Es kann Teams helfen, große Mengen von Antworten zu prüfen. Seine Urteile müssen aber mit Beispielen abgeglichen werden, die Menschen bewertet haben.

## Mit Aufgabe und Kriterienkatalog beginnen

Wählen Sie eine Aufgabe, etwa die Beantwortung von Supportfragen anhand einer vorgegebenen Richtlinie. Beschreiben Sie das erwartete Verhalten anhand beobachtbarer Merkmale. Prüfen Sie beispielsweise, ob die Antwort der Richtlinie folgt, die Frage beantwortet und unbelegte Aussagen vermeidet. Der Kriterienkatalog sollte auch festlegen, was bei fehlenden Belegen zu tun ist.

Bewerten Sie die Kriterien einzeln, bevor Sie ein Gesamtergebnis bilden. Eine Antwort kann knapp, aber ungenau sein; ein einzelner Punktwert kann diesen Unterschied verdecken. Bewahren Sie den Kriterienkatalog und die Version des Bewertungsmodells zusammen mit den Ergebnissen auf, damit spätere Vergleiche eingeordnet werden können.

## Eine Vergleichsmethode wählen

Geben Sie dem Bewerter für eine Bestanden/Nicht-bestanden-Prüfung die Frage, die verfügbaren Belege und eine Antwort. Fordern Sie für jedes Kriterium eine Entscheidung und eine kurze, auf das vorgelegte Material gestützte Begründung an. Dies funktioniert am besten, wenn die Kriterien präzise genug sind, um einheitlich angewendet zu werden.

Für einen Vergleich geben Sie zwei Antworten auf dieselbe Frage vor und fragen, welche den Kriterien besser entspricht; ein Unentschieden muss möglich sein. Wiederholen Sie den Vergleich mit umgekehrter Reihenfolge. Wechselt der Gewinner, markieren Sie den Fall zur Prüfung, statt eines der Ergebnisse als endgültig anzusehen. Entfernen Sie unnötige Kennzeichnungen, die das erzeugende System verraten.

Bei Fragen mit bekannter Antwort kann eine Referenzantwort helfen. Betrachten Sie sie bei offenen Aufgaben als Beispiel für akzeptable Qualität, nicht als einzige gültige Formulierung.

## Ergebnisse nutzbar machen

Fordern Sie ein strukturiertes Ergebnis mit einer Entscheidung und einer kurzen Begründung je Kriterium an. Zum Beispiel:

```json
{"policy_supported":{"result":"pass","reason":"Die Antwort nennt die vorgegebene Stornierungsregel."},"addresses_question":{"result":"fail","reason":"Sie erklärt nicht, wie man storniert."}}
```

Dies zeigt eine mögliche Antwort und belegt nicht, dass ein Bewerter einen realen Fall geprüft hat. Validieren Sie die Ausgabe, bevor Sie sie in einem Bericht verwenden; wiederholen Sie den Versuch oder geben Sie fehlerhaft formatierte Ergebnisse gemäß Ihrem Ablauf zur Prüfung weiter. Auch die Erklärung eines Modells ist eine zu prüfende Ausgabe und kein Beweis für ein richtiges Urteil.

## Mit Menschen kalibrieren

Stellen Sie eine repräsentative Stichprobe mit einfachen Fällen, Grenzfällen und bekannten Fehlern zusammen. Lassen Sie Prüfende denselben Kriterienkatalog unabhängig auf eine gemeinsame Teilmenge anwenden, Abweichungen besprechen und Entscheidungen dokumentieren. Vergleichen Sie dann die Ergebnisse des Bewerters mit diesen menschlichen Bewertungen, untersuchen Sie Abweichungen und überarbeiten Sie Kriterien oder Ablauf, bevor Sie sich auf die Kennzahl verlassen.

Achten Sie besonders auf Reihenfolge, Länge und Stil. Eine ansprechend formulierte oder längere Antwort ist nicht zwingend genauer. Nehmen Sie knappe korrekte und plausibel klingende falsche Antworten in die Stichprobe auf. Messen Sie bei paarweisen Tests, wie oft sich die Entscheidung durch eine Umkehr der Reihenfolge ändert.

## Den Bewerter als eine Ebene einsetzen

Führen Sie zuerst deterministische Prüfungen aus, wo sie passen: Validieren Sie etwa JSON oder prüfen Sie ein Pflichtfeld. Nutzen Sie den Bewerter für Kriterien, die Interpretation erfordern, und behalten Sie die menschliche Prüfung für unsichere oder folgenreiche Fälle bei. Verfolgen Sie aggregierte Ergebnisse auf einem stabilen Datensatz, untersuchen Sie aber auch einzelne Fehler.

Prüfen Sie die Kalibrierung erneut, wenn sich Modell, Kriterienkatalog, Aufgabe oder Verteilung der Eingaben ändern. Eine höhere Punktzahl allein belegt keine Verbesserung: Untersuchen Sie die Antworten und halten Sie einen separaten Evaluierungsdatensatz vor, wenn dieselbe automatisierte Kennzahl zur Optimierung eines Systems dient.

## Praktische Checkliste

1. Definieren Sie Aufgabe, verfügbare Belege und Kriterien.
2. Sammeln Sie Beispiele und einigen Sie sich auf menschliche Bewertungen.
3. Wählen Sie Einzelantwortbewertung oder paarweisen Vergleich und sehen Sie Unentschieden oder Unsicherheit als Ergebnis vor.
4. Validieren Sie strukturierte Ergebnisse und prüfen Sie Abweichungen.
5. Halten Sie Versionen fest und kalibrieren Sie nach wesentlichen Änderungen neu.

Weitere Informationen finden Sie in den [Empfehlungen von OpenAI zur Evaluierung](https://platform.openai.com/docs/guides/evaluation-best-practices).
