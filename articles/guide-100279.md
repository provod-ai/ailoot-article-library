# The real cost of LLM inference is the GPU you are not using

> Two historical API rates for input tokens differed 600-fold. See how GPU utilization, idle rental hours and peak rates shape LLM inference costs.



A 2026 study (arXiv:2603.28576, §4) compared two API price benchmarks. The study used USD 60 per million input tokens for its 2020 GPT-3 benchmark and USD 0.10 for the economy-tier Gemini 2.0 Flash in February 2025, a 600-fold difference. It estimated a price half-life of 1.1 years for its economy tier.

What the deflation headlines hide is the part that actually sets your bill: how many of your GPU hours are doing useful work. Inference is billed by the token, but served by the hour.

A data centre aisle of GPU servers, most glowing with activity while one sits dark and idle

## The number teams miss

A June 2026 vLLM benchmark (arXiv:2606.11690, §§4–5) ran Mixtral 8x7B Instruct in FP16 on two H100 NVL GPUs with tensor parallelism (TP=2). It used a combined rental rate of USD 13.96 per hour and synthetic requests of 512 input tokens and 256 output tokens, with prefix caching disabled. The table divides the GPU rental cost by measured output-token volume over the same period. Request rates count arrivals offered to the server.

| Mixtral 8x7B on two H100 NVL GPUs | Effective cost per 1M output tokens |
|------------------------------------|-------------------------------------|
| 1 request per second (near idle)   | about \$15.25                       |
| 100 offered requests per second (near saturation)             | about \$0.87                        |

The two measurements differ by 17.5×. At 25 offered requests per second, the cost was about USD 0.95 per million output tokens. At 100 offered requests per second, the server completed about 17.4 requests per second. The study found costs from USD 0.21 to USD 15.25 per million output tokens across six H100 configurations and the measured loads. Treat those values as measurements for this test workload. In production, measure throughput at a load that meets your latency target.

For the same hourly rental rate, operating at 40% of peak output throughput raises the cost per output token by a factor of 2.5. In the following examples, utilization is the share of peak output throughput that the service actually achieves. A GPU can report high activity while producing few output tokens.

This is why two teams running the same model can quote wildly different unit costs. One runs a bursty chatbot at 40 percent utilization; the other runs a saturated batch pipeline at 90 percent. The model, the hardware, and the sticker price are identical. The unit cost is not. When a vendor quotes you a cost per token, ask what utilization assumption is baked into it.

## Open-weight models made this worse

A mixture-of-experts (MoE) model uses a subset of its weights for each token. Mixtral 8x7B activates about 12.9 billion parameters per token and contains 46.7 billion in total. For an all-on-GPU deployment, budget memory for all the weights at their stored precision, plus the KV cache and runtime overhead. Active parameters help estimate compute per token. Memory bandwidth, expert routing and batch size also affect throughput.

Estimate the break-even point for your own workload. Compare the API bill for the same mix of input and output tokens with the cost of renting GPUs for the hours you need, including idle hours, and operating the service. Measure output throughput under your traffic pattern and latency target. API prices, model configuration and utilization all affect the result.

## The second hidden cost: time of day

As of 25 November 2026, the direct DeepSeek API applies peak rates from 01:00 to 04:00 and from 06:00 to 10:00 UTC, Monday through Friday except on Chinese public holidays. In Indian Standard Time (IST, UTC+05:30), the windows are 06:30–09:30 and 11:30–15:30. All other hours are off-peak, including the whole of each weekend day and Chinese public holiday. [DeepSeek API pricing](https://api-docs.deepseek.com/quick_start/pricing/)

On an eligible weekday, 10:00 IST (04:30 UTC) is off-peak and 15:00 IST (09:30 UTC) is peak. In USD per million tokens, the off-peak and peak rates for `deepseek-flash` are 0.003 and 0.006 for cache-hit input, 0.15 and 0.30 for cache-miss input, and 0.60 and 1.20 for output. For `deepseek-v4-pro`, they are 0.022 and 0.044, 0.66 and 1.32, and 1.98 and 3.96 in the same order.

## What actually moves the number

If you are sizing an inference budget, work down this list before you compare model prices:

1.  Utilization before hardware. A 40 percent utilized H200 can cost more per token than a fully loaded H100.
2.  Check whether your provider discounts cache hits. Reusing a long system prompt or shared prefix can reduce the input bill when it qualifies for the cache-hit rate.
3.  Weight peak and off-peak rates by your traffic. With the direct DeepSeek API, the same token usage under the same cache conditions costs twice as much during peak hours.
4.  Batch background jobs such as RAG indexing and bulk extraction where they can wait. Measure output throughput and latency under the batching settings you plan to use.
5.  For MoE models, use the active parameter count to estimate compute and allow memory for the full weights, KV cache and runtime overhead.
