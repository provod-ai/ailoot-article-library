# Проектирование инструментов для ИИ-агентов: уроки для работы с Claude Code

> Практическое руководство по определению и тестированию инструментов ИИ-агентов с примерами для задач программирования.



ИИ-агенту нужна не только хорошая модель, но и инструменты, которые он способен выбирать, понимать и использовать в границах задачи. В этом руководстве показано, как проектировать такие интерфейсы на примере задач программирования.

## Начните с проверяемой задачи

Опишите, чего агент должен достичь, прежде чем решать, какие инструменты ему предоставить. Например, при вопросе о репозитории задача может состоять в том, чтобы найти, где читается настройка, и указать соответствующие файлы. Подходящий набор позволит агенту перечислять файлы, искать текст и читать выбранные файлы; разрешение на развёртывание для ответа не требуется.

Запишите ожидаемый результат и действия вне задачи. Инструмент полезен, когда его вход и выход помогают агенту принять следующее решение, а приложение может проверить допустимость действия.

## Определите чёткий контракт каждого инструмента

Описание инструмента должно указывать, что он делает, какие входные данные обязательны и как устроен результат. Для инструментов со схожим назначением используйте различимые имена и описания параметров. Если у операции есть важное ограничение, опишите его: например, поиск может возвращать ограниченный список подходящих путей, а не содержимое всех файлов.

Пример запроса к инструменту текстового поиска может содержать запрос и каталог. Результат может включать пути и номера подходящих строк. Приложение должно проверять каталог и явно обрабатывать отсутствие путей или сбой поиска. Корректная форма запроса не доказывает правильность найденного ответа.

## Найдите баланс гибкости и контроля

Универсальная командная оболочка поддерживает множество задач, но открывает и широкий набор действий. Более узкий инструмент может упростить понимание типовой операции и ограничить выполняемое действие. Выбор зависит от задачи, среды и доступных разрешений; увеличение числа инструментов само по себе не улучшает результат.

Начальный набор должен быть достаточно небольшим для навигации. Добавляйте специализированный инструмент, когда это оправдано наблюдаемыми сбоями или повторяющейся работой. Если инструмент может менять данные или обращаться к внешнему сервису, явно укажите этот эффект в описании и обеспечьте проверку необходимых разрешений в приложении.

## Вовремя запрашивайте недостающую информацию

Агент не должен выдумывать отсутствующее решение. Если задача действительно зависит от информации, которую он не может найти, структурированный вопрос может представить варианты и объяснить их последствия. Пока ожидается ответ, процесс может продолжить готовую независимую работу.

Задавайте конкретные вопросы. Например, если для отчёта не указан диапазон дат, спросите его, а не просите пользователя повторить всё задание. Вопрос не заменяет проверку доступного контекста.

## Тестируйте инструмент и агента вместе

Создайте небольшой набор представительных задач: обычные запросы, неоднозначный ввод, недоступные файлы и попытки использовать инструмент за пределами его назначения. Проверяйте выбранный инструмент, переданные аргументы, возвращённый результат и итоговый ответ. Успешный вызов API всё равно может вернуть неполные данные, поэтому сверяйте ответ с исходными доказательствами.

При расследовании повторяющегося сбоя меняйте за раз одну часть интерфейса. Запишите версию описания инструмента и повторите соответствующий тест. При неопределённом результате действия с побочными эффектами сначала сверяйте исходную операцию: повтор может выполнить уже успешное действие ещё раз.

## Примените идеи к задачам программирования

Claude Code поддерживает рабочие процессы, объединяющие инструменты и многократно используемые инструкции. Контракт API приведён в актуальной [документации Claude по использованию инструментов](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview), а организация повторно используемых инструкций — в [документации Claude Code о навыках](https://code.claude.com/docs/en/skills). Доступность и точные интерфейсы могут меняться, поэтому проверяйте документацию используемой версии.

Те же вопросы проектирования применимы к разным агентным платформам: что требуется задаче, что может наблюдать агент, что способен изменить каждый инструмент и как проверить результат?
