# Claude API kezdőknek: gyakorlati útmutató az induláshoz

> Ez a Claude API-kezdőkalauz a beállítást, az első kérést, a modellválasztást, az alapfunkciókat és az éles környezet gyakorlatait ismerteti.



Minden, amire egy fejlesztőnek szüksége van az első Claude API-híváshoz: kulcsok, Messages API, modellválasztás és az első kéréstől az éles használatig vezető alapfogalmak.

## Mi a Claude API?

A Claude API az Anthropic fejlesztői platformja. Programozott hozzáférést biztosít a Claude-modellekhez a Messages API-n keresztül, rendszerpromptokkal, eszközhasználattal, streameléssel, képfeldolgozással és strukturált kimenetekkel.

A Messages API állapot nélküli HTTP-végpont. Elküldöd a felhasználói és asszisztensi üzenetek listáját, a modell azonosítóját és a tokenkorlátot; a Claude strukturált választ ad vissza. A kiegészítő végpontok közé tartozik a batch-feldolgozás, a fájlkezelés és a tokenszámlálás.

- **Állapot nélküli:** Az API nem őrzi meg az előzményeket. Minden hívásnál küldd el újra a beszélgetés teljes előzményét.
- **Modellválasztás:** Modellváltáskor általában a modell azonosítóját kell módosítani.
- **SDK-k:** A hivatalos Python- (anthropic) és TypeScript-könyvtárak (@anthropic-ai/sdk) a megfelelő kérésformátumot használják.

Az architektúra megértése segít elkerülni a kezdők gyakori hibáját: azt várni, hogy az API emlékezzen egy korábbi kérésre.

## 1. lépés: Szerezz kulcsot és állítsd be a konzolt

Nyisd meg a **console.anthropic.com** oldalt, hozz létre fiókot vagy szervezeti fiókot a csapatodnak, majd a beállításoknál generálj egy API-kulcsot. A kulcsot kezeld jelszóként: tárold környezeti változóban, és soha ne tedd verziókezelésbe.

A közvetlen HTTP-kérések **x-api-key** és **anthropic-version** fejlécet használnak. Az SDK-k automatikusan beolvassák az **ANTHROPIC_API_KEY** értékét a környezetből, ezért a legtöbb kódban nem kell közvetlenül kezelni a kulcsot.

- Külön kulcsot hozz létre fejlesztéshez, staginghez és éles használathoz.
- A csapatprojektjeidet és a költéseket workspaces használatával különítsd el.
- Mielőtt több csapattagnak is kulcsot adnál, állíts be használati limiteket a Console-ban.

## 2. lépés: Küldd el az első Messages API-kérést

Telepítsd az SDK-t a **pip install anthropic** paranccsal, exportáld a kulcsodat, majd futtasd:

```
import anthropic

client = anthropic.Anthropic()
msg = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Explain REST in one paragraph."}],
)
for block in msg.content:
    if block.type == "text":
        print(block.text)
```

Három paraméter kötelező: **model**, **max_tokens** (a kimenet felső korlátja) és **messages**. A válasz tartalomblokkok listáját tartalmazza. Ellenőrizd minden blokk típusát, és ne feltételezd, hogy csak egyszerű szöveget kapsz, mert az eszközhasználat és a gondolkodás további blokkfajtákat is hozzáadhat. A **usage** objektum a bemeneti és kimeneti tokenek számát jelenti, és költségmérésre is használható.

## 3. lépés: Válassz modellt

Az Anthropic aktuális Claude modelljei és API-azonosítóik az alábbiak.

- **Claude Haiku 5.5** (**claude-haiku-5-5**) — gyors és alacsony költségű modellként írja le osztályozáshoz és nagy volumenű, egyszerű feladatokhoz.
- **Claude Sonnet 5.5** (**claude-sonnet-5-5**) — kiegyensúlyozott modellként írja le éles munkaterheléshez, a kódolást is beleértve.
- **Claude Opus 5.5** (**claude-opus-5-5**) — nehéz következtetési feladatokhoz és hosszabb, önálló ügynöki munkához ajánlja.
- **Claude Fable 5.2** (**claude-fable-5-2**) — igényes következtetési feladatokra szánt zászlóshajóként írja le.

Kezdd az Opus 5.5 modellel. A sebesség és a minőség egyensúlyához próbáld ki a Sonnet 5.5 modellt, nagy mennyiségű egyszerű feladathoz a Haiku 5.5 modellt, összetett következtetéshez pedig a Fable 5.2 modellt. Az aktuális díjakért nézd meg az Anthropic árlistáját.

## Az öt következőként megtanulandó fogalom

Ha az első kérés már működik, ezek a funkciók sok alkalmazási igényt lefednek:

- **Rendszerpromptok** — legfelső szintű **system** paraméter, amely a felhasználói üzenetektől elkülönítve határozza meg a szerepet, a hangnemet és a szabályokat.
- **Többfordulós beszélgetések** — fűzd hozzá az asszisztens minden válaszát a messages tömbhöz, majd küldd el újra; az első üzenetnek felhasználói fordulónak kell lennie.
- **Streaming** — a szerver által küldött események a generálás közben továbbítják a tokeneket, ami hasznos lehet csevegőfelületeknél és hosszú kimeneteknél.
- **Képfeldolgozás** — képeket base64- vagy URL-tartalmú blokkokként adj meg a szöveg mellett.
- **Eszközhasználat** — definiálj JSON-sémával rendelkező függvényeket; a Claude kiválaszthatja, mikor hívja meg őket, a kódod pedig végrehajtja a függvényt és visszaadja az eredményt.

Ha számít a költség, vedd fontolóra a **prompt caching** és **batch processing** használatát; ha a következő kódnak fel kell dolgoznia a választ, a **structured outputs** is hasznos lehet.

## Az oktatóanyagtól az éles rendszerig

A működő szkriptből éles integrációt építeni mérnöki fegyelmet igényel:

- **Hibakezelés:** Kezeld külön a sebességkorlátokat (429) és a szerverhibákat. A forrás szerint az SDK-k háttérkésleltetéssel automatikusan újrapróbálják ezeket; az aktuális működésért nézd meg a megfelelő SDK dokumentációját.
- **Költségáttekintés:** Naplózd minden válasz **usage** értékét a metrikarendszeredben.
- **Promptverziózás:** Kezeld a promptokat kódként: nézd át, verziózd, majd teszteld kis értékelési adathalmazon.
- **Modellrögzítés:** Konfigurációból hivatkozz a modellazonosítókra, így a frissítések tudatosan és tesztelve történnek.

### Fő tanulságok

- A Messages API állapot nélküli; minden hívásnál küldd el újra a beszélgetés előzményeit.
- A közvetlen HTTP-hitelesítés x-api-key fejlécet használ; az SDK-k az ANTHROPIC_API_KEY értékét a környezetből olvashatják be.
- A három kötelező kérésparaméter: model, max_tokens és messages.
- Kezdd az Opus 5.5 modellel, és hasonlítsd össze az alternatívákat a saját adataidon.
- A rendszerpromptok, a streaming, a képfeldolgozás, az eszközhasználat és a többfordulós előzmény sokféle alkalmazási mintát támogat.
- A költségek áttekintéséhez és a kapacitás tervezéséhez naplózd a tokenhasználatot.

## GYIK

### Kell ismernem a gépi tanulást a Claude API használatához?

Nem. A Claude API REST API, hivatalos Python- és TypeScript-SDK-kkal. Ha tudsz HTTP-végpontot hívni és JSON-t feldolgozni, már építhetsz alkalmazást a Claude-dal. A prompttervezés, a hibakezelés és a költségek kezelése hasznos mérnöki készség, de az első API-híváshoz nem szükséges gépi tanulási elmélet.

### Melyik Claude-modellel kezdjen egy kezdő?

Az Anthropic a legtöbb feladathoz a Claude Opus 5.5 modellt (API-azonosító `claude-opus-5-5`) javasolja kiindulópontként. Ha a promptjaid már stabilak, hasonlítsd össze a többi modellt a saját adataidon.

### Emlékszik a Claude API a korábbi beszélgetésekre?

Nem. A Messages API állapot nélküli. Az alkalmazásod tárolja a beszélgetést, és minden kérésnél újraküldi a teljes üzenetelőzményt. Így te szabályozhatod a kontextust, rövidítheted vagy összefoglalhatod a régebbi fordulókat, és prompt cachinggel is kombinálhatod.
