# Priser for OpenAI Moderation API: gratis, bruksgrenser og alternativer

> OpenAIs modereringsmodeller er gratis. Se priser, bruksgrenser etter bruksnivå, Python-eksempler og når et OpenAI-kompatibelt alternativ passer bedre.




OpenAIs Moderation-endepunkt er gratis for brukere av OpenAI API. Når du skal velge en arbeidsflyt for produksjon, bør du sjekke hvilke inndata og kategorier endepunktet støtter, hvilke bruksgrenser som gjelder for kontoen din, og hvordan endepunktet passer inn i gjennomgangen din.

Denne veiledningen skiller mellom det offisielle svaret om priser og den praktiske tekniske beslutningen.

## Kort fortalt

- **OpenAIs Moderation-endepunkt er gratis for brukere av OpenAI API**, ifølge OpenAIs hjelpesenter.
- OpenAIs `omni-moderation-latest`-modell er utviklet for å oppdage skadelig innhold og godtar tekst og bilder som inndata, ifølge den offisielle OpenAI-modellsiden.
- Gratis pris fjerner ikke arbeidsflytkostnader som logging, gjennomgangskøer, policytilordning, nye forsøk, reserveatferd og applikasjonsspesifikke beslutninger.
- Velg OpenAIs gratis endepunkt hvis du allerede bruker OpenAI direkte og modereringsarbeidsflyten din passer til kategoriene og svarformatet deres.
- Vurder EvoLink Moderation 1.0 hvis du allerede bruker EvoLink og vil ha multimodale kontroller, en risikooversikt og betaling per kall i samme arbeidsflyt.

## Er OpenAI Moderation API gratis?

Ja. OpenAIs offisielle hjelpesenter oppgir at Moderation-endepunktet er gratis for brukere av OpenAI API, og at bruk av verktøyet ikke teller med i de månedlige bruksgrensene.

Kilde: [OpenAI Help Center: Is the Moderation endpoint free to use?](https://help.openai.com/en/articles/4936833-is-the-moderation-endpoint-free-to-use)

Det er svaret om priser. Det neste spørsmålet er operasjonelt:

**Er et gratis modereringsendepunkt nok for produksjonsarbeidsflyten din?**

For prototyper, interne verktøy og enkel tekstbasert moderering kan det være det. For applikasjoner som håndterer brukergenerert innhold, bildeopplastinger, AI-agenter eller gjennomgangskøer er API-kallet bare én del av systemet.

## Hva dekker OpenAI-moderering?

OpenAI beskriver `omni-moderation-latest` som en modereringsmodell utviklet for å identifisere potensielt skadelig innhold i tekst og bilder. Den offisielle modellsiden omtaler den som OpenAIs mest avanserte modereringsmodell og oppgir støtte for tekst som inndata/utdata og bilder som inndata. Kilde: [OpenAI model page for omni-moderation-latest](https://platform.openai.com/docs/models/omni-moderation-latest) OpenAIs modereringsveiledning forklarer også kategoriene for innholdsklassifisering og påpeker at noen kategorier bare gjelder tekst. Hvis du bare sender bilder til `omni-moderation-latest`, får kategorier som ikke støtter bildeinndata, en poengsum på 0. Kilde: [OpenAI Moderation guide](https://developers.openai.com/api/docs/guides/moderation)

Det betyr at team bør lese kategoritabellen nøye før de antar at alle tekstkategorier kan overføres direkte til bildemoderering.

## Den reelle kostnaden ligger i arbeidsflyten, ikke bare i API-prisen

Moderation-endepunktet kan være gratis, men et modereringssystem i produksjon krever fortsatt beslutninger om:

- hvor kontrollene skal kjøres: før modellkall, etter modellsvar eller begge deler
- hvordan kategorier skal knyttes til beslutninger om å tillate, gjennomgå eller blokkere
- hvordan modereringsresultater skal logges uten unødvendig lagring av sensitivt innhold
- hvordan falske positiver og klager skal håndteres
- hvordan bildeopplastinger skal modereres separat fra tekstinndata
- hvordan ventetid, feil og bruksgrenser skal overvåkes
- hvordan policyatferd skal være konsistent på tvers av produktflater

Dette er kostnader knyttet til utvikling og drift. De vises ikke på en prisside, men avgjør om modereringslaget faktisk er vedlikeholdbart.

I en vanlig arbeidsflyt sjekker du prompter før du sender dem til modellen, og utdata før du leverer dem. Send tvilstilfeller til gjennomgang, loggfør bare det nødvendige om beslutningene, og planlegg hvordan nye forsøk og klager skal håndteres.

## Når OpenAIs gratis endepunkt passer godt

OpenAIs gratis Moderation-endepunkt er ofte et godt førstevalg når:

- du allerede bruker OpenAI direkte
- appen din hovedsakelig er tekstbasert
- du bare trenger OpenAIs dokumenterte modereringskategorier
- du kan bygge din egen arbeidsflyt for gjennomgang og eskalering
- teamet ditt er komfortabelt med å håndtere svarparsing, terskler og logger

I så fall er det vanskelig å argumentere mot det gratis endepunktet. Begynn der, test det mot det faktiske innholdet ditt, og mål falske positiver og tilfeller som ikke fanges opp før du sender produksjonstrafikk gjennom det.

## Når et OpenAI-kompatibelt alternativ gir mening

EvoLink Moderation 1.0 er et betalt alternativ med en OpenAI-kompatibel `/v1/moderations`-rute. EvoLink godtar høyst ett bilde per forespørsel.

- kontroller av bare tekst, bare bilder og tekst pluss bilder gjennom ett endepunkt
- 13 skade­kategorier med poengsummer per kategori
- et `evolink_summary`-objekt med `risk_level`, `flagged`, `violations`, `max_score` og `max_category`
- fast pris per kall i stedet for tokenberegning
- et svarformat som er enklere å knytte til logikk for å tillate, gjennomgå eller blokkere

## Slik bruker du OpenAI Moderation API i Python

Hvis du allerede bruker OpenAI SDK, ser et grunnleggende kall for tekstmoderering slik ut:

```
from openai import OpenAI

client = OpenAI()

response = client.moderations.create(
    model="omni-moderation-latest",
    input="user text here"
)

print(response.results[0].flagged)
print(response.results[0].categories)
```

Sett `EVOLINK_API_KEY` til EvoLink-nøkkelen din og `EVOLINK_BASE_URL` til HTTPS-basisadressen fra EvoLink API-konfigurasjonen. Adressen skal slutte på `/v1`. Svaret inneholder i tillegg objektet `evolink_summary`.

```python
import os

from openai import OpenAI

# EVOLINK_API_KEY=YOUR_EVOLINK_API_KEY
client = OpenAI(
    api_key=os.environ["EVOLINK_API_KEY"],
    base_url=os.environ["EVOLINK_BASE_URL"],
)

response = client.moderations.create(
    model="evolink-moderation-1.0",
    input=[{"type": "text", "text": "user text here"}],
)

summary = response.model_extra["evolink_summary"]
print(summary["risk_level"])
print(summary["violations"])
```

## Praktisk anbefaling

Bruk OpenAIs gratis Moderation-endepunkt hvis applikasjonen din allerede er OpenAI-basert og modereringspolicyen din passer godt til de dokumenterte kategoriene deres.

Hvis teamet ditt allerede bruker EvoLink, bør du vurdere kostnaden per kall og la `evolink_summary.risk_level` være én av faktorene appens regler bruker for å avgjøre om innhold skal tillates, sendes til gjennomgang eller blokkeres.

Bruk et modereringssystem med flere lag hvis applikasjonen har egne policykrav som omfatter merkevareregler, menneskelig gjennomgang, klager eller arbeidsflyter for etterlevelse utover det én enkelt modererings-API kan tilby.

## Vanlige spørsmål

### Er OpenAI Moderation API gratis?

Ja. OpenAIs hjelpesenter sier at Moderation-endepunktet er gratis for brukere av OpenAI API og ikke teller med i de månedlige bruksgrensene.

### Støtter OpenAI-moderering bilder?

Ja, `omni-moderation-latest` godtar bilder som inndata ifølge OpenAIs offisielle modellsiden. OpenAIs modereringsveiledning påpeker imidlertid at noen kategorier bare gjelder tekst, så team bør kontrollere inndatastøtten for hver kategori før de baserer seg på moderering av bare bilder.

### Er EvoLink Moderation billigere enn OpenAI Moderation?

OpenAIs Moderation-endepunkt er gratis for brukere av OpenAI API. EvoLink tar en fast pris per kall. Sammenlign kostnaden for hele arbeidsflyten, inkludert gjennomgang og vedlikehold.

### Kan jeg bruke EvoLink som et alternativ til OpenAI Moderation API?

Ja. Bruk EvoLink API-nøkkelen din og modellen `evolink-moderation-1.0` på EvoLinks kompatible rute `/v1/moderations`. Tilpass svarbehandlingen slik at den håndterer det separate `evolink_summary`-objektet.

### Bør jeg moderere prompter, utdata eller begge deler?

For AI-applikasjoner i produksjon modererer mange team både inndata og utdata. Moderering av inndata kan redusere usikre forespørsler før de når en modell. Moderering av utdata kan fange opp usikre genererte svar før de når brukerne.

### Hva er omni-moderation-latest?

Det er OpenAIs modereringsmodell for tekst og bilder. Les `flagged`, `categories` og `category_scores` i `results` og bruk din egen modereringspolicy.

### Hva er bruksgrensen for OpenAI Moderation API?

Gratis tilgang gjelder betalingen. Bruksgrensene for forespørsler og tokener gjelder fortsatt. I [modellreferansen](https://developers.openai.com/api/docs/models/omni-moderation-latest) betyr RPM forespørsler per minutt, RPD forespørsler per dag der denne grensen er oppgitt, og TPM tokener per minutt.

Bruksgrensene for OpenAI Moderation API varierer etter kontonivå og kan endres over tid. Sjekk [OpenAIs dokumentasjon for bruksgrenser](https://platform.openai.com/docs/guides/rate-limits) og kontoens [side for bruksgrenser](https://platform.openai.com/settings/organization/limits) før du planlegger produksjonskapasitet.

### Hvordan bruker jeg OpenAI Moderation API i Python?

Installer pakken `openai`, sett `OPENAI_API_KEY` og kall `client.moderations.create()` med modellen `omni-moderation-latest` og teksten din. For bilder sender du `input` som en liste med objekter. Hvert bildeelement har `type: "image_url"` og et `image_url`-objekt som inneholder `url`, som vist i referansen til OpenAI API nedenfor.
