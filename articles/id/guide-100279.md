# Biaya sebenarnya dari inferensi LLM adalah GPU yang tidak Anda gunakan

> Dua harga acuan lama untuk token input API berbeda 600 kali lipat. Biaya inferensi LLM dipengaruhi pemanfaatan GPU, jam sewa tak terpakai, dan tarif jam sibuk.



Sebuah studi tahun 2026 (arXiv:2603.28576, §4) membandingkan dua tolok ukur harga API. Untuk satu juta token input, studi itu menggunakan 60 USD sebagai tolok ukur harga GPT-3 tahun 2020 dan 0,10 USD untuk Gemini 2.0 Flash kelas ekonomis pada Februari 2025. Selisihnya 600 kali lipat. Untuk kelas ekonomis yang ditelitinya, studi itu memperkirakan harga turun menjadi separuh dalam 1,1 tahun.

Yang disembunyikan oleh berita utama tentang deflasi adalah hal yang benar-benar menentukan tagihan Anda: berapa banyak jam GPU Anda yang digunakan untuk pekerjaan produktif. Inferensi ditagih berdasarkan token, tetapi disediakan berdasarkan jam.

Lorong pusat data dengan deretan server GPU, sebagian besar menyala saat beroperasi sementara satu server gelap dan tidak digunakan

## Angka yang luput dari perhatian tim

Dalam pengujian vLLM pada Juni 2026 (arXiv:2606.11690, §§4–5), peneliti menjalankan Mixtral 8x7B Instruct pada presisi FP16 di dua GPU H100 NVL dengan paralelisme tensor (TP=2). Total tarif sewa GPU adalah 13,96 USD per jam. Pengujian menggunakan permintaan sintetis dengan 512 token input dan 256 token output per permintaan, dengan cache prefiks dinonaktifkan. Biaya dalam tabel diperoleh dengan membagi biaya sewa GPU dengan jumlah token output yang terukur pada periode yang sama. Laju permintaan dihitung berdasarkan jumlah permintaan yang dikirim ke server.

| Mixtral 8x7B pada dua GPU H100 NVL | Biaya efektif per 1M token output |
|----------------------------------------------|-----------------------------------|
| 1 permintaan per detik (hampir menganggur)   | sekitar \$15.25                   |
| 100 permintaan dikirim per detik (mendekati titik jenuh)                      | sekitar \$0.87                    |

Kedua pengukuran tersebut menghasilkan selisih biaya 17,5 kali lipat. Saat 25 permintaan per detik dikirim ke server, biayanya sekitar 0,95 USD per satu juta token output. Saat 100 permintaan per detik dikirim, server menyelesaikan sekitar 17,4 permintaan per detik. Pada enam konfigurasi H100 dengan beban yang diuji, studi itu mencatat biaya antara 0,21 USD dan 15,25 USD per satu juta token output. Angka tersebut adalah hasil pengukuran untuk beban kerja pengujian ini. Untuk penggunaan produksi, ukur throughput pada beban yang memenuhi target latensi Anda.

Dengan tarif sewa per jam yang sama, jika throughput output turun menjadi 40% dari nilai puncaknya, biaya per token output menjadi 2,5 kali lipat. Dalam contoh berikut, tingkat pemanfaatan adalah persentase dari throughput output puncak yang benar-benar dicapai layanan. GPU bisa melaporkan aktivitas tinggi meski hanya menghasilkan sedikit token output.

Inilah sebabnya dua tim yang menjalankan model yang sama bisa menyebutkan biaya satuan yang sangat berbeda. Satu tim menjalankan chatbot dengan beban yang naik turun pada tingkat pemanfaatan 40 persen; tim lainnya menjalankan pipeline batch yang jenuh pada 90 persen. Model, perangkat keras, dan harga yang tercantum sama. Biaya satuannya tidak. Saat vendor menyebutkan biaya per token, tanyakan asumsi tingkat pemanfaatan yang mendasarinya.

## Model berbobot terbuka memperburuk keadaan

Model mixture-of-experts (MoE) menggunakan sebagian bobotnya untuk setiap token. Mixtral 8x7B mengaktifkan sekitar 12,9 miliar parameter per token dan memiliki 46,7 miliar parameter secara keseluruhan. Untuk menjalankan model sepenuhnya di GPU, siapkan memori untuk seluruh bobot sesuai presisi penyimpanannya, ditambah cache KV dan kebutuhan memori runtime. Jumlah parameter aktif membantu memperkirakan kebutuhan komputasi per token. Bandwidth memori, pemilihan expert, dan ukuran batch juga memengaruhi throughput.

Perkirakan titik impas untuk beban kerja Anda sendiri. Bandingkan tagihan API untuk kombinasi token input dan output yang sama dengan total biaya sewa GPU dan pengoperasian layanan. Hitung seluruh jam sewa yang Anda perlukan, termasuk saat GPU menganggur. Ukur throughput output berdasarkan pola trafik Anda pada kondisi yang memenuhi target latensi. Harga API, konfigurasi model, dan tingkat pemanfaatan GPU semuanya memengaruhi hasilnya.

## Biaya tersembunyi kedua: waktu dalam sehari

Per 25 November 2026, jika Anda mengakses API DeepSeek secara langsung, tarif jam sibuk berlaku pukul 01:00–04:00 dan 06:00–10:00 UTC pada Senin hingga Jumat, kecuali hari libur nasional di Tiongkok. Dalam Waktu Standar India (IST, UTC+05:30), rentang waktunya adalah 06:30–09:30 dan 11:30–15:30. Tarif luar jam sibuk berlaku pada waktu lainnya, termasuk sepanjang hari pada akhir pekan dan hari libur nasional di Tiongkok. [Tarif API DeepSeek](https://api-docs.deepseek.com/quick_start/pricing/)

Pada hari kerja yang menerapkan tarif jam sibuk, pukul 10:00 IST (04:30 UTC) termasuk luar jam sibuk dan pukul 15:00 IST (09:30 UTC) termasuk jam sibuk. Dalam USD per satu juta token, tarif luar jam sibuk dan jam sibuk untuk `deepseek-flash` masing-masing adalah 0,003 dan 0,006 untuk token input dengan cache hit, 0,15 dan 0,30 untuk token input dengan cache miss, serta 0,60 dan 1,20 untuk output. Untuk `deepseek-v4-pro`, tarifnya masing-masing 0,022 dan 0,044, 0,66 dan 1,32, serta 1,98 dan 3,96, dengan urutan yang sama.

## Hal yang benar-benar mengubah angka

Jika Anda sedang menyusun anggaran inferensi, telusuri daftar ini sebelum membandingkan harga model:

1.  Dahulukan pemanfaatan daripada perangkat keras. H200 dengan tingkat pemanfaatan 40 persen bisa berbiaya lebih tinggi per token daripada H100 yang terisi penuh.
2.  Periksa apakah penyedia Anda memberikan tarif lebih rendah untuk cache hit. Menggunakan kembali system prompt yang panjang atau prefiks bersama dapat mengurangi tagihan input jika input tersebut memenuhi syarat untuk tarif cache hit.
3.  Gunakan proporsi trafik Anda pada jam sibuk dan luar jam sibuk sebagai bobot untuk menghitung biaya. Jika Anda mengakses API DeepSeek secara langsung, biaya pada jam sibuk menjadi dua kali lipat untuk penggunaan token dan kondisi cache yang sama.
4.  Proses pekerjaan latar belakang yang bisa menunggu dalam batch, misalnya pengindeksan RAG dan ekstraksi massal. Ukur throughput output dan latensi dengan pengaturan batch yang akan Anda gunakan.
5.  Untuk model MoE, gunakan jumlah parameter aktif untuk memperkirakan kebutuhan komputasi. Siapkan memori untuk seluruh bobot, cache KV, dan overhead runtime.
