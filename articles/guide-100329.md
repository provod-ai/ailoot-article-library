# Gemini API tooling updates: context circulation, tool combos and Maps grounding for Gemini 3

> Developers can combine function calling with built-in tools such as Google Search in a single Gemini API call, circulate context across tool calls and turns, and use Grounding with Google Maps with Gemini 3 models.



Mar 17, 2026

Google’s [March 17, 2026 announcement](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-api-tooling-updates/) described three changes to Gemini API workflows: combining built-in and application-defined tools, carrying tool context between steps, and adding Google Maps grounding to Gemini 3. The practical value is less glue code around a model’s tool choices; your application still owns execution, permissions, and validation.

## New tooling capabilities in the API

Google’s current documentation marks built-in/custom tool combination as a preview feature and lists the eligible Gemini models. Check the documentation before relying on it in production.
See the [official tool-combination guide](https://ai.google.dev/gemini-api/docs/tool-combination) for supported models, endpoints, and examples.

### Combine built-in and custom tools in the same interaction


A request can offer Gemini a built-in tool such as Google Search alongside a function that your application exposes. The model can select a useful sequence, for example searching public information and then asking your service to check an internal record. Your code must still run that function, validate its arguments, enforce access rules, and return the result. This can reduce application-side orchestration steps; it does not guarantee a faster response or remove the need for control flow.

### Cross-tool context circulation for built-in tools


In a multi-step exchange, later steps can use the earlier tool call and response kept in the interaction context. That avoids manually restating every result when a built-in tool informs a later action. Treat the retained context as conversation state: keep the interaction chain intact and decide what data is appropriate to send to each tool.

### Tool response IDs

An Interactions API `function_call` step carries the call’s `id`. To return the result, send a `function_result` with `call_id` set to that same value; the field name changes on the response. This pairing ties the result to its request, including when calls run in parallel. See Google’s [function-calling documentation](https://ai.google.dev/gemini-api/docs/function-calling).

## Expanded built-in tooling support


Tool combination and context handling are also documented for the broader API workflow. Google’s announcement says these capabilities are supported in generateContent as well; it recommends the [Interactions API](https://ai.google.dev/gemini-api/docs/interactions) when server-managed state and unified reasoning traces are useful. Check the current model and tool support before choosing an endpoint.

### Grounding with Google Maps for the Gemini 3 family


The announcement added Google Maps as a built-in option for Gemini 3. A location-aware request can draw on place details and local business information, which is useful for discovery tasks such as finding nearby services. Make the geographic scope explicit and verify the returned places and details before presenting them as current facts; grounding supplies context, not a guarantee that every result is complete or suitable. See the [Maps grounding guide](https://ai.google.dev/gemini-api/docs/maps-grounding) and its official examples.
