# Utforma verktyg för AI-agenter: lärdomar för arbetsflöden i Claude Code

> En praktisk guide till att definiera och testa verktyg för AI-agenter, med exempel från arbetsflöden för kodning.



En AI-agent behöver mer än en bra modell: den behöver verktyg som den kan välja, förstå och använda inom uppgiftens ramar. Guiden visar hur man utformar sådana gränssnitt med arbetsflöden för kodning som praktiskt exempel.

## Börja med en observerbar uppgift

Beskriv vad agenten ska uppnå innan du bestämmer vilka verktyg som ska göras tillgängliga. För en fråga om ett kodförråd kan uppgiften vara att hitta var en inställning läses och hänvisa till relevanta filer. En lämplig verktygsuppsättning kan låta agenten lista filer, söka text och läsa utvalda filer; den behöver inte behörighet att driftsätta något för att besvara frågan.

Skriv ned det förväntade resultatet och vilka åtgärder som ligger utanför uppgiften. Ett verktyg är användbart när dess indata och utdata hjälper agenten att fatta nästa beslut och när applikationen kan kontrollera att åtgärden är tillåten.

## Ge varje verktyg ett tydligt kontrakt

En verktygsbeskrivning bör ange vad verktyget gör, vilka indata som krävs och hur resultatet är utformat. Använd olika namn och parameterbeskrivningar när verktyg har liknande syften. Beskriv betydelsefulla begränsningar i en operation: ett sökverktyg kan exempelvis returnera en begränsad lista över matchande sökvägar i stället för innehållet i varje fil.

En illustrativ förfrågan till ett textsökverktyg kan innehålla en sökfråga och en katalog. Resultatet kan innehålla sökvägar och matchande radnummer. Applikationen bör validera katalogen och uttryckligen hantera saknade sökvägar eller misslyckade sökningar. En korrekt utformad förfrågan bevisar inte att det funna svaret är korrekt.

## Balansera flexibilitet och kontroll

Ett generellt skal kan stödja många uppgifter men ger också tillgång till ett brett utbud av åtgärder. Ett mer avgränsat verktyg kan göra en vanlig operation lättare att förstå och begränsa åtgärden det utför. Rätt val beror på uppgiften, miljön och de tillgängliga behörigheterna; fler verktyg ger inte automatiskt bättre resultat.

Håll den ursprungliga uppsättningen tillräckligt liten för att vara överskådlig. Lägg till ett specialiserat verktyg när observerade fel eller upprepat arbete motiverar det. Om ett verktyg kan ändra data eller kontakta en extern tjänst, gör effekten tydlig i beskrivningen och upprätthåll relevanta behörigheter i applikationen.

## Be om saknad information vid rätt tillfälle

En agent ska inte hitta på ett beslut som saknas. Om en uppgift verkligen beror på information som den inte kan hitta kan en strukturerad fråga presentera relevanta alternativ och förklara deras konsekvenser. Om oberoende arbete är redo kan arbetsflödet fortsätta med det medan svaret inväntas.

Håll frågorna konkreta. Om en rapport exempelvis kräver ett datumintervall som inte har angetts, fråga efter intervallet i stället för att be användaren upprepa hela uppdraget. Använd inte en fråga som ersättning för att kontrollera tillgänglig kontext.

## Testa verktyget och agenten tillsammans

Skapa en liten uppsättning representativa uppgifter: vanliga förfrågningar, tvetydiga indata, otillgängliga filer och försök att använda ett verktyg utanför dess avsedda område. Granska vilket verktyg som valdes, argumenten som skickades, resultatet som returnerades och det slutliga svaret. Ett lyckat API-anrop kan ändå returnera ofullständiga data, så kontrollera svaret mot det underliggande underlaget.

Ändra en del av gränssnittet åt gången när ett återkommande fel undersöks. Registrera versionen av verktygsbeskrivningen och upprepa det relevanta testet. För åtgärder med sidoeffekter, utred ett osäkert resultat innan du försöker igen; ett nytt försök kan upprepa en åtgärd som redan har lyckats.

## Tillämpa idéerna i ett arbetsflöde för kodning

Claude Code stöder arbetsflöden som kombinerar verktyg och återanvändbara instruktioner. Se aktuell [dokumentation om verktygsanvändning i Claude](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview) för API-kontraktet och [dokumentationen om färdigheter i Claude Code](https://code.claude.com/docs/en/skills) för hur återanvändbara instruktioner organiseras. Tillgänglighet och exakta gränssnitt kan ändras, så kontrollera dokumentationen för den version som används.

Samma designfrågor gäller i olika agentramverk: vad kräver uppgiften, vad kan agenten observera, vad kan varje verktyg ändra och hur ska resultatet verifieras?
