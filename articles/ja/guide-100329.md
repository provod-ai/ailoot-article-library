# Gemini API のツール機能アップデート：Gemini 3 のコンテキスト循環、ツールの組み合わせ、マップによるグラウンディング

> 開発者は、Google 検索などの組み込みツールと関数呼び出しを1回の Gemini API 呼び出しで組み合わせ、ツール呼び出しやターンをまたいでコンテキストを循環させ、Gemini 3 モデルで Google マップによるグラウンディングを利用できます。



2026年3月17日

Google の2026年3月17日の[発表](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-api-tooling-updates/)では、Gemini API の3つの更新が紹介されました。組み込みツールと独自関数の併用、複数ステップ間でのコンテキスト引き継ぎ、Gemini 3 での Google マップによるグラウンディングです。対応状況はモデルや API の版によって異なるため、実装前に最新ドキュメントを確認してください。

組み込みツールと独自関数の組み合わせは、ドキュメント上でプレビュー機能として案内されています。

## ツールと独自関数を同じリクエストに

エージェントは公開情報を検索した後、社内システムを確認できます。[公式ガイド](https://ai.google.dev/gemini-api/docs/tool-combination)では、Google 検索などの組み込みツールとアプリ側で宣言した関数を一緒に指定する方法を説明しています。モデルは呼び出しを要求し、実際の関数実行、引数の検証、アクセス許可はサーバーが担当します。まず[Google 検索の公式例](https://ai.google.dev/gemini-api/docs/google-search)を確認し、独自関数の入力と返却データを必要最小限にしましょう。

## コンテキストと呼び出し ID

前のツール呼び出しと応答を後続ステップに引き継げます。たとえば検索結果を予約関数へ渡せます。ただし、これはアプリの状態管理の代わりではありません。権限、ユーザー確認、エラー処理、再試行はバックエンドで制御します。Interactions API では、`function_call.id` は入力側の `function_result.call_id` と対応します。`function_response.id` が対応先ではありません。詳細は[公式の関数呼び出しガイド](https://ai.google.dev/gemini-api/docs/function-calling)を確認してください。

## Maps の位置情報

[Google マップによるグラウンディング](https://ai.google.dev/gemini-api/docs/maps-grounding)は、対応する Gemini 3 モデルで場所や地域の店舗情報を扱えるようにします。営業時間や移動時間は変わるため、モデルの対応を確認し、常に最新だと保証しないでください。Google はサーバー側の状態管理などを理由に[Interactions API](https://ai.google.dev/gemini-api/docs/interactions?ua=chat)を案内しており、ドキュメントには generateContent の対応も記載されています。最新の公式例から始め、入力検証とエラー処理をアプリ側でテストしてください.
