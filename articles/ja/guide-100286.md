# Zapierとn8nの比較：セルフホスティングで得るもの、手放すもの

> Zapierとn8nの料金、連携機能、ライセンス、セルフホスティングの要件、ワークフロー設計を比較し、チームに適した自動化ツールを選びましょう。



**Zapierはホスティング型サービスで、課金対象のアクションをタスク単位で計上します。[n8n](https://n8n.io/)の有料プランはワークフローの実行回数に基づいて課金され、セルフホスト版も提供されています。**

ワークフローを1,000回実行し、毎回12件の課金対象アクションが完了するとします。各アクションが1タスクを消費する場合、Zapierでは合計12,000タスクになります。これらの実行がすべてn8nプランの上限に算入される場合、1,000回の実行として記録されます。

一方で、手放すものも現実にあります。n8nを使うには、自分でインフラを運用するか、より小規模な連携機能のライブラリを受け入れるか、あるいはその両方が必要です。

- **Zapier**：幅広いアプリ連携、ホスティング型サービス、タスク単位の課金
- **n8n**：セルフホスト可能、有料プランは実行回数ベース、Sustainable Use Licenseに基づきソースを公開
- **選択を分ける問い**：制約はアプリの対応範囲ですか、それともワークフローの長さやデータの保管場所ですか？

## 早見比較

|  | Zapier | n8n |
|----|----|----|
| 課金単位 | 正常に完了した課金対象アクションを、適用されるレートでタスクとして計上 | 実行—ワークフロー全体の実行1回 |
| ステップ追加のコスト | 課金対象のアクションごとに増加 | 実行回数は変わらない |
| セルフホスティング | 不可 | 可能、Community Edition |
| ライセンス | プロプライエタリなSaaS | Sustainable Use License（ソース利用可能、OSIの定義上のオープンソースではない） |
| アプリ対応範囲 | 幅広いディレクトリ | より小規模な連携ライブラリ |
| コードステップ | JavaScriptとPython、サンドボックス環境 | JavaScriptとPythonのノード。セルフホスティング時はnpmパッケージも利用可能 |
| メンテナンス担当 | Zapier | セルフホスティングの場合は自分 |
| 適している用途 | 幅広いアプリへの対応、非技術者が管理する場合 | 長いワークフロー、データ管理、技術チーム |

## ステップごとの課金と実行ごとの課金、その違いが設計に与える影響

トリガーや新着データの確認にタスクは使われません。FormatterやFilterなどの組み込みツールもタスクを消費しません。課金対象のアクションによっては複数のタスクを消費するため、各アクションのレートを確認してください。

n8nの料金モデルでは、ワークフロー全体の1回の実行を1実行として数えます。プラットフォームの[料金ページ](https://n8n.io/pricing/)によると、ステップ数やワークフローを通過するデータ量は実行回数に影響しません。

設計上の影響は、両者で逆の方向に働きます。

必要に応じて、分岐にはPaths、データの変換にはFormatterを使えます。実際に実行される課金対象のアクションと、それぞれのレートからタスク数を見積もります。

n8nのプランで上限の対象となるワークフロー実行は、ステップ数にかかわらず1回と数えます。複数のレコードを1回でまとめて処理すると、上限に算入される実行回数を減らせることがあります。

この点は、Zapierから移行する人が見落としがちです。Zapierではレコードごとの実行が一般的で、アクション数が少なければ費用も抑えられることがあります。

## ライセンスについての正確な説明

n8nはオープンソースと説明されることがよくあります。しかし、実際にはオープンソースではなく、n8n自身もそう主張していません。n8nはfair-codeライセンスであるSustainable Use Licenseの下で配布されています。ソースコードはGitHubで公開されており、内部利用のために閲覧、変更、セルフホスティングできます。

このライセンスでは、n8nをホスト型サービスとして第三者に提供することは認められていません。Open Source Initiativeの定義では利用制限が認められないため、n8nは「オープンソース」という呼称を避けています。

多くのチームにとって、この違いは実務上あまり問題になりません。ライセンスで認められている社内でのセルフホスティングには、ワークフロー数や実行頻度の上限がありません。ただし、管理されたn8n環境の再販売を計画する代理店などには重要で、その場合は商用契約が必要です。

## セルフホスティングに実際にかかるコスト

「n8nは無料」という説明では、実際に支払う費用が見落とされています。

- **サーバーと、その保守を担当する人。** アップデート、バックアップ、TLS証明書、監視、そしてキューが停止したときに午前2時に対応する人
- **スケーリング作業。** 単一のインスタンスで処理しきれなくなった後、ワーカーノードを使うキューモードに移行する作業
- 機能はプランによって異なります。セルフホスト向けのBusinessにはSSOとLDAPが含まれます。Enterpriseではログのストリーミングと外部のシークレットストアとの連携も利用できます。
- **自力でのデバッグ。** ノードが正常に動作しないとき、問い合わせを送るサポート窓口がない場合があります

チーム内にインフラを担当する人がいなければ、n8nのセルフホスティングは節約ではなく負担になる可能性があります。n8n Cloudなら、運用の負担なしで実行ベースの課金を利用でき、多くの購入者にとってZapierとの比較対象になります。

## それぞれが優れている場面

**対応範囲ではZapierが優位です。** Zapierのアプリディレクトリは、n8nの連携ライブラリより幅広いです。利用中の技術スタックにニッチなツールが含まれている場合、Zapierならすでに対応している可能性が高いでしょう。n8nのHTTP RequestノードはあらゆるREST APIと通信できますが、「あらゆるAPI」とは、自分でドキュメントを読み、認証にも対応するということです。

**担当者が技術者でない場合もZapierが有利です。** エンジニアでなくてもZapを管理できます。一方、n8nではデータの形、式、JSONに慣れていることが前提です。セルフホスティングのn8nでは、サーバーの運用にも慣れている必要があります。

**長いワークフローではn8nが有利になる場合があります。** 実行ごとの課金では、ステップを追加しても料金は増えないため、多くのステップを含むワークフローに適していることがあります。

**データの保管場所と管理面ではn8nが有利になる場合があります。** 規制対象の業界や、顧客データを第三者のクラウド経由で送れない組織では、セルフホスティングが必要になることがあります。Zapierにはセルフホスティングの選択肢がありません。

**AI関連の作業にはn8nが適する場合があります。** LangChainノードとローカルモデルのサポートは、エージェント型のワークフローに役立つことがあります。

## 後悔しない選び方

次の順に検討してください。

1. **データの保管場所に厳格な要件がありますか？** はい → n8nをセルフホスティング。
2. **サーバーを担当する人はいますか？** いいえ → Zapierまたはn8n Cloud。
3. **ワークフローの長さはどのくらいですか？** 長いワークフローなら、n8nの課金モデルが魅力的になる可能性があります。
4. **利用する技術スタックはどの程度ニッチですか？** あまり知られていないツールを複数使うなら、ステップごとの料金を払ってもZapierの対応範囲に価値があるかもしれません。
5. **それ以外の場合** → チームのスキルと連携機能に最も合うツールから始めましょう。動いている自動化ツールから移行する方が、一度も稼働させられなかったものを完成させるより簡単です。

Makeはいくつかの点で両者の中間に位置します。Zapierと同じクラウドホスト型で、ビジュアルキャンバスはn8nに近い構成です。

## よくある質問

**n8nは無料ですか？**

Community Editionはセルフホスティングで無料で利用でき、ワークフロー数や実行回数に上限はありません。サーバーとメンテナンスの費用はかかります。n8n Cloudは有料で、セルフホスティングでEnterprise機能を利用するにはライセンスキーが必要です。

**n8nはオープンソースですか？**

いいえ。n8n自身もオープンソースとは主張していません。ソースコードはSustainable Use Licenseの下で利用でき、内部での利用と変更は認められていますが、n8nをホスト型サービスとして再販売することは禁止されています。利用制限があるライセンスは、OSIのオープンソースの定義を満たしません。

**n8nは本当にZapierより安くなりますか？**

Zapierで課金対象となるアクションが多い長いワークフローでは、n8nのほうが費用を抑えられる場合があります。実行回数と、課金対象アクションごとのタスク消費量を比較してください。セルフホストする場合は、インフラや保守の費用も含めます。

**Zapを自動でn8nに移行できますか？**

サポート対象の変換ツールがない場合があります。移行では作り直しが必要になることがあるため、導入を決める前に、最も負荷の大きいワークフローをn8nで試作しておくとよいでしょう。

**n8nには開発者が必要ですか？**

セルフホスティングの場合、誰かがサーバーを担当する必要があります。n8n Cloudならサーバー管理は不要ですが、n8nでワークフローを作るには、Zapierよりもデータ構造や式に慣れていることが求められます。

**Power Automateはどうですか？**

Microsoftはユーザー単位とプロセス単位のサブスクリプションを提供しています。対象となるフローには、実行回数に応じた従量課金も案内されています。利用するフローに合わせて料金体系を比較してください。
