# LLMルーターとは？

> LLMルーターがコスト、レイテンシ、機密性、品質に基づいてモデルを選択する方法と、ルーティングとゲートウェイやフォールバックとの関係について解説します。



> **定義:** LLMルーターは、アプリケーションと複数のAIモデルの間にあるコントロールプレーン層です。コスト、レイテンシ、品質、機密性に基づいて各リクエストを最適なモデルに送ります。支出を削減し、単一ベンダーへの依存を解消するとともに、自動フェイルオーバーを可能にします。

LLMルーター（*AIゲートウェイ*、*モデルルーター*、*LLMブローカー*とも呼ばれます）は、アプリケーションと複数のモデルの間にある層です。単一プロバイダーのAPIに合わせてコードを書く代わりに、アプリケーションからルーターを呼び出します。ルーターはリクエストごとに最適なモデルを選び、統一されたインターフェースを提供します。

- 各リクエストを分析する（タスクの種類、複雑さ、機密性）
- 最適なモデルを選択する（単純なタスクには低コストのモデル、難しいタスクには最先端モデル）
- プロバイダー間の負荷分散とフェイルオーバーを処理する
- 選んだモデルが必要な品質を満たす場合、ルーティングでコストを抑えられます。

## LLMルーターとAIゲートウェイの違いは？

両者の機能は重なっています。**ルーター**はリクエストごとのモデル選択を重視し、**AIゲートウェイ**は認証、ガバナンス、可観測性を加えます。**ブローカー**は、多数のプロバイダー間をベンダーに依存せず仲介することを重視します。堅牢なソリューションは、この3つすべてを実現します。

## LLMルーティングの仕組みは？

ルーターは、次の4つの基準に基づいて各リクエストを評価します。

- **コスト** — 単純なタスクは低コストのモデルに、コストの高いモデルは必要な場合にのみ割り当てます。
- **レイテンシ** — 時間が重要なリクエストは、高速で小規模なモデルに割り当てます。
- **機密性 / 保護クラス** — 機密性の高いリクエストは、承認済みのサービスと処理場所にのみ送信します。
- **品質** — 複雑なタスクは最先端モデルに割り当てます。

ルーティング方式には、**静的**（ルールベース）、**動的**（スコアリング／モデルベース）、**ハイブリッド**、<strong>学習ベース（RL）</strong>があります。

## LLMルーティングでどれくらい節約できる？（根拠）

- **RouteLLM**（UC Berkeley/LMSYS、arXiv 2406.18665）：著者らは、MT Benchで、すべてのリクエストにGPT-4を使用する場合に比べ、GPT-4のスコアの約95%を維持しながら、コストが約85%低下したと報告しています \[R1\]。
- **AWS Bedrock Intelligent Prompt Routing:** AWSは、同一モデルファミリー内でルーティングするとコストを最大30%削減できると見積もっています [\[R2\]](https://aws.amazon.com/bedrock/intelligent-prompt-routing/)。
- **コストの差:** 料金はモデルやプロバイダーによって異なります。モデルを選ぶ際は、入力トークンと出力トークンの最新料金を比較してください。


## ベンダーに依存しないルーティングでベンダーロックインを解消する

プロバイダー独自のルーターを使うと、より高いレベルでロックインされます。**ベンダーに依存しない**ブローカーは、プロバイダー（OpenAI、Anthropic、Google、Mistral、オープンウェイトモデル）をまたいで抽象化するため、モデルの切り替えはコード変更ではなく設定で済みます。これはAIベンダーロックインを直接解消する方法です。

## EU主権対応およびオンプレミスのLLMルーティング

ルーターは、機密性の高いリクエストの処理を、EU内またはオンプレミスで稼働する承認済みモデルに限定し、許可されている場合は公開情報に関するリクエストを低コストのクラウドモデルに送れます。各サービスのデータ処理と保存の方法を、適用される要件に照らして確認してください。

## 内製か購入か

総所有コストと、保護クラスやEU主権対応を組み込む必要があるかどうかが判断の決め手になります。

## よくある質問

**LLMルーターとは？**

LLMルーターは、アプリケーションと複数のAIモデルの間にあるソフトウェア層です。コスト、レイテンシ、品質、機密性に基づいて各リクエストを最適なモデルに振り分け、統一されたAPIを提供します。

**LLMルーティングの仕組みは？**

各リクエストを評価し、静的ルール、動的スコアリング、または学習済みポリシーを使ってモデルを選択します。単純なタスクは低コストのモデルに、難しいタスクは最先端モデルに送ります。

**LLMルーターはAIゲートウェイと同じもの？**

厳密には異なります。ルーターはリクエストごとのモデル選択を重視し、ゲートウェイは認証、ガバナンス、可観測性を加えます。堅牢なプラットフォームは両方に加えて、ベンダーに依存しない仲介機能も備えています。

**LLMルーターでどれくらい節約できる？**

RouteLLMの著者らは、MT Benchで、すべてのリクエストにGPT-4を使用する場合に比べ、GPT-4のスコアの約95%を維持しながら、コストが約85%低下したと報告しています。AWSは、同一モデルファミリー内でのルーティングで最大30%のコスト削減を報告しています。実際の削減幅はワークロードによって異なります。

**ルーティングによって回答の品質は低下する？**

品質はタスク、モデル、ルーティングルールによって変わります。実際のワークロードを代表するリクエストでルールをテストしてください。

**LLMルーターをオンプレミス / EU内で実行できる？**

はい。ルーターとモデルがその構成をサポートしていれば可能です。機密性の高いリクエストを扱えるサービスを指定し、適用されるデータ処理要件を確認してください。
