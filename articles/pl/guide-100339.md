# Gemini: jak wybrać między aplikacją a API

> Praktyczny przewodnik po wyborze między aplikacją Gemini a API, ocenie modeli i szacowaniu kosztów użycia.



Z Gemini można korzystać przez konsumencką aplikację Google lub integrować go z oprogramowaniem za pomocą API. Wybór punktu wyjścia zależy od tego, czy chcesz samodzielnie wykonać zadanie, czy zbudować powtarzalny proces dla innych.

## Zacznij od zadania

W przypadku jednorazowego zadania, takiego jak przygotowanie wiadomości lub rozwinięcie pomysłu, interaktywna aplikacja pozwala zadawać pytania i dopracowywać odpowiedź. Sprawdź wynik, zanim na nim polegniesz: płynna odpowiedź nadal może zawierać błąd, pomijać kontekst lub nieprawidłowo cytować źródło.

API przydaje się, gdy aplikacja musi wysyłać dane wejściowe i przetwarzać wyniki w ramach procesu. Na przykład aplikacja obsługi klienta może podsumować zgłoszenie dla osoby oceniającej. Programista musi obsłużyć instrukcje, dostęp do danych, błędy oraz sposób wyświetlania lub zapisywania wyników.

Aplikacja i API to różne produkty. Nie zakładaj, że funkcja, limit, subskrypcja lub ustawienie danych jednego z nich są automatycznie dostępne w drugim. Sprawdź dokumentację i ustawienia produktu oraz konta, których faktycznie używasz.

## Wybierz model do zadania

Zacznij od kilku reprezentatywnych przykładów zamiast wybierać model wyłącznie po nazwie. W zadaniu podsumowania uwzględnij krótką wiadomość, długą wiadomość i przypadek z brakującymi informacjami. Określ, co dobra odpowiedź musi zachować, czego nie może dopowiadać i jaką powinna mieć długość.

Jeśli zadanie obejmuje obrazy, dźwięk lub inne dane wejściowe, sprawdź, czy konkretny model i endpoint obsługują potrzebny format. Obsługiwane modalności, limity kontekstu i dostępność mogą różnić się między modelami i zmieniać się w czasie. Aktualne opcje i formaty żądań znajdziesz w [dokumentacji Gemini API](https://ai.google.dev/gemini-api/docs) Google.

## Oszacuj koszt na realistycznej próbce

W procesie korzystającym z API zapisz ilość danych wejściowych i wyjściowych zużytą przez mały, reprezentatywny zestaw żądań. Pomnóż zmierzone zużycie przez odpowiednie opublikowane ceny, uwzględniając każdy mający zastosowanie rodzaj danych wejściowych i wyjściowych. Następnie oszacuj częstotliwość uruchamiania procesu i uwzględnij zapas na ponowne próby oraz różnice długości odpowiedzi.

Traktuj wynik jako szacunek, a nie gwarantowany rachunek. Sprawdź aktualne [ceny Gemini API](https://ai.google.dev/gemini-api/docs/pricing), limity i ustawienia rozliczeń swojego konta. Subskrypcja aplikacji i korzystanie z API mogą podlegać różnym warunkom.

## Oceń przed skalowaniem

Porównaj wyniki z przykładami ocenionymi przez ludzi. W każdej odpowiedzi sprawdź fakty względem danych wejściowych, wymaganego formatu i zasad konkretnego zadania. Uwzględnij trudne przypadki oraz takie, których model powinien odmówić lub które powinien przekazać człowiekowi. Odpowiedź wyglądająca na poprawną nie musi być prawidłowa.

Śledź błędy i zmieniaj pojedynczo elementy procesu: instrukcje, przygotowanie danych wejściowych, model lub walidację wyników. Po zmianie powtórz ten sam zestaw testów. Jeśli zmieni się model lub rodzaj przychodzących danych, ponownie oceń wynik zamiast zakładać, że poprzednia ocena nadal obowiązuje.

## Świadomie obsługuj dane i błędy

Przesyłaj tylko dane potrzebne do zadania, a przed użyciem informacji wrażliwych sprawdź ustawienia przetwarzania danych danego produktu. Waliduj wyniki, zanim aplikacja podejmie na ich podstawie działania. Zaplanuj obsługę limitów częstotliwości, przekroczeń czasu i niepełnych wyników; pokaż komunikat umożliwiający działanie lub skieruj sprawę do przeglądu, zamiast po cichu uznawać błąd za ukończone zadanie.

W przypadku żądań mogących uruchomić działania zewnętrzne zapisuj operację i sprawdzaj jej status przed ponowną próbą. Odpowiedź utracona podczas przesyłania nie dowodzi, że działanie się nie powiodło.
