# Gemini API의 관리형 에이전트 소개

> Gemini API 관리형 에이전트를 위한 실용 가이드: 작업을 선택하고 결과를 검토하며 비용, 개인정보 보호와 실패에 대비합니다.



언어 모델에 요청하면 보통 답변이 생성되지만, 에이전트는 결과를 얻기 위해 중간 단계를 수행할 수도 있습니다. 예를 들어 데이터를 살펴보고 코드를 작성해 실행한 뒤 보고서를 반환할 수 있습니다. Google의 관리형 에이전트는 Gemini API를 통해 이런 작업을 위한 호스팅 작업 공간을 제공합니다. 이 기능은 미리보기이므로 프로덕션 업무에 도입하기 전에 현재 문서와 이용 가능 여부를 확인하세요.

이 가이드에서는 첫 작업을 선택하고 결과를 평가하며 관리형 에이전트의 운영에 필요한 일을 계획하는 방법을 설명합니다. 현재 요청 예시와 지원되는 에이전트 식별자는 Google의 [Gemini API 문서](https://ai.google.dev/gemini-api/docs)를 참고하세요.

## 제공업체가 관리하는 것은 무엇인가요?

관리형 에이전트 방식에서는 제공업체가 에이전트 환경을 실행하고 에이전트가 사용할 도구를 제공합니다. Google은 Antigravity 에이전트가 파일 작업, 코드 실행, 웹 사용을 할 수 있는 원격 샌드박스를 설명합니다. 애플리케이션은 여전히 목표를 정의하고 적절한 입력을 제공하며 반환된 결과의 수용 여부를 결정해야 합니다.

여러 단계와 중간 작업 공간이 필요한 작업에는 호스팅 환경이 유용합니다. 그러나 애플리케이션의 권한 부여, 검토 또는 데이터 처리 결정을 대신하지는 않습니다. 의존하기 전에 프로젝트와 버전에서 사용할 수 있는 도구와 환경 설정을 확인하세요.

## 범위가 제한된 첫 작업 선택하기

에이전트의 설명을 믿지 않고도 결과를 확인할 수 있는 작업부터 시작하세요. 작은 CSV 요약이 좋은 예입니다. 민감하지 않은 샘플을 제공하고 합계 표를 요청하며 출력 형식을 지정하세요. 몇 가지 합계를 독립적으로 계산해 결과와 비교합니다.

유용한 작업 설명에는 다음이 포함됩니다.

- 입력과 각 필드의 의미.
- 요약과 CSV 파일처럼 의도한 출력.
- 누락되거나 잘못된 값에 대한 규칙.
- 에이전트가 사용할 수 있는 데이터와 도구의 범위.
- 결과를 사용하기 전에 받는 사람이 수행할 수 있는 검사.

예를 들어 “이 판매 CSV 샘플을 월과 통화별로 요약하세요. 통화를 합치지 마세요. 날짜가 없는 행은 별도로 나열하고 각 합계에 사용한 계산을 제공하세요.”라고 요청할 수 있습니다. 첫 테스트에서는 메시지 전송, 프로덕션 데이터 변경 또는 다른 외부 작업을 요청하지 마세요.

## 상호작용 실행 및 검사하기

Google의 [시작 가이드](https://ai.google.dev/gemini-api/docs/get-started)에 따라 SDK와 자격 증명을 설정한 다음 관리형 에이전트 예시를 따르세요. 예시에는 에이전트 식별자, 입력과 원격 환경이 제공됩니다. 오래된 미리보기 식별자를 계속 사용할 수 있다고 가정하지 말고 Google이 현재 문서화한 식별자를 사용하세요.

마지막 문단만 보지 마세요. 반환된 상태와 출력, 사용하려는 파일을 확인하세요. 데이터 작업은 숫자를 원본과 비교하고, 생성된 스크립트는 통제된 환경에서 검토하고 테스트합니다. 웹 정보에 의존하는 작업이라면 인용된 출처를 열어 주장을 뒷받침하는지 확인하세요. 완성도 높아 보이는 결과에도 오류가 있을 수 있습니다.

여러 상호작용에 걸쳐 작업을 계속한다면 Google이 문서화한 환경 및 상호작용 수명 주기를 따르세요. 관련 식별자를 애플리케이션 작업 기록에 보관하고 만료나 실패를 명시적으로 처리하세요. 작업 공간이 무기한 유지된다고 가정하지 마세요.

## 맞춤형 에이전트에 명확한 지시 제공하기

Google은 관리형 에이전트에 맞춤 지시, 스킬과 데이터를 제공하는 방법도 문서화합니다. 이 기능으로 문서에 비밀 정보를 넣지 말고 작업과 출력 요구 사항을 설명하세요. 보고 작업에서는 데이터를 그룹화하는 방법, 불확실성을 표시하는 방법, 계산을 완료할 수 없을 때 할 일을 정의할 수 있습니다.

지시 파일을 버전 관리하고 애플리케이션 코드처럼 변경 사항을 검토하세요. 빈 파일, 예상치 못한 값, 의도된 범위 밖의 요청을 포함한 소규모 대표 입력 집합으로 새 버전을 테스트하세요. 출력이 바뀌면 조사할 수 있도록 각 평가에 사용한 버전과 입력을 기록하세요.

## 비용, 개인정보 및 실패에 대비하기

여러 단계의 에이전트는 결과를 반환하기 전에 모델을 여러 번 호출하거나 도구를 사용할 수 있습니다. 시험 전에 Google의 [가격 페이지](https://ai.google.dev/gemini-api/docs/pricing)와 프로젝트 한도를 확인하세요. 요금과 미리보기 조건은 변경될 수 있습니다. 대표 작업의 사용량을 측정하고 워크로드에 적합한 애플리케이션 수준의 예산을 설정하세요.

작업 절차에서 처리하도록 허용된 데이터만 전송하세요. 검색한 페이지와 업로드한 파일은 신뢰할 수 없는 입력으로 취급하고, 생성된 코드를 샌드박스 밖에서 실행하기 전에 검토하세요. 작업 시간이 초과되거나 도구가 실패하거나 에이전트가 불완전한 결과를 반환할 때의 대응을 정하세요. 부수 효과가 있는 작업을 재시도하면 효과가 반복될 수 있으므로 다시 시도하기 전에 원래 작업의 상태를 확인하세요.

## 언제 관리형 에이전트를 사용해야 하나요?

여러 도구 단계가 유용하고 사람이나 자동 검사가 출력을 검증할 수 있는 범위가 제한된 조사, 분석 또는 파일 생성 작업이라면 관리형 에이전트를 평가해 볼 만합니다. 예측 가능한 단일 변환에는 모델 직접 요청이나 일반 애플리케이션 코드가 더 운영하기 쉬울 수 있습니다. 품질, 지연 시간, 비용과 해당 용도에 필요한 검토량을 기준으로 방식을 비교하세요.
