# LLM 평가자의 편향을 테스트하는 방법

> LLM 평가자의 순서, 문체와 자기 선호 편향을 테스트하고 결과를 해석하는 실용적인 가이드입니다.



LLM 평가자는 개방형 AI 출력을 평가하는 데 도움이 되지만, 측정하려는 품질과 무관한 이유로 판정이 바뀔 수 있습니다. 통제된 비교는 평가 업무에 사용하기 전에 이런 약점 일부를 드러낼 수 있습니다.

## 평가 대상 정하기

기준 하나를 선택하고 검토자가 확인할 수 있게 정의하세요. 예를 들어 답변이 제공된 정책에 근거한 취소 기한을 명시하는지 확인합니다. 평가자와 사람 검토자에게 같은 질문, 원자료와 기준을 제공하고 합격, 불합격과 불확실한 사례의 의미를 기록하세요.

어렵고 모호한 사례를 포함해 실제 작업을 반영하는 사례를 수집하세요. 사람들이 대표 표본에 라벨을 붙이고 의견 차이를 해결하도록 합니다. 사람의 라벨은 테스트의 참조 기준이지 모든 사례에 명확한 답이 하나뿐이라는 보장은 아닙니다.

## 순서가 결과를 바꾸는지 테스트하기

쌍별 평가자에게 같은 두 답변을 두 순서로 제시하되 질문, 출처와 평가 기준은 고정하세요. 판정을 화면의 위치가 아닌 답변 자체에 연결합니다. 순서가 바뀌었을 때 선호 답변이 얼마나 자주 바뀌는지 세고 해당 사례를 살펴보세요.

순서를 무작위로 정하면 전체 집합에서 특정 위치에 체계적으로 노출되는 현상을 줄일 수 있지만 위치 편향이 사라졌다는 증거는 아닙니다. 순서가 결과를 바꾼다면 해당 쌍을 검토 대상으로 보내거나 비교 결과와 함께 불안정성을 보고하는 방안을 고려하세요.

## 문체와 내용 구분하기

기준과 관련된 사실은 보존하면서 표현 방식이 다른 테스트 쌍을 만드세요. 예를 들어 근거가 있는 간결한 답변을 관련 근거를 추가하지 않은 더 긴 버전과 비교합니다. 사용 전에 의도한 품질이 실제로 동등한지 검토자에게 확인받으세요.

평가자가 특정 문체를 선호한다면 설명과 구체적인 평가 기준을 살펴보세요. 적절한 경우 사례를 추가하고 기준을 명확히 한 뒤 프롬프트 수정에 사용하지 않은 사례로 다시 테스트하세요. 한 작업이나 모델에서 관찰한 선호가 모든 평가자에게 적용된다고 가정해서는 안 됩니다.

## 모델과 프롬프트의 영향 확인하기

서로 다른 모델의 출력을 비교할 때 평가 자료에서 불필요한 식별자를 제거하세요. 결정의 중요성에 따라 여러 평가 모델이나 사람 검토자를 사용해 표본을 테스트하세요. 모델이 자신의 출력을 평가하면 자기 선호를 보일 수 있고 다른 모델에도 고유한 편향이 있을 수 있습니다. 어느 쪽이든 실제 작업 흐름의 검증은 필요합니다.

평가 모델, 프롬프트, 사례와 출력 형식의 버전을 관리하세요. 변화의 원인을 진단할 때는 한 번에 한 구성 요소만 바꾸고 별도 보관한 집합에서 결과를 비교합니다. 짧은 근거 설명은 판정이 바뀐 이유를 찾는 데 도움이 될 수 있지만 그 자체도 모델 출력이므로 근거와 대조해야 합니다.

## 결과의 사용 방법 결정하기

잘못된 합격이나 불합격의 비용이 큰 사례를 포함해 사람이 검토한 사례에서 오류와 불일치를 측정하세요. 프로그램이 직접 검증할 수 있는 속성에는 결정론적 검사를 사용하고 불확실하거나 영향이 큰 사례는 자격 있는 검토자에게 보내세요. LLM 평가자는 제공받은 자료나 도구를 바탕으로 주장의 근거를 평가할 수 있지만 그 입력을 넘어 독립적으로 주장을 검증했다고 가정하지 마세요.

작업, 모델, 프롬프트 또는 입력 분포가 바뀌면 평가자를 다시 확인하세요. 안정적인 점수만으로 정확성이 증명되지는 않습니다. 평가 구축 지침은 [OpenAI의 평가 모범 사례](https://platform.openai.com/docs/guides/evaluation-best-practices)를 참고하세요.
