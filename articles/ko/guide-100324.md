# 소형 모델이 거대 모델을 이길 때.

> 소형 언어 모델이 잘하는 일과 어려워하는 일, 그리고 자신의 사례로 모델을 평가하는 방법.



이 가이드에서는 약 100억 파라미터를 소형 언어 모델(SLM)의 대략적인 상한으로 삼습니다. 분류, 추출, 라우팅, 짧은 요약처럼 반복되는 작업에서는 소형 모델이 더 큰 모델과 비슷한 품질을 낼 수 있습니다. 실제 요청에서 지연 시간과 비용을 비교하세요.

개방형 추론, 어려운 코딩, 폭넓은 세상 지식에서는 거대 모델이 여전히 우세합니다. 어떤 종류의 작업인지 파악하는 것이 중요합니다. 소형 언어 모델은 2026년에 충분히 발전해 모든 작업에서 이 질문을 해볼 만해졌습니다.

요약

- 약 100억 파라미터는 기준점입니다. 휴대전화나 노트북에서 돌아가는지는 메모리와 런타임에 달려 있습니다.
- 범위가 좁은 작업에서는 비용과 지연이 줄어들 수 있습니다. 개인정보 보호와 오프라인 사용은 배포 방식에 따라 다릅니다.
- 폭넓은 지식, 긴 다단계 추론, 어려운 코딩, 매우 긴 입력에서의 정보 회상에서는 약합니다.
- Gemma 4 E2B, Qwen3.5-4B, Ministral 3 3B, Granite 4.2 3B 등이 있습니다.
- 전환하기 전에 자신의 실제 업무 사례 50개로 소형 모델을 테스트하세요.

## 소형 언어 모델이란?

공식적인 기준선은 없습니다. NVIDIA 연구진의 유용한 실무 정의에 따르면 소형 모델은 일반 소비자용 기기에 들어가고 한 사람의 요청에 충분히 빠르게 응답하는 모델입니다. 이들은 2025년 기준으로 대부분의 10 billion개 미만 파라미터 모델이 여기에 해당한다고 설명했습니다.

파라미터는 모델이 학습 과정에서 배우는 숫자입니다. 새롭게 알아둘 만한 크기 표기 두 가지가 있습니다.

**유효 파라미터와 활성 파라미터**

Gemma 4 E4B의 전체 파라미터는 80억 개이며 Google 기준 유효 파라미터는 45억 개입니다. gpt-oss-20b의 전체 파라미터는 210억 개이고 토큰당 36억 개가 활성화됩니다. 모든 가중치를 담을 RAM, VRAM, 필요시 보조 저장 공간을 확보하세요.

## 소형 모델이 매우 좋아진 이유

세 가지 변화가 격차의 상당 부분을 좁혔습니다. 소형 모델은 이제 방대한 텍스트로 학습합니다. Liquid AI는 1.2 billion 파라미터의 LFM2.5를 28 trillion 토큰으로 학습했습니다. 소형 모델은 증류라고 부르는 과정을 통해 더 큰 모델로부터 학습합니다. 또한 모델 설계가 파라미터 하나하나에서 더 많은 성능을 끌어냅니다.

Qwen 평가에서 Qwen3.5-9B와 gpt-oss-120b는 GPQA Diamond에서 81.7점과 80.1점을 기록했습니다. LiveCodeBench v6에서는 65.6점과 82.7점이었습니다. 실제 작업에서 두 모델을 비교하세요.

## 소형 모델을 선택해야 하는 이유: 속도, 비용, 개인정보 보호, 오프라인 사용

장점은 실용적이며, 대부분은 규모가 커질수록 누적됩니다.

- **비용.** NVIDIA 연구는 7B 모델과 70B~175B 모델의 지연 시간, 에너지, 연산량에 10\~30배 차이가 있다고 추정했습니다. 합격 결과당 비용을 비교할 때 전력, 하드웨어, 재시도를 포함하세요.

- **속도.** 소형 모델은 지연을 줄일 수 있습니다. 예상 입력 길이와 부하에서 측정하세요.

- **개인정보 보호.** 처리, 도구, 로그가 모두 로컬에 있으면 프롬프트를 기기에 남길 수 있습니다.

- **오프라인 사용.** 파일을 내려받은 뒤 런타임과 도구가 로컬에서 동작하면 네트워크 없이 사용할 수 있습니다.

## 소형 모델이 잘하는 작업과 어려워하는 작업

소형 모델의 약점은 사실에 대한 기억입니다. Microsoft는 3.8 billion 파라미터 Phi-4-mini의 모델 카드에서 이 모델이 많은 사실 지식을 저장하기에는 너무 작다고 밝히며 검색과 함께 사용할 것을 제안합니다. 이 점은 모든 것에 영향을 줍니다.

**소형 모델이 강점을 보이는 작업**

- 분류와 라우팅: 티켓, 이메일, 의도
- 양식, 송장, 메시지에서 필드를 추출해 JSON으로 변환
- 제공된 짧은 텍스트 요약 및 다시 쓰기
- 번역: Gemma 4와 Qwen3.5는 다양한 언어를 지원
- 더 큰 에이전트 안에서 수행하는 단일의 명확한 단계

**소형 모델이 어려워하는 작업**

- 기억에 의존해 답하기: 사실을 지어내는 경우가 더 많음
- 긴 추론 및 계획 과정
- 여러 파일을 다루는 어려운 코딩
- 긴 입력 깊숙한 곳에 있는 세부 정보 찾기

마지막 약점은 큰 컨텍스트 수치 뒤에 가려져 있습니다. Gemma 4 E2B는 128,000 토큰을 입력받을 수 있지만, Google의 자체 장문 컨텍스트 검색 테스트(MRCR v2)에서 이 길이의 입력을 대상으로 평가했을 때 19.1%를 기록했습니다. 31B 모델은 66.4%를 기록했습니다.

## 소형 모델과 대형 모델을 비교하는 방법

벤치마크는 후보군을 좁혀줍니다. 최종 결정은 자신의 사례로 내려야 합니다. 오후 한나절이면 진행할 수 있는 테스트는 다음과 같습니다.

### 실제 사례 50개 수집하기

만든 사례가 아니라 로그나 받은 편지함에서 실제 입력을 가져오세요. 까다로운 사례와 정돈되지 않은 사례도 몇 개 포함하세요.

### ‘정답’의 기준 적어두기

레이블에는 정확한 답을, JSON에는 스키마 검사를, 자유 형식 텍스트에는 간단한 평가 기준을 사용하세요.

### 같은 프롬프트로 두 모델 실행하기

프롬프트, 설정, 사례를 동일하게 유지하세요. 응답 시간과 토큰 수를 포함해 모든 답변을 기록하세요.

### 블라인드 평가하기

어떤 모델이 작성했는지 모른 채 답변에 점수를 매기세요. 평가자 모델은 대량 평가에 도움이 되지만, 그 판단을 직접 표본 검사하세요.

### 토큰당 비용이 아니라 작업당 비용 비교하기

API에서는 입력, 출력, 재시도 요금을 합산하고 로컬에서는 하드웨어와 전력을 계산하세요. 기준을 통과한 결과당 비용을 비교하세요.

### 결정하기: 전환, 라우팅, 유지

소형 모델이 이기거나 비기면 전환하세요. 대부분의 사례에서 이기면 먼저 모든 요청을 소형 모델로 보내고, 답변이 검사 기준을 통과하지 못할 때 대형 모델로 올리세요.

모델 이름을 가리고 평가하세요. A와 B를 바꿔 다시 테스트하고 결과가 바뀐 쌍을 검토하세요.

```
You are grading two answers to the same task. You do not know which model wrote which.

Task: {task}
Reference answer, if any: {reference}

Answer A: {answer_a}
Answer B: {answer_b}

Judge only correctness, whether the instructions were followed, and the required format.
Return one JSON object. Set "winner" to "A", "B", or "tie" and "reason" to one sentence.
Example: {"winner":"A","reason":"A follows the requested schema."}
```

## FAQ

소형 언어 모델을 휴대전화에서 실행할 수 있나요?

네. Google은 휴대전화와 엣지 기기용으로 Gemma 4 E2B와 E4B를 만들었으며, Liquid AI는 LFM2.5-1.2B가 휴대전화 칩에서 1 GB 미만의 메모리로 실행된다고 보고합니다. 대형 클라우드 모델보다 지식이 적고 추론 능력이 약할 수 있습니다.

소형 모델은 양자화 모델과 같은 건가요?

아닙니다. 소형 모델은 파라미터가 더 적습니다. 양자화는 어떤 모델이든 파라미터를 더 적은 비트로 저장해 메모리 사용량을 줄입니다. 소형 모델을 양자화해 더 작게 만들 수도 있습니다.

소형 모델은 정확도가 낮나요?

폭넓은 지식과 어려운 추론에서는 대체로 그렇습니다. 명확한 지침과 프롬프트에 제공된 사실이 있는 범위가 좁은 작업에서는 좋은 소형 모델이 대형 모델에 맞먹는 경우가 많습니다. 결정하기 전에 자신의 작업에서 테스트하세요.

소형 모델을 미세 조정해야 하나요?

경우에 따라 다릅니다. 미세 조정은 고정된 출력 형식처럼 하나의 좁은 작업을 소형 모델에 가르치는 데 효과적이며, Gemma 4와 gpt-oss 같은 공개 모델은 미세 조정을 염두에 두고 출시되었습니다. 먼저 예시를 포함한 강력한 프롬프트를 시도하세요.

핵심 정리

- 약 100억 파라미터는 기준점입니다. 휴대전화나 노트북에서 돌아가는지는 메모리와 런타임에 달려 있습니다.
- 범위가 좁은 작업에서는 비용과 지연이 줄어들 수 있습니다. 개인정보 보호와 오프라인 사용은 배포 방식에 따라 다릅니다.
- 사실을 프롬프트에 제공하고 모델의 기억에 의존하지 마세요.
- 50개의 실제 사례로 테스트하고, 블라인드 평가를 한 뒤 작업당 비용을 비교하세요.
- 쉬운 작업은 소형 모델에, 어려운 작업은 대형 모델에 라우팅하면 어느 한쪽만 쓰는 것보다 나은 경우가 많습니다.
