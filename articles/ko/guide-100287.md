# LLM 라우터란 무엇인가요?

> LLM 라우터가 비용, 지연 시간, 기밀성, 품질을 기준으로 모델을 선택하는 방식과 라우팅이 게이트웨이 및 장애 조치와 어떤 관계가 있는지 알아보세요.



> **정의:** LLM 라우터는 애플리케이션과 여러 AI 모델 사이에 있는 제어 플레인 계층으로, 비용, 지연 시간, 품질, 기밀성을 기준으로 각 요청을 가장 적합한 모델에 전달합니다. 지출을 줄이고 단일 공급업체에 대한 의존성을 없애며 자동 장애 조치를 추가합니다.

LLM 라우터(*AI 게이트웨이*, *모델 라우터*, *LLM 브로커*라고도 함)는 애플리케이션과 여러 모델 사이에 있는 계층입니다. 애플리케이션에서 한 공급업체의 API를 대상으로 코드를 작성하는 대신 라우터를 호출하면, 라우터가 요청별로 최적의 모델을 선택하고 통합 인터페이스를 제공합니다.

- 각 요청을 분석합니다(작업 유형, 복잡도, 민감도).
- 최적의 모델을 선택합니다(단순한 작업에는 저렴한 모델, 어려운 작업에는 최첨단 모델).
- 공급업체 간 부하 분산과 장애 조치를 처리합니다.
- 선택한 모델이 품질 요건을 충족하면 라우팅으로 비용을 줄일 수 있습니다.

## LLM 라우터와 AI 게이트웨이: 차이점은 무엇인가요?

두 개념은 서로 겹칩니다. **라우터**는 요청별 모델 선택을 강조하고, **AI 게이트웨이**는 인증, 거버넌스, 관측 가능성을 더하며, **브로커**는 여러 공급업체 간 공급업체 중립적인 중개를 강조합니다. 견고한 솔루션은 이 세 가지 기능을 모두 제공합니다.

## LLM 라우팅은 어떻게 작동하나요?

라우터는 다음 네 가지 기준으로 각 요청을 평가합니다.

- **비용** — 단순한 작업은 저렴한 모델로 보내고, 비싼 모델은 필요한 경우에만 사용합니다.
- **지연 시간** — 시간에 민감한 요청은 빠르고 작은 모델로 보냅니다.
- **기밀성 / 보호 등급** — 민감한 요청은 승인된 서비스와 처리 위치로만 보냅니다.
- **품질** — 복잡한 작업은 최첨단 모델로 보냅니다.

라우팅은 **정적**(규칙 기반), **동적**(점수화 또는 모델 기반), **하이브리드**, **학습 기반(RL)** 방식일 수 있습니다.

## LLM 라우팅은 비용을 얼마나 절감하나요? (근거)

- **RouteLLM** (UC Berkeley/LMSYS, arXiv 2406.18665): 저자들은 MT Bench에서 모든 요청에 GPT-4를 사용하는 경우보다 비용이 약 85% 낮았고, GPT-4 점수의 약 95%를 유지했다고 보고했습니다 \[R1\].
- **AWS Bedrock Intelligent Prompt Routing:** AWS는 같은 모델 제품군 내에서 요청을 라우팅하면 비용을 최대 30% 절감할 수 있다고 추정합니다 [\[R2\]](https://aws.amazon.com/bedrock/intelligent-prompt-routing/).
- **비용 차이:** 요금은 모델과 공급업체에 따라 다릅니다. 모델을 선택할 때 현재 입력 토큰과 출력 토큰 요금을 비교하세요.


## 공급업체 중립적 라우팅: 공급업체 종속을 끝내는 방법

공급업체 자체 라우터를 사용하면 한 단계 위에서 해당 공급업체에 종속됩니다. **공급업체 중립적인** 브로커는 여러 공급업체(OpenAI, Anthropic, Google, Mistral, 오픈 웨이트 모델)를 추상화하므로 모델 전환이 코드 변경이 아닌 설정 변경으로 이루어집니다. 이는 AI 공급업체 종속을 직접 해결하는 방법입니다.

## EU 주권 및 온프레미스 LLM 라우팅

라우터는 민감한 요청을 EU 내 또는 온프레미스에서 실행되는 승인된 모델로 제한하고, 허용되는 경우 공개 요청을 더 저렴한 클라우드 모델로 보낼 수 있습니다. 각 서비스의 데이터 처리와 저장 방식이 적용되는 요건에 부합하는지 확인하세요.

## 직접 구축할까요, 구매할까요?

총소유비용과 보호 등급 및 EU 주권 요건을 기본 기능으로 구축해야 하는지가 선택을 좌우합니다.

## FAQ

**LLM 라우터란 무엇인가요?**

LLM 라우터는 애플리케이션과 여러 AI 모델 사이에 있는 소프트웨어 계층입니다. 비용, 지연 시간, 품질, 기밀성을 기준으로 각 요청을 가장 적합한 모델에 라우팅하며, 통합 API를 제공합니다.

**LLM 라우팅은 어떻게 작동하나요?**

각 요청을 평가하고 정적 규칙, 동적 점수화 또는 학습된 정책을 사용해 모델을 선택합니다. 단순한 작업은 저렴한 모델로, 어려운 작업은 최첨단 모델로 보냅니다.

**LLM 라우터는 AI 게이트웨이와 같은 것인가요?**

정확히 같지는 않습니다. 라우터는 요청별 모델 선택을 강조하고, 게이트웨이는 인증, 거버넌스, 관측 가능성을 더합니다. 견고한 플랫폼은 두 기능에 공급업체 중립적인 중개 기능까지 결합합니다.

**LLM 라우터는 비용을 얼마나 절감하나요?**

RouteLLM 저자들은 MT Bench에서 모든 요청에 GPT-4를 사용하는 경우보다 비용이 약 85% 낮았고, GPT-4 점수의 약 95%를 유지했다고 보고했습니다. AWS는 같은 모델 제품군 내에서 요청을 라우팅하면 비용을 최대 30% 절감할 수 있다고 추정합니다. 실제 절감 폭은 워크로드에 따라 달라집니다.

**라우팅이 답변 품질을 떨어뜨리나요?**

품질은 작업, 모델, 라우팅 규칙에 따라 달라집니다. 실제 워크로드를 대표하는 요청으로 규칙을 테스트하세요.

**LLM 라우터를 온프레미스나 EU에서 실행할 수 있나요?**

예. 라우터와 모델이 해당 배포 방식을 지원하면 가능합니다. 민감한 요청을 처리할 수 있는 서비스를 지정하고 적용되는 데이터 처리 요건을 확인하세요.
