# 텍스트 분류 파이프라인에서 LLM 특징 사용하기

> 분류 파이프라인에서 LLM이 생성한 특징을 사용하고 임계값과 보정을 평가하는 실용적인 가이드입니다.



언어 모델은 텍스트를 직접 분류하거나 다른 모델이 다른 데이터와 함께 사용할 신호를 생성할 수 있습니다. 어느 방식도 자동으로 더 나은 것은 아닙니다. 유용한 선택은 작업, 사용 가능한 라벨과 오류의 비용에 따라 달라집니다.

## 기준선부터 시작하기

목표 결과를 정의하고 내려야 할 결정을 반영하는 사례를 수집하세요. 지원 업무에서는 긴급한 사람의 검토가 필요한 문의를 식별하는 작업일 수 있습니다. 무엇을 긴급하다고 볼지 합의하고 모호한 사례를 포함하며 사람들이 어떻게 라벨을 붙였는지 기록하세요.

복잡성을 추가하기 전에 간단한 기준선을 테스트하세요. 규칙, 라벨을 반환하도록 지시받은 모델 또는 기존 라벨 데이터로 학습한 지도 분류기가 될 수 있습니다. 동일한 별도 보관 사례에서 방식을 비교하세요. 직접 LLM 분류기도 유용할 수 있으므로 다른 방식이 있다는 이유만으로 배제해서는 안 됩니다.

## 모델 출력을 특징으로 바꾸기

언어 모델에 최종 결정만 요청하는 대신 작업에 특화된 소수의 신호를 보고하도록 요청하세요. 지원 사례에서는 메시지가 서비스 중단이나 청구 관련 질문을 설명하는지 나타내는 신호일 수 있습니다. 후속 분류기는 제품 범주와 같은 사용이 허용된 구조화 필드와 함께 이 신호를 사용할 수 있습니다.

각 신호를 정확히 정의하고 출력 형식을 검증하세요. 생성된 신호는 틀리거나 누락될 수 있으며 후속 모델이 그런 오류에서 학습할 수 있습니다. 실제 결정을 내릴 때 사용할 수 없는 정보는 포함하지 마세요.

## 학습 전에 데이터 나누기

특징을 선택하거나 임계값을 조정하기 전에 학습 데이터를 검증 및 테스트 데이터와 분리하세요. 같은 고객의 메시지나 이후 기간의 메시지가 서로 관련된다면 시스템의 실제 사용 방식을 반영하는 분할을 선택하세요. 그렇지 않으면 테스트 집합의 정보가 학습에 유출되어 결과가 실제보다 좋아 보일 수 있습니다.

후속 모델은 학습 집합으로 학습시키세요. 검증 데이터로 특징과 결정 임계값을 선택한 다음 별도 테스트 집합에서 선택한 작업 흐름을 평가합니다. LLM 출력을 얻거나 파싱하지 못한 경우를 포함해 전체 파이프라인을 확인하고 성공한 호출만 평가하지 마세요.

## 결과의 영향에 맞춰 임계값 선택하기

분류기는 각 항목에 점수나 확률을 생성할 수 있습니다. 임계값은 그 값을 문의를 검토 대상으로 보내는 등의 행동으로 바꿉니다. 임계값을 바꾸면 정밀도와 재현율이 달라질 수 있지만 적절한 절충은 놓친 사례와 불필요한 검토의 비용에 따라 달라집니다.

점수를 확률로 해석하려면 적절한 별도 보관 데이터에서 보정 상태를 평가하세요. 로지스틱 회귀를 학습시키거나 모델에 신뢰도를 요청한다고 해서 보정된 확률이 보장되지는 않습니다. 분류 지표뿐 아니라 보정도 비교하고 중요한 집단과 드문 사례의 성능을 살펴보세요.

## 전체 작업 흐름 측정하기

동일한 평가 집합에서 기준선과 특징 기반 시스템을 비교하세요. 거짓 양성, 거짓 음성, 지연 시간, 비용, 실패하거나 사람의 검토가 필요했던 호출의 비율을 기록하세요. 더 복잡한 작업 흐름은 해당 작업에서 측정 가능한 이점으로 추가 운영 비용을 정당화해야 합니다.

프롬프트, 모델, 특징과 임계값의 버전을 추적하세요. 이들이 바뀌거나 유입 데이터가 변하면 다시 평가합니다. 평가의 생성과 유지에 관한 자세한 내용은 [OpenAI의 평가 모범 사례](https://platform.openai.com/docs/guides/evaluation-best-practices)를 참고하세요.
