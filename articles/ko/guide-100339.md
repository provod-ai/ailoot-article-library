# Gemini 앱과 API 중 선택하기

> Gemini 앱과 API 중 선택하고, 모델을 평가하며, 사용 비용을 추정하는 실용적인 가이드입니다.



Gemini는 Google의 소비자용 앱에서 사용하거나 API를 통해 소프트웨어에 통합할 수 있습니다. 직접 작업을 수행하려는지, 다른 사람을 위한 반복 가능한 작업 흐름을 구축하려는지에 따라 적합한 출발점이 달라집니다.

## 작업부터 살펴보기

메시지 초안을 작성하거나 아이디어를 탐색하는 일회성 작업에는 질문을 하고 답변을 다듬을 수 있는 대화형 앱이 적합합니다. 결과를 믿고 사용하기 전에 확인하세요. 유창한 답변에도 오류가 있거나 맥락이 빠지거나 출처가 잘못 인용될 수 있습니다.

애플리케이션이 작업 흐름의 일부로 입력을 보내고 출력을 처리해야 한다면 API가 유용합니다. 예를 들어 지원 애플리케이션이 사람이 검토할 수 있도록 문의를 요약할 수 있습니다. 개발자는 지시, 데이터 접근, 실패와 결과의 표시 또는 저장 방식을 처리해야 합니다.

앱과 API는 서로 다른 제품입니다. 한쪽의 기능, 한도, 구독 또는 데이터 설정이 다른 쪽에서도 자동으로 제공된다고 가정하지 마세요. 실제로 사용하는 제품과 계정의 문서와 설정을 확인하세요.

## 작업에 맞는 모델 선택하기

이름만 보고 모델을 선택하기보다 대표 사례 몇 가지부터 시작하세요. 요약 작업이라면 짧은 메시지, 긴 메시지와 정보가 누락된 사례를 포함하세요. 좋은 답변이 무엇을 보존해야 하고 무엇을 지어내면 안 되며 얼마나 길어야 하는지 정하세요.

작업에 이미지, 오디오 또는 다른 입력이 포함된다면 특정 모델과 엔드포인트가 필요한 형식을 지원하는지 확인하세요. 지원되는 입력 유형, 컨텍스트 한도와 이용 가능 여부는 모델마다 다를 수 있고 변경될 수 있습니다. 현재 옵션과 요청 형식은 Google의 [Gemini API 문서](https://ai.google.dev/gemini-api/docs)에서 확인하세요.

## 현실적인 샘플로 비용 추정하기

API 작업 흐름에서는 대표적인 소수의 요청이 사용한 입력과 출력의 양을 기록하세요. 측정된 사용량에 해당 공개 가격을 곱하고 적용되는 모든 입력 및 출력 유형을 고려합니다. 그런 다음 작업 흐름의 실행 빈도를 추정하고 재시도와 응답 길이 변동을 위한 여유를 두세요.

결과는 확정 청구액이 아닌 추정치로 취급하세요. 계정의 현재 [Gemini API 가격](https://ai.google.dev/gemini-api/docs/pricing), 할당량과 결제 설정을 확인하세요. 앱 구독과 API 사용에는 서로 다른 조건이 적용될 수 있습니다.

## 규모를 늘리기 전에 평가하기

사람이 검토한 사례와 결과를 비교하세요. 각 응답의 사실을 입력과 대조하고 요청된 형식과 작업별 규칙도 확인합니다. 어려운 사례와 모델이 거절하거나 사람에게 넘겨야 하는 사례를 포함하세요. 유효해 보이는 응답이 반드시 정확한 것은 아닙니다.

실패를 추적하고 지시, 입력 준비, 모델 또는 출력 검증 중 작업 흐름의 한 부분씩 수정하세요. 변경 후 같은 테스트 세트를 반복합니다. 모델이나 유입 데이터의 종류가 바뀌면 이전 평가가 여전히 유효하다고 가정하지 말고 결과를 다시 평가하세요.

## 데이터와 실패를 신중히 처리하기

작업에 필요한 데이터만 전송하고 민감한 정보를 사용하기 전에 해당 제품의 데이터 처리 설정을 검토하세요. 애플리케이션이 출력에 따라 행동하기 전에 출력을 검증합니다. 요청 한도, 시간 초과와 불완전한 결과에 대비하고, 실패를 완료된 작업으로 조용히 처리하는 대신 조치 가능한 오류를 표시하거나 검토 대상으로 보내세요.

외부 작업을 유발할 수 있는 요청은 작업 기록을 보관하고 재시도 전에 상태를 확인하세요. 전송 중 응답이 유실됐다고 해서 작업이 실패한 것은 아닙니다.
