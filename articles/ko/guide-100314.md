# LLM 추론 비용 최적화: AI 인프라 지출을 줄이는 전략

> 배치 처리와 양자화부터 API와 자체 호스팅의 비용 비교까지, LLM 추론 비용과 최적화 방법을 살펴봅니다.



## 소개

추론 비용은 AI 기반 제품의 반복적인 운영 비용이며 사용량에 따라 증가합니다. 비용은 모델, 워크로드, 하드웨어, 서빙 구성에 따라 달라집니다. 최적화 기법에는 양자화, 배칭, 캐싱, 모델 선택이 포함됩니다. 비용과 출력 품질에 미치는 영향은 구체적인 워크로드에 따라 다르므로 측정해야 합니다.

## 추론 비용의 구성

추론 비용은 연산, 메모리, 데이터 이동의 영향을 받습니다.

### 연산

표준 자기회귀 디코딩에서는 단계마다 시퀀스별로 새 토큰 하나를 예측합니다. 연산 요구량은 모델 크기, 아키텍처, 정밀도, 서빙 구현에 따라 달라집니다.

### 메모리

모델 가중치는 GPU 메모리를 차지하고, 키-값(KV) 캐시는 활성 시퀀스의 중간 어텐션 데이터를 저장합니다. 캐시 수요는 컨텍스트 길이와 동시 요청 수에 따라 증가하므로 서빙에서 중요한 제약이 될 수 있습니다.

### 대역폭

자기회귀 생성에서는 모델 가중치와 캐시 데이터가 메모리를 통해 반복적으로 이동합니다. 메모리 대역폭이 처리량을 제한할 수 있으며, 가중치 표현에 사용하는 바이트 수를 줄이면 데이터 이동량을 줄일 수 있습니다.

## 배치 추론과 실시간 추론의 절충

배치 처리는 요청을 묶어 하드웨어 활용률을 높입니다. 실시간 처리는 응답 지연 시간을 우선시합니다. 배치가 커지면 처리량이 향상될 수 있지만, 대기열이 지연 시간을 늘릴 수 있습니다. 적합한 방식은 요청 도착 패턴과 지연 시간 요구 사항에 따라 달라집니다.

채팅, 음성, 검색과 같은 애플리케이션에는 지연 시간이 짧은 서빙이나 작은 동적 배치가 적합할 수 있습니다. 데이터 보강, 콘텐츠 생성, 대량 분석과 같은 오프라인 작업은 대체로 더 큰 배치를 허용할 수 있습니다.

## 모델 양자화: INT8 vs INT4 vs FP8

양자화는 모델 가중치를 표현하는 데 사용하는 비트 수를 줄여 메모리 사용량과 대역폭 요구량을 낮출 수 있습니다. 처리량, 비용, 모델 품질에 미치는 효과는 하드웨어, 모델, 양자화 방식에 따라 다릅니다. 배포 전에 양자화된 모델을 실제 사용할 워크로드에서 평가하세요.

### FP8

FP8은 8비트 부동소수점 표현을 사용합니다. 지원 여부와 품질에 미치는 영향은 하드웨어와 모델에 따라 달라집니다. 낮은 정밀도 추론을 평가하는 팀이 출발점으로 삼을 수 있습니다.

### INT8

INT8은 가중치를 8비트 정수로 표현합니다. SmoothQuant 및 LLM.int8()과 같은 방법으로 모델을 양자화합니다. 선택한 모델과 배포 환경에서 품질과 성능을 측정하세요.

### INT4

INT4는 4비트 표현을 사용하므로 메모리 요구량을 더 줄일 수 있습니다. GPTQ 및 AWQ와 같은 방법을 가중치 양자화에 사용합니다. 품질에 미치는 영향은 다를 수 있으므로 관련 작업에서 결과를 평가하세요.

## 추측 디코딩

추측 디코딩의 한 가지 일반적인 방식에서는 더 작은 초안 모델이 토큰을 제안하고 대상 모델이 이를 검증합니다. 성능은 대상 모델이 초안 토큰을 받아들이는 빈도와 구현 방식에 따라 달라집니다. 배칭이 제한되는 지연 시간 민감 워크로드에서 평가할 수 있습니다.

vLLM 및 TensorRT-LLM과 같은 서빙 프레임워크에서 추측 디코딩을 구현할 수 있습니다. 대상 배포 환경에서 처리량, 지연 시간, 출력 동작을 테스트하세요.

## KV 캐시 최적화

KV 캐시는 활성 시퀀스의 중간 어텐션 값을 저장합니다. 메모리 수요는 모델 아키텍처, 컨텍스트 길이, 동시성에 따라 달라집니다. 캐시 관리 방식은 GPU당 처리 가능한 요청 수에 영향을 줄 수 있습니다.

### KV 캐시 양자화

KV 캐시 항목의 정밀도를 낮추면 메모리 사용량을 줄일 수 있습니다. 품질에 미치는 영향은 모델과 워크로드에 따라 달라집니다. 서빙 프레임워크의 지원과 구성 옵션은 각각 다릅니다.

### 프리픽스 캐싱

요청이 프리픽스를 공유할 경우 서빙 시스템은 해당 프리픽스의 캐시된 계산을 재사용할 수 있습니다. 구현 방식과 요청 패턴에 따라 공통 시스템 프롬프트나 컨텍스트 문서의 반복 작업을 줄일 수 있습니다.

### PagedAttention

PagedAttention은 KV 캐시 메모리를 블록 단위로 관리합니다. vLLM은 이를 사용해 캐시 할당과 공유를 관리합니다. 실제 효과는 서빙 워크로드와 구성에 따라 달라집니다.

## 배칭 전략

배칭 전략은 처리량과 지연 시간에 영향을 줍니다. 동적 배칭과 연속 배칭은 일반적인 요청 스케줄링 방식입니다. 프리필과 디코딩을 분리하는 것은 배칭과 결합할 수 있는 배포 방식입니다.

### 동적 배칭

동적 배칭은 일정 시간 동안 또는 배치 임계값에 도달할 때까지 요청을 모은 뒤 함께 처리합니다. 활용률을 높일 수 있지만 대기 시간 때문에 지연 시간이 늘어날 수 있습니다.

### 연속 배칭 (in-flight batching)

연속 배칭은 다른 시퀀스가 계속 처리되는 동안 완료된 시퀀스를 제거하고 새 시퀀스를 추가할 수 있습니다. 출력 길이가 다양할 때 유휴 작업을 줄일 수 있습니다. vLLM, TensorRT-LLM, TGI는 연속 배칭 구현을 제공합니다.

### 분리형 서빙

분리형 서빙에서는 입력 컨텍스트를 처리하는 프리필과 토큰을 생성하는 디코드를 별도의 GPU 리소스에 배치합니다. 성능 효과는 워크로드와 리소스 할당에 따라 달라집니다.

## 비용 절감을 위한 모델 증류

지식 증류는 더 작은 학생 모델이 더 큰 교사 모델의 선택된 동작을 재현하도록 학습합니다. 작은 모델은 의도된 작업에 더 적은 리소스를 필요로 할 수 있지만, 결과는 학습 데이터, 목적 함수, 평가 방식에 따라 달라집니다.

증류는 작업별로 이루어져야 합니다. 요약용으로 학습된 모델이 코드 생성에서도 잘 작동하지 않을 수 있습니다. 작은 모델이 요구 사항을 충족하는지 확인하려면 작업별 학습 데이터와 평가가 필요합니다. 목표 사용량에서 예상되는 서빙 절감액과 학습 및 배포 비용을 비교하세요.

## 추론 비용 비교 방법

텍스트 API는 청구 대상 입력 및 출력 토큰 수에 공급자의 과금 단위에 맞춰 각각의 요율을 곱합니다. 적용되는 경우 캐시나 배치 요율을 사용합니다. 자체 호스팅은 유휴 시간을 포함한 GPU 용량 비용에 기타 인프라와 운영 비용을 더합니다. 각 총액을 동일한 기간에 얻은 유효 응답 수로 나누고 품질과 지연 시간 목표를 동일하게 맞춰 비교합니다.

## 쿼리당 비용 모니터링

지연 시간과 품질에 더해 쿼리당 비용도 추적하세요. 유용한 지표는 다음과 같습니다.

- **생성당 비용** — 연산 비용을 생성 횟수로 나눈 값으로, 모델, 사용 사례, 프롬프트 템플릿별로 추적합니다.
- **토큰당 비용** — 연산 비용을 생성된 출력 토큰 수로 나눈 값입니다.
- **GPU 활용률** — 생성 중 GPU 활동을 워크로드 맥락에서 해석한 값입니다.
- **KV 캐시 적중률** — 재계산하는 대신 프리픽스 캐시에서 처리한 캐시 가능 작업의 비율입니다.

모니터링을 통해 지나치게 큰 프롬프트, 작업에 비해 비용이 과도한 모델, GPU를 충분히 활용하지 못하는 배칭 구성을 파악할 수 있습니다. 계측은 최적화 기회를 찾는 데 도움이 됩니다.

## 최적화 스택: 종합 적용

여러 기법을 조합할 수 있지만, 효과는 워크로드에 따라 달라지며 효과가 서로 곱해진다고 가정해서는 안 됩니다. 대상 워크로드에서 각 변경 사항을 측정하세요.

실용적인 평가 순서는 다음과 같습니다.

1. FP8과 같은 저정밀도 가중치를 평가합니다.
2. 서빙 프레임워크에서 연속 배칭을 검토합니다.
3. 반복되는 프리픽스에 대한 프리픽스 캐싱의 이점을 측정합니다.
4. KV 캐시 정밀도 옵션을 평가합니다.
5. 배칭이 제한되는 경우 추측 디코딩을 테스트합니다.
6. 대량 처리에 적합한 경로에 INT4 가중치를 평가합니다.
7. 작업별 증류 모델을 기존 모델과 비교합니다.

초기 단계에서는 서빙 프레임워크 기능과 애플리케이션 구성을 활용할 수 있습니다. 증류에는 학습 투자와 작업별 평가가 필요합니다.

## 결론

추론 비용 최적화는 지속적인 과정입니다. 양자화, 추측 디코딩, KV 캐시 관리, 배칭, 증류는 특정 워크로드를 기준으로 평가할 수 있는 선택지입니다. 변경 사항을 도입하면서 비용, 지연 시간, 출력 품질을 측정하세요.

하드웨어와 서빙 프레임워크는 계속 발전하고 있습니다. 추론 성능과 비용을 측정하는 팀은 모델과 사용 패턴이 바뀔 때 정보에 기반한 결정을 내릴 수 있습니다.
