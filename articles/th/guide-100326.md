# LLM router คืออะไร?

> ทำความเข้าใจการกำหนดเส้นทางโมเดล ส่วนประกอบของเราเตอร์ ข้อแลกเปลี่ยนระหว่างการสร้างเองกับการนำมาใช้ และกรณีที่อาจไม่จำเป็นต้องมีเราเตอร์



## LLM router คืออะไร — และคุณจำเป็นต้องใช้จริงหรือไม่?

เราเตอร์ LLM ทำงานระหว่างแอปพลิเคชันกับเอนด์พอยต์ของโมเดล สำหรับคำขออนุมานแต่ละครั้ง เราเตอร์สามารถเลือกโมเดล ผู้ให้บริการโมเดลนั้น หรือทั้งสองอย่าง กฎจะกำหนดว่าเมื่อใดควรลองเอนด์พอยต์อื่นหลังเกิดข้อผิดพลาด

คำนี้กำลังเป็นที่นิยม ซึ่งหมายความว่ามีการขยายความหมายให้ครอบคลุมสิ่งที่ไม่ควรนับรวมด้วย ก่อนประเมินหรือสร้างเราเตอร์ ควรทำความเข้าใจให้ชัดเจนก่อนว่าภายในมีอะไรอยู่จริง

## สิ่งสองอย่างที่แตกต่างกันใช้ชื่อเดียวกัน

**การกำหนดเส้นทางโมเดล** เลือกว่าโมเดลใดจะประมวลผลคำขอ โมเดลขนาดเล็กอาจเพียงพอสำหรับการจัดหมวดหมู่ทั่วไป ส่วนงานสังเคราะห์ที่ซับซ้อนอาจต้องใช้โมเดลที่มีความสามารถสูงกว่า **การกำหนดเส้นทางระหว่างผู้ให้บริการ** ช่วยคงโมเดลที่เลือกไว้และเปลี่ยนไปยังเอนด์พอยต์อื่นที่รองรับเมื่อผู้ให้บริการรายแรกมีภาระงานเกินชั่วคราว

**การกำหนดเส้นทางการเรียกเครื่องมือ** เลือกบริการที่จะดำเนินการหลังจากเอเจนต์เลือกเครื่องมือแล้ว การค้นเว็บอาจเริ่มจากดัชนีภายในและลอง API ค้นหาอื่นหากต้องการขอบเขตที่กว้างขึ้น บริการในลำดับนี้ทำงานประเภทเดียวกัน

ทั้งสองแบบใช้กฎจัดลำดับตัวเลือกที่ตรงตามข้อกำหนดของคำขอ คุณภาพคำตอบของโมเดลอาจประเมินล่วงหน้าได้ยาก ผลลัพธ์จากเครื่องมือบางแบบตรวจได้ง่ายกว่า เช่น ดูว่าดึงเนื้อหาบทความออกมาได้หรือไม่ การค้นหาอาจมีผลลัพธ์แต่ยังไม่ตอบคำถามของผู้ใช้

โพสต์นี้ครอบคลุมทั้งสองแบบ เพราะมีองค์ประกอบร่วมกัน

## ภายใน LLM router มีอะไรอยู่จริง

ตัดเรื่องการตลาดออกไป เราเตอร์มีองค์ประกอบสี่อย่าง หากผลิตภัณฑ์แสดงทั้งสี่อย่างให้คุณดูไม่ได้ ก็เป็นเพียงพร็อกซีที่มีความเห็นของตัวเอง

**นโยบาย** กรองตัวเลือกตามความสามารถที่คำขอต้องการก่อน แล้วเรียงตามคุณภาพที่คาดไว้ ราคา หรือเวลาตอบสนอง รายการลำดับความสำคัญแบบคงที่อาจเพียงพอ หากใช้ตัวจำแนกเลือกระดับโมเดล ให้ประเมินว่าช่วยให้อะไรดีขึ้น

**ตัวชี้วัดสถานะ** ติดตามอัตราข้อผิดพลาด จำนวนครั้งที่หมดเวลารอ และเปอร์เซ็นไทล์ของเวลาตอบสนองแยกตามเอนด์พอยต์ กำหนดเวลาสูงสุดต่อครั้งเพื่อให้การเรียกไปต่อได้หากเอนด์พอยต์ไม่ตอบ ใช้แนวโน้มจากหลายคำขอเพื่อตัดสินใจว่าจะข้ามเอนด์พอยต์ที่ทำงานได้แย่ลงชั่วคราวเมื่อใด

**กฎการเปลี่ยนไปใช้ตัวสำรอง** ระบุข้อผิดพลาดที่ให้ลองใหม่ได้ เช่น ภาระงานเกินชั่วคราวหรือหมดเวลารอในกรณีที่ส่งคำขอซ้ำได้อย่างปลอดภัย กำหนดกฎแยกสำหรับการค้นหาที่คืน HTTP 200 โดยไม่มีผลลัพธ์ จำกัดจำนวนครั้งและเวลารวม เมื่อไคลเอนต์หมดเวลารอ ผลของคำขอและค่าใช้จ่ายที่อาจเกิดขึ้นยังไม่แน่ชัด

**การบันทึกต้นทุน** บันทึกโมเดลและบริการที่ตอบกลับ เวลาตอบสนอง และข้อมูลการใช้งานกับค่าใช้จ่ายที่ทราบ ผูกทุกครั้งที่ลอง รวมถึงครั้งที่ไม่สำเร็จ เข้ากับคำขอเดียวกัน แยกต้นทุนประมาณการจากยอดที่ยืนยันแล้วเพื่อเปรียบเทียบค่าใช้จ่ายตลอดทั้งลำดับ

## สร้างเองหรือนำมาใช้?

เราเตอร์แบบง่ายเริ่มจากรายการเอนด์พอยต์ที่รองรับ เวลาสูงสุดต่อครั้ง เวลารวม กฎสำหรับตัวสำรอง และบันทึกการลองแต่ละครั้ง เก็บกฎไว้ในแอปพลิเคชันได้ตราบใดที่ยังตอบโจทย์งาน

นำโซลูชันมาใช้เมื่อคุณต้องการส่วนที่สร้างและดูแลรักษาเองได้ยุ่งยาก เช่น การเชื่อมต่อกับผู้ให้บริการที่ปรับตามการเปลี่ยนแปลงของ API การติดตามสถานะระบบพร้อมค่าเริ่มต้นที่เหมาะสม ตารางต้นทุนที่อัปเดตอยู่เสมอ และระบบจัดการการรับส่งข้อมูล เซิร์ฟเวอร์ MCP สามารถให้บริการเครื่องมือผ่านอินเทอร์เฟซเดียวและเลือกผู้ให้บริการที่จะดำเนินการเรียกได้

ตรวจสอบว่าคุณควบคุมข้อมูลรับรองของผู้ให้บริการ ส่งออกบันทึกการใช้งาน และเปลี่ยนเอนด์พอยต์โดยไม่ต้องเขียนคำสั่งเรียกใหม่ได้หรือไม่ เปรียบเทียบต้นทุนระหว่างเราเตอร์ที่ดูแลเองกับบริการโฮสต์ รวมค่าบริการเราเตอร์หากมี

## เมื่อเราเตอร์เกินความจำเป็น

ส่วนนี้พูดกันตรง ๆ เพราะบางครั้งคำตอบของคำถามในชื่อเรื่องก็คือไม่

เราเตอร์มักไม่จำเป็นสำหรับงานที่ไม่สำคัญและมีคำขอน้อย ซึ่งใช้โมเดลเดียวจากผู้ให้บริการรายเดียว ตัวอย่างเช่น หากจ่ายเดือนละ 40 ดอลลาร์ ให้เปรียบเทียบเงินที่อาจประหยัดได้กับต้นทุนพัฒนาและบำรุงรักษา

การผสานระบบขนาดเล็กอาจต้องการผู้ให้บริการสำรองเพียงรายเดียว จัดการข้อผิดพลาดชั่วคราวที่ระบุไว้ แล้วลองตัวสำรองที่รองรับภายในเวลาที่กำหนดหากส่งคำขอซ้ำได้อย่างปลอดภัย

รวมกฎไว้ที่เดียวหากหลายผู้ให้บริการรองรับงานเดียวกัน เหตุขัดข้องกระทบผู้ใช้ ต้นทุนที่วัดได้คุ้มกับการลงมือทำ หรือตรรกะการกำหนดเส้นทางกระจายอยู่ในแอปพลิเคชัน นโยบายร่วมช่วยให้ดูแลและทดสอบการตัดสินใจจากที่เดียวได้

เริ่มจากรายการเอนด์พอยต์ที่รองรับ ลำดับการลอง และเงื่อนไขที่ให้ลองครั้งต่อไปได้ ระยะแรกอาจใช้รายการคงที่ได้ เพิ่มตัวสำรองเมื่องานต้องการ
