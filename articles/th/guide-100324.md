# เมื่อโมเดลขนาดเล็กเอาชนะโมเดลยักษ์

> โมเดลภาษาขนาดเล็กทำอะไรได้ดี มีข้อจำกัดตรงไหน และจะประเมินโมเดลด้วยตัวอย่างของคุณเองได้อย่างไร



คู่มือนี้ใช้ประมาณหนึ่งหมื่นล้านพารามิเตอร์เป็นขอบเขตอ้างอิงของโมเดลภาษาขนาดเล็ก (SLM) ในงานที่ทำซ้ำอย่างการจัดประเภท ดึงข้อมูล กำหนดเส้นทาง และสรุปสั้น ๆ โมเดลเล็กอาจมีคุณภาพเทียบเท่าโมเดลใหญ่ ให้เปรียบเทียบความหน่วงและต้นทุนกับคำขอจริง

โมเดลยักษ์ยังเหนือกว่าในด้านการให้เหตุผลแบบปลายเปิด การเขียนโค้ดที่ยาก และความรู้รอบด้าน ทักษะสำคัญคือการรู้ว่างานของคุณเป็นงานประเภทใด และโมเดลภาษาขนาดเล็กก็เก่งขึ้นมากในปี 2026 จนควรพิจารณาคำถามนี้กับทุกงาน

สรุปสั้น ๆ

- ราวหนึ่งหมื่นล้านพารามิเตอร์เป็นเกณฑ์อ้างอิง การรันบนมือถือหรือคอมพิวเตอร์ขึ้นกับหน่วยความจำและสภาพแวดล้อม
- โมเดลเล็กอาจลดต้นทุนและความหน่วงได้ในงานเฉพาะ ความเป็นส่วนตัวและการใช้ออฟไลน์ขึ้นกับการติดตั้ง
- โมเดลขนาดเล็กมีข้อจำกัดด้านความรู้รอบด้าน การให้เหตุผลหลายขั้นตอนที่ยาวนาน การเขียนโค้ดที่ยาก และการจดจำข้อมูลจากอินพุตที่ยาวมาก
- ตัวอย่างได้แก่ Gemma 4 E2B, Qwen3.5-4B, Ministral 3 3B และ Granite 4.2 3B
- ทดสอบโมเดลขนาดเล็กด้วยตัวอย่างจริง 50 รายการจากงานของคุณเองก่อนเปลี่ยนไปใช้

## อะไรจึงถือว่าเป็นโมเดลภาษาขนาดเล็ก?

ไม่มีเกณฑ์ตัดแบ่งอย่างเป็นทางการ นิยามใช้งานที่เป็นประโยชน์มาจากนักวิจัยของ NVIDIA: โมเดลขนาดเล็กคือโมเดลที่ทำงานบนอุปกรณ์ผู้บริโภคทั่วไปได้ และตอบสนองเร็วพอที่จะรองรับคำขอของผู้ใช้หนึ่งคน ในปี 2025 นักวิจัยระบุว่าโดยมากหมายถึงโมเดลที่มีพารามิเตอร์ต่ำกว่า 10 พันล้านตัว

พารามิเตอร์คือตัวเลขที่โมเดลเรียนรู้ระหว่างการฝึก มีคำเรียกขนาดใหม่สองคำที่ควรรู้จัก:

**พารามิเตอร์เชิงผลและพารามิเตอร์ที่ทำงาน**

Gemma 4 E4B มีพารามิเตอร์รวม 8 พันล้าน โดยมี 4.5 พันล้านพารามิเตอร์เชิงผลตามเกณฑ์ของ Google ส่วน gpt-oss-20b มีรวม 21 พันล้านและทำงาน 3.6 พันล้านต่อโทเคน ให้เผื่อพื้นที่สำหรับค่าน้ำหนักทั้งหมดใน RAM, VRAM และพื้นที่จัดเก็บเสริมที่ใช้

## เหตุใดโมเดลขนาดเล็กจึงเก่งขึ้นมาก

มีสามปัจจัยที่ช่วยลดช่องว่างลงได้มาก ปัจจุบันโมเดลขนาดเล็กฝึกด้วยข้อความจำนวนมหาศาล: Liquid AI ฝึก LFM2.5 ซึ่งมีพารามิเตอร์ 1.2 พันล้านตัวด้วยโทเค็น 28 ล้านล้านตัว โมเดลเหล่านี้เรียนรู้จากโมเดลที่ใหญ่กว่าในกระบวนการที่เรียกว่าการกลั่นความรู้ และการออกแบบยังช่วยให้ใช้พารามิเตอร์แต่ละตัวได้คุ้มค่าขึ้น

ในการประเมินของ Qwen คะแนนของ Qwen3.5-9B และ gpt-oss-120b ใน GPQA Diamond คือ 81.7 และ 80.1 ใน LiveCodeBench v6 ได้ 65.6 และ 82.7 ควรเปรียบเทียบกับงานของคุณเอง

## เหตุใดจึงเลือกโมเดลขนาดเล็ก: ความเร็ว ค่าใช้จ่าย ความเป็นส่วนตัว และการใช้งานออฟไลน์

ประโยชน์เหล่านี้นำไปใช้ได้จริง และส่วนใหญ่ยิ่งเพิ่มขึ้นเมื่อใช้งานในวงกว้าง

- **ค่าใช้จ่าย** งานวิจัยของ NVIDIA ประเมินความต่าง 10–30 เท่าด้านความหน่วง พลังงาน และการคำนวณ เมื่อเปรียบเทียบโมเดล 7B กับโมเดล 70B ถึง 175B ให้นับค่าไฟ ฮาร์ดแวร์ และการลองซ้ำในต้นทุนต่อผลลัพธ์ที่ผ่านเกณฑ์

- **ความเร็ว** โมเดลเล็กอาจลดความหน่วงได้ ให้วัดเมื่อใช้ความยาวอินพุตและภาระงานตามที่คาดไว้

- **ความเป็นส่วนตัว** พรอมป์ต์อยู่ในอุปกรณ์ได้เมื่อการประมวลผล เครื่องมือ และบันทึกอยู่ในเครื่องทั้งหมด

- **การใช้งานออฟไลน์** หลังดาวน์โหลดไฟล์ คุณใช้โดยไม่ต้องต่อเครือข่ายได้หากสภาพแวดล้อมรันไทม์และเครื่องมือทำงานในเครื่อง

## งานที่โมเดลขนาดเล็กทำได้ดีและทำได้ไม่ดี

จุดอ่อนของโมเดลขนาดเล็กคือการจดจำข้อเท็จจริง การ์ดโมเดลของ Microsoft สำหรับ Phi-4-mini ซึ่งมีพารามิเตอร์ 3.8 พันล้านตัว ระบุว่าโมเดลมีขนาดเล็กเกินกว่าจะเก็บความรู้เชิงข้อเท็จจริงได้มาก และแนะนำให้ใช้คู่กับการค้นหา เรื่องนี้ส่งผลต่อทุกอย่าง:

**โมเดลขนาดเล็กทำได้ดีในเรื่อง**

- การจำแนกและกำหนดเส้นทาง: ทิกเก็ต อีเมล และเจตนา
- การดึงฟิลด์เป็น JSON จากแบบฟอร์ม ใบแจ้งหนี้ และข้อความ
- การสรุปและเขียนข้อความสั้น ๆ ที่คุณป้อนใหม่
- การแปล โดย Gemma 4 และ Qwen3.5 รองรับภาษาอย่างกว้างขวาง
- ขั้นตอนเดียวที่กำหนดไว้อย่างชัดเจนภายในเอเจนต์ขนาดใหญ่

**โมเดลขนาดเล็กมีปัญหากับเรื่อง**

- การตอบจากความจำ ซึ่งมีโอกาสแต่งข้อเท็จจริงขึ้นมามากกว่า
- การให้เหตุผลและการวางแผนเป็นลำดับยาว
- การเขียนโค้ดที่ยากและเกี่ยวข้องกับหลายไฟล์
- การค้นหารายละเอียดที่อยู่ลึกในอินพุตยาว ๆ

จุดอ่อนข้อสุดท้ายถูกบดบังด้วยตัวเลขบริบทขนาดใหญ่ Gemma 4 E2B รับโทเค็นได้ 128,000 ตัว แต่ในการทดสอบการค้นคืนข้อมูลจากบริบทยาวของ Google เองที่ความยาวดังกล่าว (MRCR v2) ได้คะแนน 19.1% เทียบกับ 66.4% ของโมเดล 31B

## วิธีทดสอบโมเดลขนาดเล็กเทียบกับโมเดลขนาดใหญ่

เกณฑ์มาตรฐานช่วยจำกัดตัวเลือก แต่มีเพียงตัวอย่างของคุณเองเท่านั้นที่ตัดสินได้ นี่คือการทดสอบที่คุณทำได้ภายในช่วงบ่าย:

### รวบรวมตัวอย่างจริง 50 รายการ

ดึงอินพุตจริงจากบันทึกหรือกล่องจดหมายของคุณ ไม่ใช่ตัวอย่างที่แต่งขึ้น ใส่กรณียาก ๆ และกรณีที่ไม่เป็นระเบียบไว้ด้วย

### จดบันทึกว่าอะไรคือคำตอบที่ “ถูกต้อง”

ใช้คำตอบที่แน่นอนสำหรับป้ายกำกับ ตรวจสอบสคีมาสำหรับ JSON และใช้เกณฑ์ประเมินสั้น ๆ สำหรับข้อความอิสระ

### รันโมเดลทั้งสองด้วยพรอมป์ต์เดียวกัน

ใช้พรอมป์ต์ การตั้งค่า และตัวอย่างชุดเดียวกัน บันทึกคำตอบทุกข้อ พร้อมเวลาตอบสนองและจำนวนโทเค็น

### ให้คะแนนโดยไม่รู้ว่าใครเป็นผู้ตอบ

ให้คะแนนคำตอบโดยไม่ทราบว่าโมเดลใดเป็นผู้เขียน โมเดลผู้ตัดสินช่วยประเมินงานจำนวนมากได้ แต่สุ่มตรวจคำตัดสินด้วยตัวคุณเอง

### เปรียบเทียบค่าใช้จ่ายต่องาน ไม่ใช่ต่อโทเค็น

ถ้าใช้ API ให้รวมค่าอินพุต เอาต์พุต และการลองซ้ำ ถ้ารันเองให้คิดฮาร์ดแวร์และไฟฟ้า เปรียบเทียบต้นทุนต่อผลลัพธ์ที่ผ่านเกณฑ์

### ตัดสินใจ: เปลี่ยนไปใช้ กำหนดเส้นทาง หรือใช้ต่อ

หากโมเดลขนาดเล็กชนะหรือเสมอ ให้เปลี่ยนไปใช้ หากชนะในกรณีส่วนใหญ่ ให้ส่งทุกอย่างไปที่โมเดลนั้นก่อน แล้วส่งต่อไปยังโมเดลขนาดใหญ่เมื่อคำตอบไม่ผ่านการตรวจสอบของคุณ

ซ่อนชื่อโมเดล สลับ A กับ B แล้วทดสอบซ้ำ ตรวจคู่ที่คำตัดสินเปลี่ยนไป

```
You are grading two answers to the same task. You do not know which model wrote which.

Task: {task}
Reference answer, if any: {reference}

Answer A: {answer_a}
Answer B: {answer_b}

Judge only correctness, whether the instructions were followed, and the required format.
Return one JSON object. Set "winner" to "A", "B", or "tie" and "reason" to one sentence.
Example: {"winner":"A","reason":"A follows the requested schema."}
```

## คำถามที่พบบ่อย

โมเดลภาษาขนาดเล็กทำงานบนโทรศัพท์ของฉันได้ไหม?

ได้ Google สร้าง Gemma 4 E2B และ E4B สำหรับโทรศัพท์และอุปกรณ์เอดจ์ ส่วน Liquid AI รายงานว่า LFM2.5-1.2B ทำงานโดยใช้หน่วยความจำน้อยกว่า 1 GB บนชิปโทรศัพท์ คาดว่าจะมีความรู้น้อยกว่าและให้เหตุผลได้อ่อนกว่าโมเดลคลาวด์ขนาดใหญ่

โมเดลขนาดเล็กเหมือนกับโมเดลที่ผ่านการควอนไทซ์หรือไม่?

ไม่เหมือนกัน โมเดลขนาดเล็กมีพารามิเตอร์น้อยกว่า การควอนไทซ์เก็บพารามิเตอร์ของโมเดลใดก็ได้ด้วยจำนวนบิตที่น้อยลง จึงใช้หน่วยความจำน้อยลง คุณสามารถควอนไทซ์โมเดลขนาดเล็กเพื่อให้มีขนาดเล็กลงไปอีก

โมเดลขนาดเล็กแม่นยำน้อยกว่าหรือไม่?

โดยทั่วไปใช่ สำหรับความรู้รอบด้านและการให้เหตุผลที่ยาก แต่ในงานเฉพาะที่มีคำสั่งชัดเจนและมีข้อเท็จจริงอยู่ในพรอมป์ต์ โมเดลขนาดเล็กที่ดีมักทำได้ทัดเทียมโมเดลขนาดใหญ่ ทดสอบกับงานของคุณก่อนตัดสินใจ

ฉันควรปรับแต่งโมเดลขนาดเล็กเพิ่มเติมหรือไม่?

บางครั้ง การปรับแต่งเพิ่มเติมเหมาะอย่างยิ่งสำหรับสอนโมเดลขนาดเล็กให้ทำงานเฉพาะอย่าง เช่น ใช้รูปแบบเอาต์พุตแบบตายตัว และโมเดลเปิดอย่าง Gemma 4 และ gpt-oss ก็เผยแพร่โดยคำนึงถึงการปรับแต่งเพิ่มเติม ลองใช้พรอมป์ต์ที่แข็งแกร่งพร้อมตัวอย่างก่อน

ประเด็นสำคัญ

- ราวหนึ่งหมื่นล้านพารามิเตอร์เป็นเกณฑ์อ้างอิง การรันบนมือถือหรือคอมพิวเตอร์ขึ้นกับหน่วยความจำและสภาพแวดล้อม
- โมเดลเล็กอาจลดต้นทุนและความหน่วงได้ในงานเฉพาะ ความเป็นส่วนตัวและการใช้ออฟไลน์ขึ้นกับการติดตั้ง
- ใส่ข้อเท็จจริงไว้ในพรอมป์ต์ อย่าพึ่งพาความจำของโมเดล
