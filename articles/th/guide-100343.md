# การใช้คุณลักษณะจาก LLM ในขั้นตอนจำแนกข้อความ

> คู่มือปฏิบัติในการใช้คุณลักษณะที่ LLM สร้างในขั้นตอนจำแนก และประเมินเกณฑ์ตัดสินกับการปรับเทียบ



โมเดลภาษาสามารถจำแนกข้อความโดยตรง หรือสร้างสัญญาณให้โมเดลอื่นใช้ร่วมกับข้อมูลอื่นได้ ไม่มีแนวทางใดดีกว่าโดยอัตโนมัติ ทางเลือกที่มีประโยชน์ขึ้นอยู่กับงาน ป้ายกำกับที่มี และต้นทุนของความผิดพลาด

## เริ่มจากวิธีพื้นฐาน

กำหนดผลลัพธ์และรวบรวมตัวอย่างที่สะท้อนการตัดสินใจที่ต้องทำ สำหรับขั้นตอนงานสนับสนุน งานอาจเป็นการระบุคำร้องที่ต้องให้มนุษย์ตรวจอย่างเร่งด่วน ตกลงกันว่าอะไรนับว่าเร่งด่วน รวมกรณีกำกวม และบันทึกวิธีที่มนุษย์ติดป้ายกำกับ

ทดสอบวิธีพื้นฐานที่เรียบง่ายก่อนเพิ่มความซับซ้อน อาจเป็นกฎ โมเดลที่ได้รับพรอมป์ต์ให้ส่งป้ายกำกับ หรือโมเดลจำแนกแบบมีผู้สอนที่ฝึกจากข้อมูลติดป้ายที่มีอยู่ เปรียบเทียบแนวทางบนตัวอย่างชุดเดียวกันที่กันไว้ การให้ LLM จำแนกโดยตรงอาจมีประโยชน์ ไม่ควรปฏิเสธเพียงเพราะมีแนวทางอื่น

## เปลี่ยนผลลัพธ์ของโมเดลเป็นคุณลักษณะ

แทนที่จะขอเพียงการตัดสินสุดท้ายจากโมเดลภาษา ให้ขอชุดสัญญาณเฉพาะงานจำนวนเล็กน้อย ในตัวอย่างงานสนับสนุน สัญญาณอาจระบุว่าข้อความกล่าวถึงบริการขัดข้องหรือคำถามเรื่องการเรียกเก็บเงิน โมเดลจำแนกขั้นปลายสามารถใช้สัญญาณเหล่านี้ร่วมกับฟิลด์แบบมีโครงสร้างที่ได้รับอนุญาต เช่น หมวดหมู่ผลิตภัณฑ์

กำหนดสัญญาณแต่ละตัวให้ชัดเจนและตรวจสอบรูปแบบผลลัพธ์ สัญญาณที่สร้างขึ้นอาจผิดหรือขาดหาย และโมเดลขั้นปลายอาจเรียนรู้จากข้อผิดพลาดเหล่านั้น อย่ารวมข้อมูลที่ไม่มีให้ใช้ในเวลาตัดสินใจจริง

## แบ่งข้อมูลก่อนฝึก

แยกข้อมูลฝึกออกจากข้อมูลตรวจสอบและข้อมูลทดสอบก่อนเลือกคุณลักษณะหรือปรับเกณฑ์ตัดสิน หากข้อความจากลูกค้ารายเดียวกันหรือจากช่วงเวลาภายหลังมีความเกี่ยวข้องกัน ให้เลือกวิธีแบ่งที่สะท้อนการใช้งานจริง มิฉะนั้นข้อมูลจากชุดทดสอบอาจรั่วเข้าสู่การฝึกและทำให้ผลดูดีกว่าความเป็นจริง

ฝึกโมเดลขั้นปลายบนชุดฝึก ใช้ข้อมูลตรวจสอบเลือกคุณลักษณะและเกณฑ์ตัดสิน จากนั้นประเมินขั้นตอนงานที่เลือกบนชุดทดสอบแยกต่างหาก ตรวจทั้งกระบวนการรวมถึงความล้มเหลวในการรับหรือแยกวิเคราะห์ผลลัพธ์ LLM อย่าประเมินเฉพาะการเรียกที่สำเร็จ

## เลือกเกณฑ์ตัดสินตามผลกระทบ

โมเดลจำแนกอาจให้คะแนนหรือความน่าจะเป็นแก่แต่ละรายการ เกณฑ์ตัดสินเปลี่ยนค่านั้นเป็นการดำเนินการ เช่น ส่งคำร้องไปตรวจ การเลื่อนเกณฑ์อาจเปลี่ยน precision และ recall แต่สมดุลที่เหมาะสมขึ้นอยู่กับต้นทุนของกรณีที่พลาดและการตรวจที่ไม่จำเป็น

หากตั้งใจตีความคะแนนเป็นความน่าจะเป็น ให้ประเมินการปรับเทียบบนข้อมูลที่กันไว้และเหมาะสม การฝึก logistic regression หรือขอค่าความมั่นใจจากโมเดลไม่ได้รับประกันว่าความน่าจะเป็นจะปรับเทียบแล้ว เปรียบเทียบทั้งการปรับเทียบและตัวชี้วัดการจำแนก และตรวจประสิทธิภาพสำหรับกลุ่มสำคัญและกรณีที่พบไม่บ่อย

## วัดขั้นตอนงานทั้งหมด

เปรียบเทียบวิธีพื้นฐานและระบบที่ใช้คุณลักษณะบนชุดประเมินเดียวกัน บันทึกผลบวกลวง ผลลบลวง ความหน่วง ค่าใช้จ่าย และสัดส่วนการเรียกที่ล้มเหลวหรือต้องให้มนุษย์ตรวจ ขั้นตอนงานที่ซับซ้อนขึ้นควรให้ประโยชน์ที่วัดได้กับงานเพื่อคุ้มกับต้นทุนปฏิบัติการที่เพิ่มขึ้น

ติดตามเวอร์ชันของพรอมป์ต์ โมเดล คุณลักษณะ และเกณฑ์ตัดสิน ประเมินใหม่เมื่อสิ่งเหล่านี้เปลี่ยนหรือข้อมูลขาเข้าเปลี่ยน ดูคำแนะนำเพิ่มเติมเกี่ยวกับการสร้างและดูแลการประเมินที่[แนวทางปฏิบัติที่ดีที่สุดสำหรับการประเมินของ OpenAI](https://platform.openai.com/docs/guides/evaluation-best-practices)
