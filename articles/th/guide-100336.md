# เปิดตัว Managed Agents ใน Gemini API

> คู่มือปฏิบัติสำหรับ Managed Agents ใน Gemini API: เลือกงาน ตรวจทานผลลัพธ์ และวางแผนค่าใช้จ่าย ความเป็นส่วนตัว และการจัดการข้อผิดพลาด



คำขอไปยังโมเดลภาษามักให้คำตอบกลับมา ส่วนเอเจนต์สามารถทำขั้นตอนระหว่างทางเพื่อบรรลุผลลัพธ์ได้ เช่น ตรวจข้อมูล เขียนโค้ด รันโค้ดนั้น และส่งรายงาน Managed Agents ของ Google ให้พื้นที่ทำงานที่โฮสต์ไว้สำหรับงานประเภทนี้ผ่าน Gemini API ฟีเจอร์นี้อยู่ในช่วงพรีวิว จึงควรตรวจเอกสารและความพร้อมใช้งานล่าสุดก่อนนำไปใช้ในงานจริง

คู่มือนี้อธิบายวิธีเลือกงานแรก ประเมินผลลัพธ์ และวางแผนงานปฏิบัติการที่เกี่ยวข้องกับเอเจนต์ที่มีการจัดการ [เอกสาร Gemini API](https://ai.google.dev/gemini-api/docs) ของ Google มีตัวอย่างคำขอและตัวระบุเอเจนต์ที่รองรับในปัจจุบัน

## ผู้ให้บริการจัดการอะไรบ้าง?

ในแนวทาง Managed Agent ผู้ให้บริการรันสภาพแวดล้อมของเอเจนต์และจัดหาเครื่องมือที่เอเจนต์ใช้ได้ Google อธิบายแซนด์บ็อกซ์ระยะไกลที่เอเจนต์ Antigravity สามารถทำงานกับไฟล์ รันโค้ด และใช้เว็บได้ แอปพลิเคชันของคุณยังต้องกำหนดเป้าหมาย จัดหาข้อมูลเข้าที่เหมาะสม และตัดสินว่าผลลัพธ์ที่ส่งกลับมายอมรับได้หรือไม่

สภาพแวดล้อมที่โฮสต์ไว้มีประโยชน์เมื่องานต้องใช้หลายขั้นตอนและพื้นที่ทำงานระหว่างทาง แต่ไม่ได้แทนที่การตัดสินใจของแอปพลิเคชันเกี่ยวกับสิทธิ์ การตรวจทาน หรือการจัดการข้อมูล ตรวจสอบเครื่องมือและการตั้งค่าสภาพแวดล้อมที่ใช้ได้สำหรับโปรเจกต์และเวอร์ชันของคุณก่อนพึ่งพา

## เลือกงานแรกที่มีขอบเขตชัดเจน

เริ่มจากงานที่ตรวจผลลัพธ์ได้โดยไม่ต้องเชื่อคำอธิบายของเอเจนต์ ตัวอย่างที่ดีคือการสรุป CSV ขนาดเล็ก: ให้ตัวอย่างที่ไม่อ่อนไหว ขอให้สร้างตารางยอดรวมและระบุรูปแบบผลลัพธ์ คำนวณยอดรวมบางรายการแยกต่างหากแล้วเปรียบเทียบกับผลที่ได้

คำอธิบายงานที่มีประโยชน์ประกอบด้วย:

- ข้อมูลเข้าและความหมายของแต่ละฟิลด์
- ผลลัพธ์ที่ต้องการ เช่น สรุปและไฟล์ CSV
- กฎสำหรับค่าที่ขาดหายหรือไม่ถูกต้อง
- ขอบเขตข้อมูลและเครื่องมือที่เอเจนต์ใช้ได้
- การตรวจสอบที่ผู้รับทำได้ก่อนนำผลลัพธ์ไปใช้

ตัวอย่าง: “สรุป CSV ตัวอย่างยอดขายนี้ตามเดือนและสกุลเงิน อย่ารวมสกุลเงิน แสดงแถวที่ไม่มีวันที่แยกต่างหากและแสดงวิธีคำนวณยอดรวมแต่ละรายการ” หลีกเลี่ยงการขอให้ส่งข้อความ เปลี่ยนข้อมูลจริง หรือดำเนินการภายนอกอื่นในการทดสอบครั้งแรก

## รันและตรวจสอบการโต้ตอบ

ใช้[คู่มือเริ่มต้น](https://ai.google.dev/gemini-api/docs/get-started)ของ Google เพื่อตั้งค่า SDK และข้อมูลรับรอง แล้วทำตามตัวอย่าง Managed Agent ของ Google ตัวอย่างระบุตัวระบุเอเจนต์ ข้อมูลเข้า และสภาพแวดล้อมระยะไกล ใช้ตัวระบุที่ Google ระบุในเอกสารปัจจุบัน แทนการสมมติว่าตัวระบุพรีวิวเก่ายังใช้ได้

ตรวจมากกว่าย่อหน้าสุดท้าย ตรวจสถานะที่ส่งกลับ ผลลัพธ์ และไฟล์ใด ๆ ที่ตั้งใจจะใช้ สำหรับงานข้อมูลให้เทียบตัวเลขกับต้นทาง สำหรับสคริปต์ที่สร้างขึ้นให้ตรวจทานและทดสอบในสภาพแวดล้อมควบคุม หากงานอาศัยข้อมูลจากเว็บ ให้เปิดแหล่งอ้างอิงและตรวจว่ารองรับข้ออ้างนั้น ผลลัพธ์ที่ดูดีอาจยังมีข้อผิดพลาด

หากทำงานต่อข้ามการโต้ตอบ ให้ปฏิบัติตามวงจรชีวิตของสภาพแวดล้อมและการโต้ตอบที่ Google ระบุไว้ เก็บตัวระบุที่เกี่ยวข้องกับบันทึกงานของแอปพลิเคชันและจัดการการหมดอายุหรือความล้มเหลวอย่างชัดเจน อย่าสมมติว่าพื้นที่ทำงานจะคงอยู่ตลอดไป

## ให้คำสั่งที่ชัดเจนแก่เอเจนต์ที่กำหนดเอง

Google ยังอธิบายวิธีให้คำสั่ง ทักษะ และข้อมูลแบบกำหนดเองแก่ Managed Agents ใช้ความสามารถเหล่านี้อธิบายงานและข้อกำหนดผลลัพธ์ ไม่ใช่ฝังความลับลงในเอกสาร สำหรับงานรายงาน คำสั่งอาจกำหนดวิธีจัดกลุ่มข้อมูล ระบุความไม่แน่นอน และสิ่งที่ต้องทำเมื่อคำนวณไม่สำเร็จ

เก็บไฟล์คำสั่งไว้ในระบบควบคุมเวอร์ชันและตรวจการเปลี่ยนแปลงเช่นเดียวกับโค้ดแอปพลิเคชัน ทดสอบเวอร์ชันใหม่กับชุดข้อมูลเข้าตัวแทนขนาดเล็ก รวมถึงไฟล์ว่าง ค่าที่ไม่คาดคิด และคำขอนอกขอบเขตที่ตั้งใจไว้ บันทึกเวอร์ชันและข้อมูลเข้าของการประเมินแต่ละครั้งเพื่อให้ตรวจสอบผลลัพธ์ที่เปลี่ยนไปได้

## วางแผนค่าใช้จ่าย ความเป็นส่วนตัว และความล้มเหลว

เอเจนต์ที่ทำงานหลายขั้นตอนอาจเรียกโมเดลหลายครั้งหรือใช้เครื่องมือก่อนส่งผลลัพธ์ ตรวจ[หน้าราคา](https://ai.google.dev/gemini-api/docs/pricing)ของ Google และขีดจำกัดของโปรเจกต์ก่อนทดลอง เพราะค่าบริการและเงื่อนไขพรีวิวอาจเปลี่ยนได้ วัดการใช้งานจากงานตัวแทนและกำหนดงบประมาณระดับแอปพลิเคชันให้เหมาะกับปริมาณงาน

ส่งเฉพาะข้อมูลที่ขั้นตอนงานได้รับอนุญาตให้ประมวลผล ถือว่าหน้าเว็บที่ดึงมาและไฟล์ที่อัปโหลดเป็นข้อมูลเข้าที่ไม่น่าไว้วางใจ และตรวจโค้ดที่สร้างขึ้นก่อนรันนอกแซนด์บ็อกซ์ กำหนดว่าจะทำอย่างไรเมื่องานหมดเวลา เครื่องมือล้มเหลว หรือเอเจนต์ส่งผลไม่ครบ การลองงานที่มีผลข้างเคียงซ้ำอาจทำให้เกิดผลซ้ำ จึงต้องตรวจสอบสถานะการดำเนินการเดิมก่อนลองอีกครั้ง

## ควรใช้ Managed Agent เมื่อใด?

Managed Agent น่าทดลองสำหรับงานค้นคว้า วิเคราะห์ หรือสร้างไฟล์ที่มีขอบเขตชัดเจน ซึ่งได้ประโยชน์จากเครื่องมือหลายขั้นตอนและมีคนหรือระบบอัตโนมัติตรวจผลได้ สำหรับการแปลงข้อมูลครั้งเดียวที่คาดการณ์ได้ การเรียกโมเดลโดยตรงหรือใช้โค้ดแอปพลิเคชันทั่วไปอาจดูแลได้ง่ายกว่า เปรียบเทียบแนวทางตามคุณภาพ ความหน่วง ค่าใช้จ่าย และระดับการตรวจทานที่กรณีใช้งานต้องการ

ขั้นตอน Managed Agent ที่อธิบายข้างต้นใช้ Gemini API ของ Google ส่วน Ailoot มี API ของตนเองสำหรับเข้าถึงโมเดล AI
