# Claude API สำหรับผู้เริ่มต้น: คู่มือเริ่มต้นใช้งานแบบลงมือทำ

> คู่มือ Claude API สำหรับผู้เริ่มต้น ครอบคลุมการตั้งค่า คำขอแรก การเลือกโมเดล ฟีเจอร์หลัก และแนวทางสำหรับ production



ทุกสิ่งที่นักพัฒนาต้องรู้เพื่อเรียก Claude API ครั้งแรก ได้แก่ คีย์ Messages API การเลือกโมเดล และแนวคิดหลักที่ช่วยให้เปลี่ยนจากคำขอแรกไปสู่การใช้งานจริง

## Claude API คืออะไร

Claude API คือแพลตฟอร์มนักพัฒนาของ Anthropic ซึ่งให้เข้าถึงโมเดล Claude ด้วยโปรแกรมผ่าน Messages API พร้อม system prompt การใช้เครื่องมือ สตรีมมิง ความสามารถด้านภาพ และเอาต์พุตแบบมีโครงสร้าง

Messages API เป็น HTTP endpoint แบบไม่มีสถานะ คุณส่งรายการข้อความของผู้ใช้และผู้ช่วย, model ID และขีดจำกัดโทเค็น แล้ว Claude จะส่งคำตอบที่มีโครงสร้างกลับมา endpoint สนับสนุนประกอบด้วยการประมวลผลแบบชุด ไฟล์ และการนับโทเค็น

- **ไม่มีสถานะ:** API ไม่เก็บความจำ ให้ส่งประวัติการสนทนาใหม่ทุกครั้งที่เรียก
- **การเลือกโมเดล:** การเปลี่ยนโมเดลมักหมายถึงการเปลี่ยน model ID
- **SDK:** ไลบรารีทางการสำหรับ Python (anthropic) และ TypeScript (@anthropic-ai/sdk) ใช้รูปแบบคำขอที่สอดคล้องกัน

การเข้าใจสถาปัตยกรรมนี้ช่วยหลีกเลี่ยงข้อผิดพลาดทั่วไปของผู้เริ่มต้น นั่นคือคาดหวังว่า API จะจำคำขอก่อนหน้าได้

## ขั้นตอนที่ 1: รับคีย์และตั้งค่า Console

ไปที่ **console.anthropic.com** สร้างบัญชีหรือองค์กรสำหรับทีม แล้วสร้าง API key ในส่วนการตั้งค่า ให้เก็บรักษาคีย์เหมือนรหัสผ่าน: บันทึกไว้ในตัวแปรสภาพแวดล้อมและอย่าใส่ไว้ในการควบคุมซอร์สโค้ด

การเรียก HTTP โดยตรงใช้ header **x-api-key** และ header **anthropic-version** ส่วน SDK จะอ่าน **ANTHROPIC_API_KEY** จากสภาพแวดล้อมโดยอัตโนมัติ โค้ดส่วนใหญ่จึงไม่ต้องจัดการคีย์โดยตรง

- สร้างคีย์แยกสำหรับการพัฒนา staging และ production
- ใช้ workspace เพื่อแยกโปรเจ็กต์และค่าใช้จ่ายของทีม
- ตั้งขีดจำกัดการใช้งานใน Console ก่อนแจกจ่ายคีย์ให้ทีมวงกว้างขึ้น

## ขั้นตอนที่ 2: เรียก Messages API ครั้งแรก

ติดตั้ง SDK ด้วย **pip install anthropic** ส่งออกคีย์ แล้วเรียกใช้:

```
import anthropic

client = anthropic.Anthropic()
msg = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Explain REST in one paragraph."}],
)
for block in msg.content:
    if block.type == "text":
        print(block.text)
```

มีพารามิเตอร์ที่จำเป็นสามรายการ ได้แก่ **model**, **max_tokens** (เพดานเอาต์พุต) และ **messages** คำตอบประกอบด้วยรายการบล็อกเนื้อหา ให้ตรวจสอบชนิดของแต่ละบล็อก อย่าสันนิษฐานว่าเป็นข้อความธรรมดา เพราะการใช้เครื่องมือและการคิดอาจเพิ่มบล็อกชนิดอื่นได้ ออบเจ็กต์ **usage** รายงานจำนวนโทเค็นขาเข้าและขาออก ซึ่งใช้เป็นข้อมูลติดตามต้นทุนได้

## ขั้นตอนที่ 3: เลือกโมเดล

ต่อไปนี้คือโมเดล Claude รุ่นปัจจุบันของ Anthropic และ ID ที่ใช้ใน API

- **Claude Haiku 5.5** (**claude-haiku-5-5**) — อธิบายว่าเร็วและมีต้นทุนต่ำ เหมาะกับการจัดประเภทและงานง่ายที่มีปริมาณสูง
- **Claude Sonnet 5.5** (**claude-sonnet-5-5**) — อธิบายว่าเป็นตัวเลือกที่สมดุลสำหรับงาน production รวมถึงการเขียนโค้ด
- **Claude Opus 5.5** (**claude-opus-5-5**) — อธิบายว่าเหมาะกับการให้เหตุผลที่ยากและงาน agent ระยะยาว
- **Claude Fable 5.2** (**claude-fable-5-2**) — อธิบายว่าเป็นรุ่นเรือธงสำหรับงานให้เหตุผลที่ท้าทาย

เริ่มจาก Opus 5.5 ลองใช้ Sonnet 5.5 เมื่อต้องการสมดุลระหว่างความเร็วกับคุณภาพ ใช้ Haiku 5.5 สำหรับงานง่ายปริมาณมาก และ Fable 5.2 สำหรับงานที่ต้องใช้การให้เหตุผลซับซ้อน ดูอัตราปัจจุบันได้ที่หน้าราคาของ Anthropic

## แนวคิดห้าข้อที่ควรเรียนรู้ต่อ

เมื่อคำขอแรกทำงานแล้ว ฟีเจอร์เหล่านี้ครอบคลุมความต้องการของแอปพลิเคชันได้มากมาย:

- **System prompt** — พารามิเตอร์ระดับบนสุด **system** ใช้กำหนดบทบาท น้ำเสียง และกฎ แยกจากข้อความของผู้ใช้
- **การสนทนาหลายเทิร์น** — ต่อคำตอบของผู้ช่วยแต่ละครั้งเข้าอาร์เรย์ messages แล้วส่งใหม่; ข้อความแรกต้องเป็นเทิร์นของผู้ใช้
- **สตรีมมิง** — server-sent events ส่งโทเค็นขณะสร้าง ซึ่งช่วยกับหน้าจอแชตและเอาต์พุตยาวได้
- **ความสามารถด้านภาพ** — ส่งภาพเป็น content block แบบ base64 หรือ URL พร้อมข้อความ
- **การใช้เครื่องมือ** — กำหนดฟังก์ชันด้วย JSON schema; Claude เลือกได้ว่าจะเรียกเมื่อใด ส่วนโค้ดของคุณเป็นผู้ทำงานและส่งผลลัพธ์กลับ

หากต้นทุนสำคัญ ให้พิจารณา **การแคช prompt** และ **การประมวลผลแบบชุด**; หากโค้ดขั้นถัดไปต้องแยกวิเคราะห์คำตอบ ให้พิจารณา **เอาต์พุตแบบมีโครงสร้าง**

## จากบทเรียนสู่ production

การยกระดับจากสคริปต์ที่ทำงานได้ไปเป็นการเชื่อมต่อ production ต้องอาศัยวินัยด้านวิศวกรรม:

- **การจัดการข้อผิดพลาด:** จัดการข้อผิดพลาดการจำกัดอัตรา (429) และข้อผิดพลาดเซิร์ฟเวอร์แยกจากกัน แหล่งข้อมูลระบุว่า SDK จะลองซ้ำโดยอัตโนมัติพร้อมช่วงเวลารอที่เพิ่มขึ้น ให้ตรวจสอบพฤติกรรมปัจจุบันในเอกสารของ SDK ที่ใช้
- **การมองเห็นต้นทุน:** บันทึก **usage** จากทุกคำตอบลงในระบบเมตริก
- **การกำหนดเวอร์ชัน prompt:** ปฏิบัติต่อ prompt เหมือนโค้ด: ตรวจทานและกำหนดเวอร์ชัน แล้วทดสอบกับชุดประเมินขนาดเล็ก
- **การตรึงโมเดล:** อ้างอิง model ID จากการตั้งค่าเพื่อให้การอัปเกรดเกิดขึ้นโดยตั้งใจและผ่านการทดสอบ

### ประเด็นสำคัญ

- Messages API ไม่มีสถานะ; ส่งประวัติการสนทนาใหม่ทุกครั้งที่เรียก
- การยืนยันตัวตน HTTP โดยตรงใช้ header x-api-key; SDK อ่าน ANTHROPIC_API_KEY จากสภาพแวดล้อมได้
- พารามิเตอร์คำขอที่จำเป็นสามรายการคือ model, max_tokens และ messages
- เริ่มจาก Opus 5.5 แล้วเปรียบเทียบทางเลือกอื่นด้วยข้อมูลของคุณเอง
- System prompt, สตรีมมิง, ความสามารถด้านภาพ, การใช้เครื่องมือ และประวัติหลายเทิร์นรองรับรูปแบบแอปพลิเคชันได้หลายแบบ
- บันทึกการใช้โทเค็นเพื่อมองเห็นต้นทุนและวางแผนความจุ

## คำถามที่พบบ่อย

### ต้องรู้เรื่องแมชชีนเลิร์นนิงก่อนใช้ Claude API หรือไม่

ไม่จำเป็น Claude API เป็น REST API ที่มี SDK ทางการสำหรับ Python และ TypeScript หากคุณเรียก HTTP endpoint และแยกวิเคราะห์ JSON ได้ ก็สร้างแอปด้วย Claude ได้ การออกแบบ prompt การจัดการข้อผิดพลาด และการควบคุมต้นทุนเป็นทักษะวิศวกรรมที่มีประโยชน์ แต่ไม่ต้องมีพื้นฐานทฤษฎีแมชชีนเลิร์นนิงเพื่อเรียก API ครั้งแรก

### ผู้เริ่มต้นควรเริ่มด้วยโมเดล Claude รุ่นใด

Anthropic แนะนำให้เริ่มจาก Claude Opus 5.5 (API ID `claude-opus-5-5`) สำหรับงานส่วนใหญ่ เมื่อพรอมต์คงที่แล้ว ให้เปรียบเทียบโมเดลอื่นด้วยข้อมูลของคุณเอง

### Claude API จำการสนทนาก่อนหน้าได้หรือไม่

ไม่ได้ Messages API ไม่มีสถานะ แอปของคุณจัดเก็บการสนทนาและส่งประวัติข้อความทั้งหมดใหม่ในทุกคำขอ วิธีนี้ช่วยให้ควบคุมบริบท ตัดหรือสรุปเทิร์นเก่า และใช้ร่วมกับการแคช prompt ได้
