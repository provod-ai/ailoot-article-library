# Gemini: cómo elegir entre la aplicación y la API

> Una guía práctica para elegir entre la aplicación de Gemini y la API, evaluar modelos y estimar costes de uso.



Gemini se puede usar mediante la aplicación de consumo de Google o integrar en software mediante una API. El punto de partida adecuado depende de si quieres resolver una tarea tú mismo o crear un proceso repetible para otras personas.

## Empieza por la tarea

Para una tarea puntual, como redactar un mensaje o explorar una idea, una aplicación interactiva ofrece un lugar para hacer preguntas y refinar la respuesta. Comprueba el resultado antes de confiar en él: una respuesta fluida puede contener errores, omitir contexto o citar incorrectamente una fuente.

Una API es útil cuando una aplicación necesita enviar entradas y procesar salidas como parte de un flujo de trabajo. Por ejemplo, una aplicación de soporte podría resumir una incidencia para que la revise una persona. El desarrollador debe gestionar las instrucciones, el acceso a datos, los fallos y la forma de mostrar o almacenar los resultados.

La aplicación y la API son productos distintos. No supongas que una función, un límite, una suscripción o una configuración de datos de uno está disponible automáticamente en el otro. Consulta la documentación y los ajustes del producto y la cuenta que realmente utilizas.

## Elige un modelo para la tarea

Empieza con unos cuantos ejemplos representativos en vez de elegir un modelo solo por su nombre. Para una tarea de resumen, incluye un mensaje corto, uno largo y un caso con información ausente. Decide qué debe conservar una buena respuesta, qué no debe inventar y qué longitud debería tener.

Si una tarea incluye imágenes, audio u otra entrada, comprueba que el modelo y el endpoint concretos admitan el formato que necesitas. Las modalidades compatibles, los límites de contexto y la disponibilidad pueden diferir según el modelo y cambiar. Consulta la [documentación de la API de Gemini](https://ai.google.dev/gemini-api/docs) de Google para conocer las opciones y los formatos de solicitud actuales.

## Estima el coste con una muestra realista

Para un flujo con API, registra la cantidad de entrada y salida utilizada por un conjunto pequeño y representativo de solicitudes. Multiplica el uso medido por los precios publicados pertinentes, teniendo en cuenta todos los tipos de entrada y salida aplicables. Después estima con qué frecuencia se ejecutará el flujo y deja margen para reintentos y variaciones en la longitud de las respuestas.

Considera el resultado una estimación, no una factura garantizada. Comprueba los [precios actuales de la API de Gemini](https://ai.google.dev/gemini-api/docs/pricing), las cuotas y los ajustes de facturación de tu cuenta. Una suscripción a la aplicación y el uso de la API pueden tener condiciones diferentes.

## Evalúa antes de escalar

Compara los resultados con ejemplos revisados por personas. Para cada respuesta, comprueba los hechos frente a la entrada, el formato solicitado y las reglas específicas de la tarea. Incluye casos difíciles y casos que el modelo deba rechazar o enviar a una persona. Una respuesta que parece válida no es necesariamente correcta.

Registra los fallos y revisa una parte del flujo cada vez: las instrucciones, la preparación de la entrada, el modelo o la validación de la salida. Repite el mismo conjunto de pruebas después de un cambio. Si cambia el modelo o el tipo de datos entrantes, vuelve a evaluar el resultado en lugar de asumir que la evaluación anterior sigue siendo aplicable.

## Gestiona los datos y los fallos de forma deliberada

Envía solo los datos necesarios para la tarea y revisa los ajustes de tratamiento de datos del producto correspondiente antes de usar información sensible. Valida las salidas antes de que una aplicación actúe en función de ellas. Planifica límites de frecuencia, tiempos de espera y resultados incompletos; muestra un error que indique cómo actuar o envía el caso a revisión en vez de tratar silenciosamente un fallo como una tarea completada.

Para solicitudes que puedan desencadenar acciones externas, guarda un registro de la operación y comprueba su estado antes de reintentar. Una respuesta perdida durante la transmisión no demuestra que la acción haya fallado.
