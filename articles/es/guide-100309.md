# Claude API para principiantes: guía práctica para empezar

> Guía de inicio de la API de Claude que cubre la configuración, la primera solicitud, la elección del modelo, las funciones principales y las prácticas de producción.



Todo lo que necesita un desarrollador para realizar su primera llamada a Claude API: claves, Messages API, elección del modelo y conceptos esenciales para pasar de la primera solicitud a producción.

## Qué es Claude API

Claude API es la plataforma para desarrolladores de Anthropic. Ofrece acceso programático a los modelos Claude mediante Messages API, con prompts de sistema, uso de herramientas, streaming, visión y respuestas estructuradas.

Messages API es un endpoint HTTP sin estado. Envías una lista de mensajes de usuario y del asistente, un ID de modelo y un límite de tokens; Claude devuelve una respuesta estructurada. Entre los endpoints complementarios están los lotes, los archivos y el recuento de tokens.

- **Sin estado:** la API no guarda memoria. Vuelve a enviar el historial de la conversación en cada llamada.
- **Elección del modelo:** cambiar de modelo normalmente implica cambiar el ID del modelo.
- **SDK:** las bibliotecas oficiales para Python (anthropic) y TypeScript (@anthropic-ai/sdk) usan las estructuras de solicitud correspondientes.

Entender esta arquitectura ayuda a evitar un error habitual entre principiantes: esperar que la API recuerde una solicitud anterior.

## Paso 1: consigue una clave y configura la Console

Ve a **console.anthropic.com**, crea una cuenta o una organización para tu equipo y genera una clave API en la sección de ajustes. Trata la clave como una contraseña: guárdala en una variable de entorno y nunca la incluyas en el control de versiones.

Las llamadas HTTP directas usan un encabezado **x-api-key** y un encabezado **anthropic-version**. Los SDK leen automáticamente **ANTHROPIC_API_KEY** del entorno, así que la mayoría del código no tiene que manejar la clave directamente.

- Crea claves distintas para desarrollo, preproducción y producción.
- Usa espacios de trabajo para aislar los proyectos y el gasto del equipo.
- Define límites de uso en la Console antes de dar acceso a las claves a un equipo más amplio.

## Paso 2: realiza tu primera llamada a Messages API

Instala el SDK con **pip install anthropic**, exporta la clave y ejecuta:

```
import anthropic

client = anthropic.Anthropic()
msg = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Explain REST in one paragraph."}],
)
for block in msg.content:
    if block.type == "text":
        print(block.text)
```

Hay tres parámetros obligatorios: **model**, **max_tokens** (el límite de salida) y **messages**. La respuesta contiene una lista de bloques de contenido. Comprueba el tipo de cada bloque en lugar de dar por hecho que es texto normal, porque el uso de herramientas y el razonamiento pueden añadir otros tipos de bloques. El objeto **usage** informa de los tokens de entrada y salida y puede servir para medir costes.

## Paso 3: elige un modelo

Estos son los modelos Claude actuales de Anthropic y sus identificadores de API.

- **Claude Haiku 5.5** (**claude-haiku-5-5**) — descrito como rápido y económico, para clasificación y tareas sencillas de gran volumen.
- **Claude Sonnet 5.5** (**claude-sonnet-5-5**) — descrito como una opción equilibrada para cargas de producción, incluida la programación.
- **Claude Opus 5.5** (**claude-opus-5-5**) — descrito para razonamiento complejo y trabajo agéntico a largo plazo.
- **Claude Fable 5.2** (**claude-fable-5-2**) — descrito como un modelo insignia para tareas de razonamiento exigentes.

Empieza con Opus 5.5. Prueba Sonnet 5.5 para equilibrar velocidad y calidad, Haiku 5.5 para tareas sencillas de gran volumen y Fable 5.2 para razonamiento complejo. Consulta la página de precios de Anthropic para ver las tarifas actuales.

## Los cinco conceptos que conviene aprender después

Cuando funcione la primera solicitud, estas funciones cubren muchas necesidades de aplicaciones:

- **Prompts de sistema** — un parámetro de nivel superior llamado **system** que establece el rol, el tono y las reglas, separado de los mensajes de usuario.
- **Conversaciones de varios turnos** — añade cada respuesta del asistente al array messages y vuelve a enviarlo; el primer mensaje debe ser un turno del usuario.
- **Streaming** — los eventos Server-Sent Events entregan tokens mientras se generan, lo que puede ayudar en interfaces de chat y respuestas largas.
- **Visión** — pasa imágenes como bloques de contenido Base64 o URL junto con el texto.
- **Uso de herramientas** — define funciones con esquemas JSON; Claude puede decidir cuándo llamarlas, mientras tu código las ejecuta y devuelve el resultado.

Si el coste importa, considera la **caché de prompts** y el **procesamiento por lotes**. Si el código posterior tiene que analizar una respuesta, considera las **respuestas estructuradas**.

## Del tutorial a producción

Pasar de un script funcional a una integración de producción requiere disciplina técnica:

- **Gestión de errores:** distingue los límites de solicitudes (429) de los errores del servidor. La fuente indica que los SDK reintentan estos errores automáticamente con espera progresiva; comprueba el comportamiento actual en la documentación del SDK correspondiente.
- **Visibilidad de costes:** registra **usage** de cada respuesta en tu sistema de métricas.
- **Versionado de prompts:** trata los prompts como código: revísalos, asígnales una versión y pruébalos con un conjunto pequeño de evaluación.
- **Fijación del modelo:** referencia los ID de modelo en la configuración para que las actualizaciones sean deliberadas y estén probadas.

### Ideas clave

- Messages API no tiene estado; vuelve a enviar el historial de la conversación en cada llamada.
- La autenticación HTTP directa usa el encabezado x-api-key; los SDK pueden leer ANTHROPIC_API_KEY del entorno.
- Los tres parámetros obligatorios de la solicitud son model, max_tokens y messages.
- Empieza con Opus 5.5 y compara las alternativas con tus propios datos.
- Los prompts de sistema, el streaming, la visión, el uso de herramientas y el historial de varios turnos cubren muchos patrones de aplicación.
- Registra el uso de tokens para controlar costes y capacidad.

## Preguntas frecuentes

### ¿Necesito saber aprendizaje automático para usar Claude API?

No. Claude API es una API REST con SDK oficiales para Python y TypeScript. Si puedes llamar a un endpoint HTTP y analizar JSON, puedes crear aplicaciones con Claude. El diseño de prompts, la gestión de errores y el control de costes son habilidades de ingeniería útiles; no necesitas teoría del aprendizaje automático para realizar tu primera llamada API.

### ¿Con qué modelo Claude debería empezar un principiante?

Anthropic recomienda empezar con Claude Opus 5.5 (ID de API `claude-opus-5-5`) para la mayoría de las cargas de trabajo. Cuando tus prompts sean estables, compara los demás modelos con tus propios datos.

### ¿Claude API recuerda conversaciones anteriores?

No. Messages API no tiene estado. Tu aplicación guarda la conversación y vuelve a enviar todo el historial de mensajes con cada solicitud. Así controlas el contexto, puedes recortar o resumir los turnos anteriores y combinarlo con la caché de prompts.
