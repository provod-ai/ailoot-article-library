# Uso de características de LLM en un proceso de clasificación de texto

> Una guía práctica para usar características generadas por LLM en un proceso de clasificación y evaluar umbrales y calibración.



Un modelo de lenguaje puede clasificar texto directamente o producir señales que otro modelo utiliza junto con otros datos. Ninguno de los dos enfoques es automáticamente mejor. La elección útil depende de la tarea, las etiquetas disponibles y el coste de los errores.

## Empieza con una referencia básica

Define el resultado y reúne ejemplos que reflejen las decisiones que necesitas tomar. En un flujo de soporte, la tarea podría ser identificar incidencias que requieren revisión humana urgente. Acordad qué se considera urgente, incluid casos ambiguos y registrad cómo los etiquetaron las personas.

Prueba una referencia básica sencilla antes de añadir complejidad. Puede ser una regla, un modelo instruido para devolver una etiqueta o un clasificador supervisado entrenado con datos etiquetados existentes. Compara los enfoques con los mismos ejemplos reservados. Un clasificador LLM directo puede ser útil; no debe descartarse solo porque exista otro enfoque.

## Convierte las salidas del modelo en características

En lugar de pedir al modelo de lenguaje únicamente una decisión final, pídele un pequeño conjunto de señales específicas de la tarea. En el ejemplo de soporte, podrían indicar si el mensaje describe una interrupción del servicio o una consulta de facturación. Un clasificador posterior puede usar esas señales junto con campos estructurados permitidos, como la categoría del producto.

Define cada señal con precisión y valida el formato de salida. Una señal generada puede ser incorrecta o faltar, y un modelo posterior puede aprender de esos errores. No incluyas información que no estaría disponible al tomar la decisión real.

## Divide los datos antes del entrenamiento

Separa los datos de entrenamiento de los de validación y prueba antes de seleccionar características o ajustar umbrales. Si están relacionados mensajes del mismo cliente o de un periodo posterior, elige una división que refleje cómo se usará el sistema. De lo contrario, la información del conjunto de prueba puede filtrarse al entrenamiento y hacer que los resultados parezcan mejores de lo que son.

Entrena el modelo posterior con el conjunto de entrenamiento. Usa los datos de validación para elegir características y un umbral de decisión y, después, evalúa el flujo seleccionado en un conjunto de prueba independiente. Comprueba todo el proceso, incluidos los fallos al obtener o analizar sintácticamente una salida del LLM; no evalúes solo las llamadas exitosas.

## Elige un umbral según las consecuencias

Un clasificador puede producir una puntuación o probabilidad para cada elemento. Un umbral convierte ese valor en una acción, como enviar una incidencia a revisión. Moverlo puede cambiar la precisión y la exhaustividad, pero el equilibrio adecuado depende del coste de los casos omitidos y las revisiones innecesarias.

Si pretendes interpretar las puntuaciones como probabilidades, evalúa su calibración con datos reservados adecuados. Ajustar una regresión logística o pedir al modelo su confianza no garantiza probabilidades calibradas. Compara la calibración además de las métricas de clasificación y examina el rendimiento en grupos importantes y casos poco frecuentes.

## Mide todo el flujo

Compara la referencia básica y el sistema basado en características en el mismo conjunto de evaluación. Registra los falsos positivos, falsos negativos, latencia, coste y proporción de llamadas que fallaron o necesitaron revisión humana. Un flujo más complejo debería justificar su coste operativo adicional con un beneficio medible para la tarea.

Registra la versión del prompt, el modelo, las características y el umbral. Vuelve a evaluar cuando cambien o cuando varíen los datos entrantes. Para más orientación sobre cómo crear y mantener evaluaciones, consulta las [buenas prácticas de evaluación de OpenAI](https://platform.openai.com/docs/guides/evaluation-best-practices).
