# Diseño de herramientas para agentes de IA: lecciones para flujos de Claude Code

> Una guía práctica para definir y probar herramientas para agentes de IA, con ejemplos de flujos de programación.



Un agente de IA necesita algo más que un buen modelo: necesita herramientas que pueda seleccionar, entender y usar dentro de los límites de una tarea. Esta guía muestra cómo diseñar esas interfaces usando los flujos de programación como ejemplo práctico.

## Empieza con una tarea observable

Describe lo que debe lograr el agente antes de decidir qué herramientas ofrecer. Para una pregunta sobre un repositorio, la tarea podría ser encontrar dónde se lee una configuración y citar los archivos pertinentes. Un conjunto adecuado podría permitir listar archivos, buscar texto y leer archivos seleccionados; no necesita permiso para desplegar nada para responder a esa pregunta.

Anota el resultado esperado y las acciones que quedan fuera del alcance. Una herramienta es útil cuando sus entradas y salidas ayudan al agente a tomar la siguiente decisión y la aplicación puede comprobar que la acción está permitida.

## Da a cada herramienta un contrato claro

La descripción debe indicar qué hace la herramienta, las entradas obligatorias y la estructura del resultado. Usa nombres y descripciones de parámetros distintos para herramientas con fines similares. Describe los límites importantes: por ejemplo, una búsqueda podría devolver una lista limitada de rutas coincidentes en vez del contenido de todos los archivos.

Una solicitud ilustrativa a una herramienta de búsqueda de texto podría contener una consulta y un directorio. Su resultado podría incluir rutas y números de línea coincidentes. La aplicación debe validar el directorio y tratar explícitamente las rutas ausentes o las búsquedas fallidas. Una solicitud bien formada no demuestra que la respuesta encontrada sea correcta.

## Equilibra flexibilidad y control

Una shell de propósito general puede servir para muchas tareas, pero también expone un amplio conjunto de acciones. Una herramienta más acotada puede facilitar la comprensión de una operación habitual y limitar la acción que realiza. La elección depende de la tarea, el entorno y los permisos disponibles; más herramientas no producen automáticamente mejores resultados.

Mantén el conjunto inicial lo bastante pequeño para poder orientarse. Añade una herramienta especializada cuando lo justifiquen fallos observados o trabajo repetido. Si una herramienta puede cambiar datos o contactar con un servicio externo, haz visible ese efecto en su descripción y aplica los permisos pertinentes en la aplicación.

## Pide la información que falta en el momento adecuado

Un agente no debe inventar una decisión pendiente. Si una tarea depende realmente de información que no puede encontrar, una pregunta estructurada puede presentar las opciones pertinentes y explicar sus consecuencias. Si hay trabajo independiente preparado, el proceso puede continuar con él mientras espera la respuesta.

Haz preguntas concretas. Por ejemplo, si un informe requiere un intervalo de fechas que no se proporcionó, pregunta por ese intervalo en vez de pedir al usuario que repita todo el encargo. Una pregunta no sustituye la comprobación del contexto disponible.

## Prueba la herramienta y el agente juntos

Crea un pequeño conjunto de tareas representativas: solicitudes habituales, entradas ambiguas, archivos no disponibles e intentos de usar una herramienta fuera del alcance previsto. Examina la herramienta elegida, los argumentos enviados, el resultado devuelto y la respuesta final. Una llamada a la API exitosa aún puede devolver datos incompletos, así que contrasta la respuesta con las pruebas originales.

Cambia una parte de la interfaz cada vez al diagnosticar un fallo recurrente. Registra la versión de la descripción de la herramienta y repite la prueba pertinente. Para acciones con efectos secundarios, comprueba un resultado incierto antes de reintentar; el reintento podría repetir una acción ya realizada con éxito.

## Aplica las ideas a un flujo de programación

Claude Code admite flujos que combinan herramientas e instrucciones reutilizables. Consulta la [documentación actual de uso de herramientas de Claude](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview) para conocer el contrato de la API y la [documentación de habilidades de Claude Code](https://code.claude.com/docs/en/skills) para ver cómo se organizan las instrucciones reutilizables. La disponibilidad y las interfaces exactas pueden cambiar, así que comprueba la documentación de la versión utilizada.

Las mismas preguntas de diseño se aplican a distintos frameworks de agentes: ¿qué requiere la tarea, qué puede observar el agente, qué puede cambiar cada herramienta y cómo verificarás el resultado?
