# Cómo medir los errores de un juez LLM

> Una guía práctica para medir aprobaciones falsas, rechazos falsos y la estabilidad de un juez LLM frente a ejemplos revisados por personas.



Un modelo juez puede ayudar a revisar respuestas de IA a gran escala, pero una puntuación solo es útil si sabes qué mide y con qué frecuencia se equivoca el juez. Esta guía muestra cómo examinar esos errores frente a ejemplos revisados por personas.

## Define primero la decisión

Elige una pregunta clara, por ejemplo si una respuesta incluye una condición de elegibilidad obligatoria. Proporciona al juez el material de referencia pertinente, la respuesta evaluada y un criterio que pueda aplicar. Define qué significan aprobar, rechazar y un resultado incierto antes de recopilar puntuaciones.

La explicación de un modelo puede ayudar a una persona revisora a investigar una decisión, pero no demuestra que sea correcta. Contrástala con las pruebas proporcionadas.

## Crea un conjunto de referencia

Recopila ejemplos que representen la tarea real, incluidas respuestas habituales, casos límite y fallos conocidos. Pide a personas que apliquen el mismo criterio escrito a cada elemento. Haz que varias revisen una parte del conjunto, resuelve los desacuerdos y registra las etiquetas acordadas y la versión del criterio.

Reserva algunos ejemplos para una evaluación posterior cuando modifiques el prompt o elijas un juez. Si ajustas repetidamente con los mismos ejemplos, la mejora medida en ese conjunto puede no trasladarse a casos nuevos. Incluye deliberadamente errores sensibles o costosos y registra cómo se construyó la muestra.

## Cuenta ambos tipos de error

Compara las decisiones del juez con las etiquetas humanas acordadas. Una aprobación falsa significa que el juez aprueba una respuesta que las personas revisoras marcaron como no aprobada. Un rechazo falso significa que rechaza una respuesta que marcaron como aprobada. Ambos importan: uno puede ocultar defectos y el otro generar trabajo de revisión innecesario.

Como ejemplo sencillo, supongamos que las personas revisoras marcaron 20 respuestas como no aprobadas y que el juez aprobó 4 de ellas. La tasa de aprobaciones falsas entre las respuestas que las personas marcaron como no aprobadas es 4 de 20, es decir, el 20 %. Supongamos que marcaron otras 80 respuestas como aprobadas y que el juez rechazó 8: la tasa de rechazos falsos entre las respuestas que las personas marcaron como aprobadas es 8 de 80, es decir, el 10 %. Son cifras ilustrativas, no una afirmación de rendimiento.

Indica siempre el denominador y el periodo de la muestra junto con una tasa. Una muestra pequeña o poco representativa puede hacer inestable una estimación. Examina las discrepancias reales; una sola cifra agregada no mostrará si los errores se concentran en fuentes ausentes, respuestas largas o un tipo particular de pregunta.

## Comprueba la estabilidad, no solo la concordancia

En comparaciones por pares, repite una muestra invirtiendo el orden de las respuestas y examina las decisiones que cambian. Si las salidas varían entre ejecuciones, mide esa variación con entradas idénticas antes de considerar real un pequeño movimiento de la puntuación. Una respuesta plausible o más larga no debería recibir crédito por su estilo cuando el criterio se refiere al respaldo factual.

Envía los casos inciertos y aquellos en los que un error tenga mayores consecuencias a una persona revisora cualificada. Usa comprobaciones deterministas para propiedades que un programa pueda verificar directamente, como la presencia de campos JSON obligatorios.

## Vuelve a comprobar después de un cambio

Registra junto con los resultados el modelo juez, las instrucciones, el criterio, el conjunto de referencia y la fecha de evaluación. Vuelve a evaluar cuando cambie cualquiera de esas entradas o la tarea subyacente. Para una decisión de lanzamiento, examina los patrones de error del juez y las consecuencias de equivocarse en vez de depender únicamente de un umbral.

Las herramientas de evaluación siguen necesitando criterios y un conjunto de validación adecuados para tu tarea. Consulta las [buenas prácticas de evaluación de OpenAI](https://platform.openai.com/docs/guides/evaluation-best-practices) para más orientación.
