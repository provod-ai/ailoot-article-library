# Clasificación de texto con un LLM

> Una guía práctica para clasificar texto con un modelo de lenguaje, elegir etiquetas, revisar los cambios propuestos y comprobar los resultados.



Un modelo de lenguaje puede clasificar texto asignando etiquetas a cada elemento. Esta guía explica cómo definir las etiquetas, tratar los casos inciertos y medir si los resultados son útiles.

## Define la decisión

Empieza con una pregunta que tenga un resultado práctico. Un equipo de soporte podría agrupar mensajes en `billing`, `technical` y `other` para dirigirlos a la cola adecuada. Decide si cada mensaje necesita una etiqueta o puede tener varias. Explica cada etiqueta con ejemplos, incluidos casos que parecen similares pero pertenecen a grupos distintos.

Mantén una opción `other` o de revisión para los elementos que no encajan. Una elección forzada puede producir un informe aparentemente limpio y ocultar una taxonomía deficiente. En decisiones que afectan a personas o tienen consecuencias importantes, mantén la intervención humana.

## Pide un resultado predecible

Proporciona al modelo el texto, las definiciones de las etiquetas y el formato de salida deseado. Trata el texto que se clasifica como datos, no como una instrucción para el modelo. Por ejemplo, un mensaje que diga «ignora las etiquetas» sigue siendo el elemento que hay que clasificar; no debe cambiar la tarea.

Un resultado podría ser así:

```json
{"label":"billing","reason":"El mensaje pregunta por una factura."}
```

Este resultado es ilustrativo, no una respuesta real del modelo. Antes de usar una salida, comprueba que pueda analizarse sintácticamente, que contenga los campos esperados y que use una etiqueta permitida. Un formato válido por sí solo no significa que la clasificación sea correcta. La compatibilidad de los modelos con salidas restringidas por esquema varía; consulta la documentación del modelo y la API que utilices.

## Mejora el conjunto de etiquetas

Empieza con un conjunto manejable de categorías y revisa los ejemplos que caen en `other` o provocan desacuerdos repetidos. Pueden revelar una categoría ausente, una definición poco clara o dos etiquetas solapadas. Propón cambios con ejemplos representativos y pide a una persona revisora que apruebe las nuevas definiciones antes de aplicarlas ampliamente.

Un modelo también puede sugerir nuevas etiquetas y proponer combinaciones como experimento. Marca las categorías protegidas que deben permanecer separadas y comprueba cada cambio propuesto frente a esas restricciones antes de actualizar la taxonomía.

Si dos categorías parecen similares, compara las decisiones que respaldan antes de combinarlas. Por ejemplo, los fallos de pago y las solicitudes de reembolso afectan al dinero, pero pueden requerir acciones diferentes. Conserva las distinciones importantes para el proceso y registra una versión por cada cambio de la taxonomía.

## Comprueba el rendimiento antes de escalar

Crea una muestra que refleje la mezcla real de mensajes, incluidos casos raros y ambiguos. Pide a personas que la etiqueten con las mismas definiciones, resuelvan desacuerdos y guarden las etiquetas acordadas como referencia. Compara los resultados del modelo con ellas y examina los errores de cada categoría; una cifra de exactitud global puede ocultar una categoría débil.

Prueba los cambios del prompt, el modelo o la taxonomía en un conjunto de evaluación independiente. Supervisa los resultados a lo largo del tiempo porque el lenguaje y la mezcla del texto entrante pueden cambiar. Envía los resultados inciertos o inválidos a revisión en vez de asignar una etiqueta sin avisar.

## Protege la entrada y planifica el proceso

Envía solo la información necesaria para la tarea y trata los registros sensibles según las normas de tu organización. Si procesas una colección grande, prueba primero un lote pequeño y representativo, registra los fallos y define cómo reanudar sin perder ni duplicar elementos. Mide el tiempo y el coste del proceso real antes de aumentar el volumen.

El objetivo no es simplemente producir etiquetas, sino crear un proceso de decisión repetible cuyas definiciones, excepciones y errores puedan examinarse.

Para más orientación, consulta la [documentación de OpenAI sobre salidas estructuradas](https://platform.openai.com/docs/guides/structured-outputs) y las [buenas prácticas de evaluación](https://platform.openai.com/docs/guides/evaluation-best-practices).
