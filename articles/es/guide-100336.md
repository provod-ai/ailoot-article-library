# Presentamos los agentes gestionados en la API de Gemini

> Una guía práctica sobre agentes gestionados en la API de Gemini: elige tareas, revisa resultados y planifica costes, privacidad y gestión de fallos.



Una solicitud a un modelo de lenguaje suele producir una respuesta; un agente también puede dar pasos intermedios hacia un resultado. Por ejemplo, puede examinar datos, escribir código, ejecutarlo y devolver un informe. Los agentes gestionados de Google proporcionan un espacio de trabajo alojado para estas tareas mediante la API de Gemini. La función está en vista previa, por lo que conviene consultar la documentación y disponibilidad actuales antes de incorporarla a un proceso de producción.

Esta guía explica cómo elegir una primera tarea, evaluar el resultado y planificar el trabajo operativo de un agente gestionado. La [documentación de la API de Gemini](https://ai.google.dev/gemini-api/docs) de Google ofrece ejemplos de solicitudes e identificadores de agente compatibles actualizados.

## ¿Qué gestiona el proveedor?

En el enfoque de agentes gestionados, el proveedor ejecuta el entorno del agente y proporciona las herramientas que puede usar. Google describe un entorno aislado remoto en el que su agente Antigravity puede trabajar con archivos, ejecutar código y usar la web. Tu aplicación sigue teniendo que definir el objetivo, proporcionar entradas adecuadas y decidir si el resultado devuelto es aceptable.

Un entorno alojado resulta útil cuando una tarea necesita varios pasos y un espacio de trabajo intermedio. No sustituye las decisiones de la aplicación sobre autorización, revisión o tratamiento de datos. Comprueba qué herramientas y ajustes del entorno están disponibles para tu proyecto y versión antes de depender de ellos.

## Elige una primera tarea delimitada

Empieza con una tarea cuyo resultado se pueda comprobar sin confiar en la explicación del agente. Un pequeño resumen de CSV es un buen ejemplo: proporciona una muestra sin datos sensibles, pide una tabla de totales y especifica el formato de salida. Calcula algunos totales por separado y compáralos con el resultado.

Una descripción útil de la tarea incluye:

- La entrada y el significado de cada campo.
- La salida deseada, como un resumen y un archivo CSV.
- Las reglas para valores ausentes o inválidos.
- Un límite sobre los datos y las herramientas que puede usar el agente.
- Comprobaciones que el destinatario puede realizar antes de usar el resultado.

Por ejemplo: «Resume este CSV de muestra de ventas por mes y moneda. No combines monedas. Enumera por separado las filas sin fecha y proporciona los cálculos de cada total». En la prueba inicial, evita pedirle que envíe mensajes, modifique datos de producción o realice otras acciones externas.

## Ejecuta e inspecciona una interacción

Usa la [guía de inicio de Google](https://ai.google.dev/gemini-api/docs/get-started) para configurar el SDK y las credenciales; después sigue su ejemplo de agente gestionado. El ejemplo proporciona un identificador de agente, una entrada y un entorno remoto. Usa el identificador documentado actualmente por Google en lugar de asumir que uno antiguo de vista previa sigue disponible.

Examina algo más que el último párrafo. Comprueba el estado devuelto, la salida y los archivos que pienses usar. En una tarea de datos, compara las cifras con la fuente; si se genera un script, revísalo y pruébalo en un entorno controlado. Si la tarea depende de información de la web, abre las fuentes citadas y comprueba que respalden las afirmaciones. Un resultado bien presentado puede contener errores.

Si continúas el trabajo entre interacciones, sigue el ciclo de vida del entorno y de las interacciones documentado por Google. Guarda los identificadores pertinentes junto al registro del trabajo en tu aplicación y gestiona explícitamente la caducidad o los fallos; no supongas que un espacio de trabajo persistirá indefinidamente.

## Da instrucciones claras a un agente personalizado

Google también documenta formas de proporcionar instrucciones, habilidades y datos personalizados a agentes gestionados. Úsalas para describir el trabajo y los requisitos de salida, no para incorporar secretos en un documento. En una tarea de informes, las instrucciones podrían definir cómo agrupar datos, señalar la incertidumbre y actuar cuando no se pueda completar un cálculo.

Mantén los archivos de instrucciones bajo control de versiones y revisa los cambios como si fueran código de aplicación. Prueba una nueva versión con un pequeño conjunto de entradas representativas, incluidos archivos vacíos, valores inesperados y una solicitud fuera del ámbito previsto. Registra la versión y la entrada de cada evaluación para poder investigar los cambios de salida.

## Planifica costes, privacidad y fallos

Un agente de varios pasos puede realizar varias llamadas al modelo o usar herramientas antes de devolver un resultado. Revisa la [página de precios de Google](https://ai.google.dev/gemini-api/docs/pricing) y los límites de tu proyecto antes de una prueba; los cargos y las condiciones de vista previa pueden cambiar. Mide el uso en tareas representativas y establece un presupuesto a nivel de aplicación adecuado a la carga de trabajo.

Envía solo datos que el proceso esté autorizado a tratar. Considera las páginas recuperadas y los archivos subidos como entradas no fiables y revisa el código generado antes de ejecutarlo fuera del entorno aislado. Define qué ocurre si una tarea agota el tiempo, falla una herramienta o el agente devuelve un resultado incompleto. Reintentar una tarea con efectos secundarios puede repetirlos, así que comprueba la operación original antes de volver a intentarlo.

## ¿Cuándo conviene usar un agente gestionado?

Merece la pena evaluar un agente gestionado para tareas delimitadas de investigación, análisis o generación de archivos cuando ayudan varios pasos con herramientas y una persona o comprobación automática puede verificar la salida. Para una sola transformación predecible, una solicitud directa al modelo o código de aplicación ordinario puede ser más sencillo de operar. Compara calidad, latencia, coste y revisión necesaria para tu caso.
