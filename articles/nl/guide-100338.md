# Tools ontwerpen voor AI-agents: lessen voor Claude Code-workflows

> Een praktische gids voor het definiëren en testen van tools voor AI-agents, met voorbeelden voor programmeerworkflows.



Een AI-agent heeft meer nodig dan een goed model: hij heeft tools nodig die hij binnen de grenzen van een taak kan kiezen, begrijpen en gebruiken. Deze gids laat zien hoe je die interfaces ontwerpt, met programmeerworkflows als praktisch voorbeeld.

## Begin met een waarneembare taak

Beschrijf wat de agent moet bereiken voordat je bepaalt welke tools beschikbaar komen. Bij een vraag over een repository kan de taak zijn om te vinden waar een instelling wordt gelezen en naar de relevante bestanden te verwijzen. Een geschikte set tools kan de agent bestanden laten opsommen, tekst laten doorzoeken en geselecteerde bestanden laten lezen; voor het beantwoorden is geen toestemming nodig om iets te deployen.

Leg het verwachte resultaat en de acties buiten de scope vast. Een tool is nuttig als zijn invoer en uitvoer de agent helpen bij de volgende beslissing en de applicatie kan controleren of de actie is toegestaan.

## Geef elke tool een duidelijk contract

Een toolbeschrijving moet aangeven wat de tool doet, welke invoer vereist is en hoe het resultaat is opgebouwd. Gebruik verschillende namen en parameterbeschrijvingen voor tools met vergelijkbare doelen. Beschrijf relevante beperkingen: een zoektool kan bijvoorbeeld een begrensde lijst met overeenkomende paden teruggeven in plaats van de inhoud van elk bestand.

Een voorbeeldverzoek aan een tekstzoektool kan een zoekopdracht en een map bevatten. Het resultaat kan paden en regelnummers van treffers bevatten. De applicatie moet de map valideren en ontbrekende paden of mislukte zoekopdrachten expliciet afhandelen. Een correct opgebouwd verzoek bewijst niet dat het gevonden antwoord juist is.

## Breng flexibiliteit en controle in balans

Een algemene shell ondersteunt veel taken, maar biedt ook toegang tot veel acties. Een beperktere tool kan een veelvoorkomende handeling begrijpelijker maken en de uitgevoerde actie afbakenen. De juiste keuze hangt af van de taak, omgeving en beschikbare rechten; meer tools leveren niet automatisch betere resultaten op.

Houd de eerste set klein genoeg om te overzien. Voeg een gespecialiseerde tool toe wanneer waargenomen fouten of herhaald werk dat rechtvaardigen. Als een tool gegevens kan wijzigen of contact kan opnemen met een externe dienst, maak dat effect dan zichtbaar in de beschrijving en handhaaf de relevante rechten in de applicatie.

## Vraag op het juiste moment om ontbrekende informatie

Een agent mag een ontbrekende beslissing niet verzinnen. Als een taak werkelijk afhangt van informatie die hij niet kan vinden, kan een gestructureerde vraag de relevante keuzes en gevolgen uitleggen. Als onafhankelijk werk klaarstaat, kan de workflow daarmee doorgaan terwijl op antwoord wordt gewacht.

Maak vragen specifiek. Als een rapport bijvoorbeeld een niet opgegeven datumbereik vereist, vraag dan om dat bereik in plaats van de gebruiker de hele opdracht te laten herhalen. Een vraag vervangt het controleren van beschikbare context niet.

## Test tool en agent samen

Maak een kleine set representatieve taken: gewone verzoeken, dubbelzinnige invoer, onbeschikbare bestanden en pogingen een tool buiten het beoogde bereik te gebruiken. Bekijk welke tool is gekozen, welke argumenten zijn meegegeven, wat de uitvoer was en wat het definitieve antwoord is. Een geslaagde API-aanroep kan nog steeds onvolledige gegevens opleveren, dus controleer het antwoord aan de hand van het onderliggende bewijs.

Verander bij onderzoek naar een terugkerende fout steeds één onderdeel van de interface. Leg de versie van de toolbeschrijving vast en herhaal de relevante test. Controleer bij acties met neveneffecten een onzeker resultaat voordat je opnieuw probeert; een nieuwe poging kan een al geslaagde actie herhalen.

## Pas de ideeën toe in een programmeerworkflow

Claude Code ondersteunt workflows die tools en herbruikbare instructies combineren. Raadpleeg de actuele [documentatie over toolgebruik in Claude](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview) voor het API-contract en de [documentatie over Claude Code-skills](https://code.claude.com/docs/en/skills) voor de organisatie van herbruikbare instructies. Beschikbaarheid en exacte interfaces kunnen veranderen; controleer daarom de documentatie van de gebruikte versie.

Dezelfde ontwerpvragen gelden voor verschillende agentframeworks: wat vereist de taak, wat kan de agent waarnemen, wat kan elke tool veranderen en hoe verifieer je het resultaat?
