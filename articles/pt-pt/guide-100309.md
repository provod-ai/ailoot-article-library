# Claude API para principiantes: guia prático para começar

> Guia da Claude API para principiantes: configuração, primeiro pedido, seleção de modelos, funcionalidades essenciais e práticas de produção.



Tudo o que um programador precisa para fazer a primeira chamada à Claude API: chaves, Messages API, seleção de modelos e conceitos essenciais para passar do primeiro pedido à produção.

## O que é a Claude API

A Claude API é a plataforma para programadores da Anthropic. Dá acesso programático aos modelos Claude através da Messages API, com prompts de sistema, utilização de ferramentas, transmissão em fluxo, visão e respostas estruturadas.

A Messages API é um endpoint HTTP sem estado. Envie uma lista de mensagens de utilizador e de assistente, um ID de modelo e um limite de tokens; o Claude devolve uma resposta estruturada. Entre os endpoints de apoio contam-se lotes, ficheiros e contagem de tokens.

- **Sem estado:** A API não guarda memória. Reenvie o histórico da conversa em cada chamada.
- **Seleção de modelos:** Mudar de modelo costuma implicar mudar o respetivo ID.
- **SDKs:** As bibliotecas oficiais para Python (anthropic) e TypeScript (@anthropic-ai/sdk) usam estruturas de pedido correspondentes.

Compreender esta arquitetura ajuda a evitar um erro comum de principiantes: esperar que a API se lembre de um pedido anterior.

## Passo 1: Obtenha uma chave e configure a consola

Aceda a **console.anthropic.com**, crie uma conta ou uma organização para a sua equipa e gere uma chave de API na área de definições. Trate a chave como uma palavra-passe: guarde-a numa variável de ambiente e nunca a inclua no controlo de versões do código-fonte.

As chamadas HTTP diretas usam o cabeçalho **x-api-key** e o cabeçalho **anthropic-version**. Os SDKs leem automaticamente **ANTHROPIC_API_KEY** do ambiente, pelo que a maior parte do código não tem de lidar diretamente com a chave.

- Crie chaves distintas para desenvolvimento, staging e produção.
- Use espaços de trabalho para separar os projetos e as despesas da equipa.
- Defina limites de utilização na Consola antes de disponibilizar as chaves a uma equipa mais alargada.

## Passo 2: Faça a primeira chamada à Messages API

Instale o SDK com **pip install anthropic**, exporte a chave e execute:

```
import anthropic

client = anthropic.Anthropic()
msg = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Explain REST in one paragraph."}],
)
for block in msg.content:
    if block.type == "text":
        print(block.text)
```

São necessários três parâmetros: **model**, **max_tokens** (o limite superior da resposta) e **messages**. A resposta contém uma lista de blocos de conteúdo. Verifique o tipo de cada bloco, em vez de presumir que é texto simples, porque a utilização de ferramentas e o raciocínio podem acrescentar outros tipos de bloco. O objeto **usage** apresenta os tokens de entrada e saída, que podem servir como telemetria de custos.

## Passo 3: Escolha um modelo

Eis os modelos Claude atuais da Anthropic e os respetivos IDs da API.

- **Claude Haiku 5.5** (**claude-haiku-5-5**) — descrito como rápido e económico, indicado para classificação e tarefas simples de grande volume.
- **Claude Sonnet 5.5** (**claude-sonnet-5-5**) — descrito como uma opção equilibrada para cargas de produção, incluindo programação.
- **Claude Opus 5.5** (**claude-opus-5-5**) — descrito para raciocínio difícil e trabalho agêntico de longo prazo.
- **Claude Fable 5.2** (**claude-fable-5-2**) — descrito como modelo de referência para tarefas de raciocínio exigentes.

Comece com Opus 5.5. Experimente Sonnet 5.5 para equilibrar velocidade e qualidade, Haiku 5.5 para tarefas simples de elevado volume e Fable 5.2 para raciocínio complexo. Consulte a página de preços da Anthropic para ver as tarifas atuais.

## Os cinco conceitos seguintes a aprender

Depois de a primeira chamada funcionar, estas funcionalidades cobrem muitas necessidades das aplicações:

- **Prompts de sistema** — um parâmetro **system** de nível superior define a função, o tom e as regras, separado das mensagens do utilizador.
- **Conversas com várias interações** — acrescente cada resposta do assistente ao array messages e volte a enviá-lo; a primeira mensagem tem de ser do utilizador.
- **Transmissão em fluxo** — os eventos enviados pelo servidor entregam tokens à medida que são gerados, o que pode ajudar em interfaces de chat e respostas longas.
- **Visão** — envie imagens como blocos de conteúdo em base64 ou URL juntamente com texto.
- **Utilização de ferramentas** — defina funções com esquemas JSON; o Claude pode decidir quando as chamar, enquanto o seu código as executa e devolve os resultados.

Considere a **cache de prompts** e o **processamento em lote** quando o custo for importante, e as **respostas estruturadas** quando o código seguinte tiver de analisar a resposta.

## Do tutorial à produção

Passar de um script funcional para uma integração de produção exige disciplina de engenharia:

- **Tratamento de erros:** Trate os erros de limite de pedidos (429) e os erros do servidor de forma distinta. A fonte afirma que os SDKs repetem estas chamadas automaticamente com espera progressiva; confirme o comportamento atual na documentação do SDK relevante.
- **Visibilidade dos custos:** Registe o **usage** de cada resposta no seu sistema de métricas.
- **Versionamento de prompts:** Trate os prompts como código: reveja-os, versione-os e teste-os com um pequeno conjunto de avaliação.
- **Fixação do modelo:** Referencie os IDs dos modelos na configuração para que as atualizações sejam deliberadas e testadas.

### Principais conclusões

- A Messages API não tem estado; reenvie o histórico da conversa em cada chamada.
- A autenticação HTTP direta usa o cabeçalho x-api-key; os SDKs podem ler ANTHROPIC_API_KEY do ambiente.
- Os três parâmetros obrigatórios são model, max_tokens e messages.
- Comece com Opus 5.5 e compare as alternativas com os seus próprios dados.
- Prompts de sistema, transmissão em fluxo, visão, utilização de ferramentas e histórico de várias interações suportam muitos padrões de aplicação.
- Registe o uso de tokens para acompanhar custos e planear a capacidade.

## Perguntas frequentes

### Preciso de saber aprendizagem automática para usar a Claude API?

Não. A Claude API é uma API REST com SDKs oficiais para Python e TypeScript. Se consegue chamar um endpoint HTTP e analisar JSON, pode criar aplicações com Claude. A conceção de prompts, o tratamento de erros e a gestão de custos são competências úteis de engenharia; não é necessária teoria de aprendizagem automática para fazer a primeira chamada à API.

### Com que modelo Claude deve começar um principiante?

A Anthropic recomenda começar com Claude Opus 5.5 (ID da API `claude-opus-5-5`) para a maioria das cargas de trabalho. Quando os seus prompts estiverem estáveis, compare os restantes modelos com os seus próprios dados.

### A Claude API lembra-se das conversas anteriores?

Não. A Messages API não tem estado. A sua aplicação guarda a conversa e reenvia o histórico completo de mensagens em cada pedido. Assim, controla o contexto, pode encurtar ou resumir interações antigas e combinar essa abordagem com a cache de prompts.
