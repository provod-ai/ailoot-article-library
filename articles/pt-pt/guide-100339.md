# Gemini: como escolher entre a aplicação e a API

> Um guia prático para escolher entre a aplicação Gemini e a API, avaliar modelos e estimar os custos de utilização.



O Gemini pode ser usado através da aplicação da Google para utilizadores ou integrado em software através de uma API. O ponto de partida adequado depende de querer realizar uma tarefa por si ou criar um processo repetível para outras pessoas.

## Comece pela tarefa

Para uma tarefa pontual, como redigir uma mensagem ou explorar uma ideia, uma aplicação interativa permite fazer uma pergunta e aperfeiçoar a resposta. Verifique o resultado antes de confiar nele: uma resposta fluente pode conter erros, omitir contexto ou citar uma fonte incorretamente.

Uma API é útil quando uma aplicação precisa de enviar entradas e processar saídas como parte de um processo. Por exemplo, uma aplicação de apoio pode resumir um pedido para revisão humana. O programador tem de tratar das instruções, do acesso a dados, das falhas e da forma como os resultados são apresentados ou guardados.

A aplicação e a API são produtos diferentes. Não presuma que uma funcionalidade, limite, subscrição ou definição de dados de um esteja automaticamente disponível no outro. Consulte a documentação e as definições do produto e da conta que utiliza efetivamente.

## Escolha um modelo para a tarefa

Comece com alguns exemplos representativos em vez de escolher um modelo apenas pelo nome. Para uma tarefa de resumo, inclua uma mensagem curta, uma longa e um caso com informação em falta. Defina o que uma boa resposta tem de preservar, o que não pode inventar e qual deve ser a sua extensão.

Se uma tarefa envolver imagens, áudio ou outra entrada, verifique se o modelo e o endpoint específicos suportam o formato necessário. As modalidades suportadas, os limites de contexto e a disponibilidade podem diferir entre modelos e mudar. Consulte a [documentação da Gemini API](https://ai.google.dev/gemini-api/docs) da Google para conhecer as opções atuais e os formatos de pedido.

## Estime o custo com uma amostra realista

Para um processo com API, registe a quantidade de entrada e saída usada por um pequeno conjunto representativo de pedidos. Multiplique a utilização medida pelos preços publicados relevantes, considerando cada tipo de entrada e saída aplicável. Depois, estime a frequência de execução e preveja margem para novas tentativas e variações no comprimento das respostas.

Trate o resultado como uma estimativa, não como uma fatura garantida. Consulte os [preços atuais da Gemini API](https://ai.google.dev/gemini-api/docs/pricing), as quotas e as definições de faturação da sua conta. Uma subscrição da aplicação e a utilização da API podem ter condições diferentes.

## Avalie antes de aumentar a escala

Compare os resultados com exemplos revistos por pessoas. Em cada resposta, confronte os factos com a entrada e verifique o formato pedido e as regras específicas da tarefa. Inclua casos difíceis e casos em que o modelo deve recusar ou encaminhar para uma pessoa. Uma resposta aparentemente válida não é necessariamente correta.

Registe as falhas e altere uma parte do processo de cada vez: as instruções, a preparação da entrada, o modelo ou a validação da saída. Repita o mesmo conjunto de testes após uma alteração. Se o modelo ou o tipo de dados recebidos mudar, volte a avaliar o resultado em vez de presumir que a avaliação anterior continua válida.

## Trate os dados e as falhas deliberadamente

Envie apenas os dados necessários e reveja as definições de tratamento de dados do produto relevante antes de usar informação sensível. Valide as saídas antes de a aplicação agir com base nelas. Planeie limites de frequência, tempos limite e resultados incompletos; apresente um erro com uma ação possível ou encaminhe o caso para revisão, em vez de tratar silenciosamente uma falha como tarefa concluída.

Para pedidos que possam desencadear ações externas, mantenha um registo da operação e verifique o seu estado antes de tentar novamente. Uma resposta perdida durante a transmissão não prova que a ação falhou.
