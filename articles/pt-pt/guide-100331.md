# LLM-as-a-Judge: Usar IA para Avaliar IA (de Forma Fiável)

> Como usar modelos de linguagem para avaliar resultados de IA, ter em conta o enviesamento do juiz, conceber rubricas e calibrar pontuações automatizadas com base em juízos humanos.



Um juiz baseado num LLM aplica critérios escritos à resposta de outro sistema de IA. Pode ajudar as equipas a analisar grandes conjuntos de respostas, mas os seus veredictos devem ser comparados com exemplos avaliados por pessoas.

## Comece pela tarefa e pelos critérios

Escolha uma tarefa, como responder a perguntas de apoio ao cliente com base numa política fornecida. Descreva o comportamento esperado em termos observáveis. Por exemplo, verifique se a resposta segue a política, responde à pergunta e evita afirmações sem fundamento. Os critérios devem também indicar o que fazer quando faltam dados.

Avalie critérios separados antes de produzir um resultado global. Uma resposta pode ser concisa, mas imprecisa; uma pontuação única pode esconder essa diferença. Guarde os critérios e a versão do modelo juiz juntamente com os resultados para dar contexto a comparações posteriores.

## Escolha uma forma de comparação

Para uma verificação de aprovação ou reprovação, forneça ao juiz a pergunta, os dados disponíveis e uma resposta. Peça uma decisão para cada critério e uma breve explicação fundamentada no material fornecido. Esta abordagem funciona melhor quando os critérios são suficientemente específicos para que os avaliadores os apliquem de forma consistente.

Para uma comparação, forneça ao juiz duas respostas à mesma pergunta e peça-lhe que escolha a que melhor cumpre os critérios, permitindo um empate. Repita a comparação com a ordem invertida. Se o vencedor mudar, assinale o caso para revisão em vez de considerar qualquer dos resultados definitivo. Remova rótulos desnecessários que revelem o sistema que produziu cada resposta.

Uma resposta de referência pode ajudar numa pergunta cuja resposta seja conhecida. Em tarefas abertas, trate-a como um exemplo de qualidade aceitável, não como a única formulação válida.

## Torne os resultados utilizáveis

Peça um resultado estruturado com uma decisão e uma breve justificação para cada critério. Por exemplo:

```json
{"policy_supported":{"result":"pass","reason":"A resposta cita a regra de cancelamento fornecida."},"addresses_question":{"result":"fail","reason":"Não explica como cancelar."}}
```

Este é um exemplo de resposta possível, não uma prova de que um juiz verificou um caso real. Valide o resultado antes de o usar num relatório; volte a tentar ou encaminhe resultados mal formatados para revisão, conforme o seu processo. A explicação do modelo também é um resultado a analisar, não uma prova de que o veredicto está correto.

## Calibre com pessoas

Crie uma amostra representativa com casos simples, casos limite e falhas conhecidas. Peça a avaliadores que apliquem independentemente os mesmos critérios a uma parte comum da amostra, discutam divergências e registem as decisões. Depois, compare os resultados do juiz com essas avaliações humanas, examine as divergências e reveja os critérios ou o processo antes de confiar na métrica.

Preste especial atenção à ordem, ao comprimento e ao estilo. Uma resposta mais polida ou mais longa não é necessariamente mais exata. Inclua na amostra respostas corretas e concisas e respostas incorretas mas plausíveis. Em testes por pares, meça com que frequência a inversão da ordem altera a decisão.

## Use o juiz como uma das camadas

Execute primeiro verificações determinísticas quando forem adequadas: por exemplo, valide o JSON ou verifique um campo obrigatório. Use o juiz para critérios que exigem interpretação e mantenha a revisão humana para casos incertos ou importantes. Acompanhe resultados agregados num conjunto de dados estável, mas examine também as falhas individuais.

Volte a verificar a calibração quando mudar o modelo, os critérios, a tarefa ou a distribuição dos dados de entrada. Uma pontuação mais alta, por si só, não demonstra melhoria: examine as respostas e mantenha um conjunto de avaliação separado quando a mesma métrica automática for usada para otimizar o sistema.

## Lista de verificação prática

1. Defina a tarefa, os dados disponíveis e os critérios.
2. Reúna exemplos e acorde as avaliações humanas.
3. Escolha a avaliação de uma resposta ou a comparação por pares e preveja empate ou incerteza.
4. Valide os resultados estruturados e reveja as divergências.
5. Acompanhe as versões e volte a calibrar após alterações relevantes.

Para mais informações, consulte as [recomendações da OpenAI para avaliação](https://platform.openai.com/docs/guides/evaluation-best-practices).
