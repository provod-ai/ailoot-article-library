# Conceber ferramentas para agentes de IA: lições para fluxos de trabalho com Claude Code

> Um guia prático para definir e testar ferramentas para agentes de IA, com exemplos para fluxos de trabalho de programação.



Um agente de IA precisa de mais do que um bom modelo: precisa de ferramentas que consiga selecionar, compreender e usar dentro dos limites de uma tarefa. Este guia mostra como conceber essas interfaces, usando fluxos de programação como exemplo prático.

## Comece com uma tarefa observável

Descreva o que o agente deve alcançar antes de decidir que ferramentas disponibilizar. Numa pergunta sobre um repositório, a tarefa pode ser encontrar onde uma definição é lida e citar os ficheiros relevantes. Um conjunto adequado pode permitir listar ficheiros, pesquisar texto e ler ficheiros selecionados; não é preciso dar permissão para fazer uma implementação em produção para responder à pergunta.

Registe o resultado esperado e as ações fora do âmbito. Uma ferramenta é útil quando as suas entradas e saídas ajudam o agente a tomar a decisão seguinte e quando a aplicação pode verificar se a ação é permitida.

## Defina um contrato claro para cada ferramenta

A descrição deve indicar o que a ferramenta faz, as entradas obrigatórias e a estrutura do resultado. Use nomes e descrições de parâmetros distintos para ferramentas com objetivos semelhantes. Descreva limites relevantes: por exemplo, uma pesquisa pode devolver uma lista limitada de caminhos correspondentes, em vez do conteúdo de todos os ficheiros.

Um pedido ilustrativo de pesquisa de texto pode conter uma consulta e um diretório. O resultado pode incluir caminhos e números das linhas correspondentes. A aplicação deve validar o diretório e tratar explicitamente caminhos inexistentes ou pesquisas falhadas. Um pedido bem formado não prova que a resposta encontrada esteja correta.

## Equilibre flexibilidade e controlo

Uma linha de comandos de uso geral suporta muitas tarefas, mas também expõe um amplo conjunto de ações. Uma ferramenta mais restrita pode tornar uma operação comum mais fácil de compreender e limitar a ação executada. A escolha depende da tarefa, do ambiente e das permissões disponíveis; mais ferramentas não produzem automaticamente melhores resultados.

Mantenha o conjunto inicial suficientemente pequeno para ser fácil de explorar. Acrescente uma ferramenta especializada quando falhas observadas ou trabalho repetido o justificarem. Se uma ferramenta puder alterar dados ou contactar um serviço externo, indique esse efeito na descrição e imponha as permissões relevantes na aplicação.

## Peça informação em falta no momento certo

Um agente não deve inventar uma decisão em falta. Se a tarefa depender realmente de informação que não consegue encontrar, uma pergunta estruturada pode apresentar as opções e explicar as consequências. Enquanto espera pela resposta, o processo pode continuar o trabalho independente que já estiver pronto.

Faça perguntas específicas. Por exemplo, se um relatório precisar de um intervalo de datas que não foi fornecido, peça esse intervalo em vez de pedir ao utilizador que repita toda a tarefa. Uma pergunta não substitui a verificação do contexto disponível.

## Teste a ferramenta e o agente em conjunto

Crie um pequeno conjunto de tarefas representativas: pedidos comuns, entradas ambíguas, ficheiros indisponíveis e tentativas de usar uma ferramenta fora do seu âmbito. Examine a ferramenta escolhida, os argumentos enviados, o resultado devolvido e a resposta final. Uma chamada à API bem-sucedida pode ainda assim devolver dados incompletos, pelo que deve comparar a resposta com os dados originais.

Ao investigar uma falha recorrente, altere uma parte da interface de cada vez. Registe a versão da descrição da ferramenta e repita o teste relevante. Para ações com efeitos secundários, reconcilie um resultado incerto antes de tentar novamente; a repetição pode executar outra vez uma ação que já tenha sido concluída.

## Aplique as ideias num fluxo de programação

O Claude Code suporta fluxos que combinam ferramentas e instruções reutilizáveis. Consulte a [documentação atual do Claude sobre utilização de ferramentas](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview) para o contrato da API e a [documentação de competências do Claude Code](https://code.claude.com/docs/en/skills) para a organização das instruções reutilizáveis. A disponibilidade e as interfaces exatas podem mudar, por isso consulte a documentação da versão em uso.

As mesmas questões de conceção aplicam-se a diferentes frameworks de agentes: o que exige a tarefa, o que pode o agente observar, o que pode cada ferramenta alterar e como será verificado o resultado?
