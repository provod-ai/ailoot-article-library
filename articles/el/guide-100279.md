# Το πραγματικό κόστος inference ενός LLM είναι η GPU που δεν χρησιμοποιείτε

> Δύο παλιές τιμές αναφοράς API για token εισόδου είχαν λόγο 600 προς ένα. Κόστος inference LLM βάσει αξιοποίησης GPU, χρεώσιμων ωρών αδράνειας και τιμών αιχμής.



Μια μελέτη του 2026 (arXiv:2603.28576, §4) συνέκρινε δύο τιμές αναφοράς API. Ως τιμή αναφοράς για το GPT-3 το 2020 χρησιμοποίησε 60 δολάρια ΗΠΑ ανά εκατομμύριο token εισόδου. Για το Gemini 2.0 Flash της οικονομικής κατηγορίας τον Φεβρουάριο του 2025 χρησιμοποίησε 0,10 δολάρια ΗΠΑ ανά εκατομμύριο. Η αναλογία είναι 600 προς ένα. Για την οικονομική κατηγορία που εξέτασε, η μελέτη εκτίμησε τον χρόνο υποδιπλασιασμού των τιμών στα 1,1 έτη.

Αυτό που κρύβουν οι τίτλοι για τον αποπληθωρισμό είναι το στοιχείο που καθορίζει πραγματικά τον λογαριασμό σας: πόσες ώρες GPU εκτελούν χρήσιμη εργασία. Το inference χρεώνεται ανά token, αλλά παρέχεται ανά ώρα.

Διάδρομος κέντρου δεδομένων με διακομιστές GPU, οι περισσότεροι φωτισμένοι και σε λειτουργία, ενώ ένας είναι σβηστός και αδρανής

## Ο αριθμός που παραβλέπουν οι ομάδες

Σε δοκιμή επιδόσεων με vLLM τον Ιούνιο του 2026 (arXiv:2606.11690, §§4–5), το Mixtral 8x7B Instruct εκτελέστηκε σε FP16 σε δύο GPU H100 NVL με παραλληλισμό τανυστών (TP=2). Το συνολικό κόστος ενοικίασης ήταν 13,96 δολάρια ΗΠΑ την ώρα. Χρησιμοποιήθηκαν συνθετικά αιτήματα με 512 token εισόδου και 256 token εξόδου, με απενεργοποιημένη την προσωρινή αποθήκευση προθεμάτων. Ο πίνακας διαιρεί το κόστος ενοικίασης των GPU με τον μετρημένο αριθμό των token εξόδου για την ίδια περίοδο. Ο ρυθμός αιτημάτων μετρά όσα έφταναν στον διακομιστή.

| Mixtral 8x7B σε δύο GPU H100 NVL | Πραγματικό κόστος ανά 1 εκατομμύριο token εξόδου |
|-------------------------------------|------------------------------------------------|
| 1 αίτημα ανά δευτερόλεπτο (σχεδόν αδρανής) | περίπου $15.25 |
| 100 εισερχόμενα αιτήματα ανά δευτερόλεπτο (κοντά στον κορεσμό) | περίπου $0.87 |

Οι δύο μετρήσεις διαφέρουν κατά συντελεστή 17,5. Με 25 εισερχόμενα αιτήματα ανά δευτερόλεπτο, το κόστος ήταν περίπου 0,95 δολάρια ΗΠΑ ανά εκατομμύριο token εξόδου. Με 100 εισερχόμενα αιτήματα ανά δευτερόλεπτο, ο διακομιστής ολοκλήρωνε περίπου 17,4 αιτήματα ανά δευτερόλεπτο. Στις έξι διαμορφώσεις H100 και στους φόρτους που μετρήθηκαν, η μελέτη βρήκε κόστος από 0,21 έως 15,25 δολάρια ΗΠΑ ανά εκατομμύριο token εξόδου. Οι τιμές αυτές αφορούν τον συγκεκριμένο φόρτο δοκιμής. Στην παραγωγή, μετρήστε τον ρυθμό παραγωγής token σε φόρτο που σας επιτρέπει να τηρείτε τον στόχο καθυστέρησης.

Με την ίδια ωριαία τιμή ενοικίασης, αν ο ρυθμός παραγωγής token πέσει στο 40% του μέγιστου, το κόστος ανά token εξόδου φτάνει στο 2,5πλάσιο. Στα παραδείγματα που ακολουθούν, η αξιοποίηση είναι το ποσοστό του μέγιστου ρυθμού παραγωγής token εξόδου που πετυχαίνει στην πράξη η υπηρεσία. Μια GPU μπορεί να εμφανίζει υψηλή δραστηριότητα ενώ παράγει λίγα token εξόδου.

Γι’ αυτό δύο ομάδες που εκτελούν το ίδιο μοντέλο μπορεί να αναφέρουν εντελώς διαφορετικό μοναδιαίο κόστος. Η μία εκτελεί ένα chatbot με απότομες διακυμάνσεις στο 40 τοις εκατό αξιοποίησης· η άλλη εκτελεί μια κορεσμένη διαδικασία batch στο 90 τοις εκατό. Το μοντέλο, το υλικό και η τιμή καταλόγου είναι ίδια. Το μοναδιαίο κόστος δεν είναι. Όταν ένας πάροχος σάς αναφέρει κόστος ανά token, ρωτήστε ποια παραδοχή αξιοποίησης έχει συνυπολογιστεί.

## Τα μοντέλα ανοιχτών βαρών επιδείνωσαν την κατάσταση

Ένα μοντέλο Mixture-of-Experts (MoE) χρησιμοποιεί μόνο ένα μέρος των βαρών του για κάθε token. Το Mixtral 8x7B ενεργοποιεί περίπου 12,9 δισεκατομμύρια παραμέτρους ανά token, από σύνολο 46,7 δισεκατομμυρίων. Αν εκτελείτε ολόκληρο το μοντέλο σε GPU, υπολογίστε τη μνήμη για όλα τα βάρη στην ακρίβεια με την οποία αποθηκεύονται, καθώς και για την KV cache και τις πρόσθετες ανάγκες μνήμης του περιβάλλοντος εκτέλεσης. Ο αριθμός των ενεργών παραμέτρων βοηθά να εκτιμήσετε το υπολογιστικό έργο ανά token. Το εύρος ζώνης της μνήμης, η δρομολόγηση προς τους ειδικούς και το μέγεθος της παρτίδας επηρεάζουν επίσης τον ρυθμό παραγωγής token.

Υπολογίστε το σημείο ισορροπίας για τον δικό σας φόρτο εργασίας. Συγκρίνετε τον λογαριασμό του API για το ίδιο μείγμα token εισόδου και εξόδου με το κόστος ενοικίασης GPU για όσες ώρες τις χρειάζεστε, μαζί με τις ώρες αδράνειας, και το κόστος λειτουργίας της υπηρεσίας. Μετρήστε τον ρυθμό παραγωγής token με βάση το μοτίβο κίνησης και τον στόχο καθυστέρησής σας. Οι τιμές του API, η διαμόρφωση του μοντέλου και η αξιοποίηση των πόρων επηρεάζουν το αποτέλεσμα.

## Το δεύτερο κρυφό κόστος: η ώρα της ημέρας

Σύμφωνα με την τιμολόγηση που ισχύει στις 25 Νοεμβρίου 2026, οι τιμές αιχμής για απευθείας χρήση του API της DeepSeek ισχύουν από 01:00 έως 04:00 και από 06:00 έως 10:00 UTC, από Δευτέρα έως Παρασκευή, εκτός από τις επίσημες αργίες στην Κίνα. Σε ώρα Ινδίας (IST, UTC+05:30), τα διαστήματα είναι 06:30–09:30 και 11:30–15:30. Όλες τις υπόλοιπες ώρες ισχύουν οι τιμές εκτός αιχμής, συμπεριλαμβανομένων ολόκληρων των ημερών του Σαββατοκύριακου και των επίσημων αργιών στην Κίνα. [Τιμές του API της DeepSeek](https://api-docs.deepseek.com/quick_start/pricing/)

Σε εργάσιμη ημέρα που ισχύουν οι τιμές αιχμής, οι 10:00 IST (04:30 UTC) είναι εκτός αιχμής και οι 15:00 IST (09:30 UTC) είναι ώρα αιχμής. Σε δολάρια ΗΠΑ ανά εκατομμύριο token, οι τιμές για το `deepseek-flash` εκτός αιχμής και σε ώρες αιχμής είναι 0,003 και 0,006 για token εισόδου που βρέθηκαν στην cache, 0,15 και 0,30 για token εισόδου που δεν βρέθηκαν στην cache και 0,60 και 1,20 για token εξόδου. Για το `deepseek-v4-pro` οι αντίστοιχες τιμές, με την ίδια σειρά, είναι 0,022 και 0,044, 0,66 και 1,32, και 1,98 και 3,96.

## Τι επηρεάζει πραγματικά τον αριθμό

Αν καταρτίζετε προϋπολογισμό για inference, εξετάστε τα παρακάτω πριν συγκρίνετε τις τιμές των μοντέλων:

1.  Πρώτα η αξιοποίηση και μετά το υλικό. Μια H200 με αξιοποίηση 40 τοις εκατό μπορεί να κοστίζει περισσότερο ανά token από μια H100 που λειτουργεί πλήρως.
2.  Ελέγξτε αν ο πάροχός σας χρεώνει λιγότερο για τα token που βρίσκει στην cache. Η επαναχρησιμοποίηση ενός μεγάλου system prompt ή ενός κοινού προθέματος μπορεί να μειώσει το κόστος των token εισόδου, εφόσον ισχύει για αυτά η μειωμένη χρέωση της cache.
3.  Σταθμίστε τις τιμές αιχμής και εκτός αιχμής με βάση την κατανομή της κίνησής σας. Με απευθείας χρήση του API της DeepSeek, η ίδια κατανάλωση token υπό τις ίδιες συνθήκες cache κοστίζει διπλάσια στις ώρες αιχμής.
4.  Επεξεργαστείτε σε παρτίδες τις εργασίες παρασκηνίου που μπορούν να περιμένουν, όπως η ευρετηρίαση για RAG και η μαζική εξαγωγή δεδομένων. Μετρήστε τον ρυθμό παραγωγής token εξόδου και την καθυστέρηση με τις ρυθμίσεις ομαδοποίησης που σκοπεύετε να χρησιμοποιήσετε.
5.  Στα μοντέλα MoE, χρησιμοποιήστε τον αριθμό των ενεργών παραμέτρων για να εκτιμήσετε τις υπολογιστικές απαιτήσεις. Υπολογίστε τη μνήμη για το σύνολο των βαρών, την KV cache και τις πρόσθετες ανάγκες του περιβάλλοντος εκτέλεσης.
