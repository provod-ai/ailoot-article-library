# 在文字分類流程中使用 LLM 特徵

> 在分類流程中使用 LLM 產生的特徵，並評估門檻與校準的實用指南。



語言模型可以直接分類文字，也可以產生訊號，讓另一個模型與其他資料一起使用。兩種方法沒有哪一種必然更好。實用的選擇取決於任務、可用標籤和錯誤成本。

## 從基準方案開始

定義結果並收集反映所需決策的範例。例如客服流程的任務可能是找出需要緊急人工審查的工單。先對「緊急」的定義達成共識，納入模糊案例，並記錄人員如何標記。

增加複雜度前先測試簡單的基準方案。它可以是規則、被提示回傳標籤的模型，或以既有標記資料訓練的監督式分類器。使用相同的保留範例比較各方法。直接使用 LLM 分類可能有用；不應僅因存在其他方法就排除它。

## 將模型輸出轉成特徵

不要只要求語言模型給出最終決策，也可以請它回報一小組任務專屬訊號。在客服範例中，這些訊號可指出訊息是否描述服務中斷或帳務問題。下游分類器可以結合這些訊號與允許的結構化欄位，例如產品類別。

精確定義每個訊號，並驗證輸出格式。產生的訊號可能錯誤或缺失，下游模型也可能從這些錯誤中學習。不要納入實際決策時無法取得的資訊。

## 擬合前先切分資料

選擇特徵或調整門檻前，先將訓練資料與驗證、測試資料分開。當同一客戶的訊息或較後時段的訊息彼此相關時，應選擇反映系統實際使用方式的切分方式。否則測試集資訊可能洩漏到訓練中，使結果看起來比實際更好。

使用訓練集擬合下游模型。用驗證資料選擇特徵與決策門檻，再以獨立測試集評估選定流程。檢查整個流程，包括無法取得或解析 LLM 輸出的失敗情況；不要只評估成功的呼叫。

## 根據後果選擇門檻

分類器可能為每個項目產生分數或機率。門檻會將數值轉成動作，例如將工單送交審查。移動門檻可能改變精確率和召回率，但適當取捨取決於漏掉案例與不必要審查的成本。

如果打算把分數解讀為機率，請在適當的保留資料上評估其校準情況。擬合邏輯斯迴歸或要求模型提供信心值，都不能保證機率已校準。比較校準情況與分類指標，也要檢查重要群體及罕見案例的表現。

## 衡量完整工作流程

在相同評估集上比較基準方案和特徵式系統。記錄偽陽性、偽陰性、延遲、成本，以及失敗或需要人工審查的呼叫比例。較複雜的流程應在任務上帶來可衡量的效益，才能證明額外營運成本值得。

追蹤提示、模型、特徵與門檻的版本。當它們變更或輸入資料分布改變時，重新評估。有關建立及維護評估的更多指引，請參閱 [OpenAI 評估最佳實務](https://platform.openai.com/docs/guides/evaluation-best-practices)。
