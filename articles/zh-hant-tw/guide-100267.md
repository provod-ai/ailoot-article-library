# AI 內容審核：運作方式、類型與最佳 API

> 了解主要的內容審核方法、自動化系統如何融入審查工作流程，以及評估時應衡量哪些指標。


過去，內容審核是文字問題。有人發布內容，分類器為其評分，由人工審查難以判定的案例，而待處理佇列大致還能跟上。
後來平台加入了音訊和影片，待處理佇列便開始跟不上。45 分鐘的 Podcast、直播、語音代理對話、使用者上傳的影片——在語音轉成文字之前，文字分類器都無法掃描這些內容。而內容量也遠遠超出人工審查的能力。這正是 AI 內容審核要解決的問題，也是有趣的工程挑戰從「這個字串有毒嗎？」轉向「一萬小時的音訊裡實際說了什麼？哪 90 秒需要人工檢視？」的原因。
本文將介紹 AI 內容審核的定義、常見的六種類型、自動化與混合式系統的實際運作方式、值得評估的 API，以及多數指南略過的部分——如何衡量自己的系統表現如何。
## 什麼是 AI 內容審核？
AI 內容審核是運用機器學習模型，自動偵測、分類並處理違反平台政策或法律義務的內容，涵蓋文字、圖片、影片和音訊。
這句話中的「AI」有其具體作用。以規則為基礎的審核方式——禁用詞清單、regex 模式、雜湊比對——至今仍廣泛用於正式環境，也依然有用，但它無法理解上下文。模型可以分辨侮辱詞是用來攻擊他人，還是在新聞報導中被引用；詞彙清單則無法做到。這種依上下文判斷的能力，正是 AI 內容審核與篩選的區別。
### 實務上的內容審核意義
去除供應商用語後，內容審核代表三項操作：
1.  **偵測** — 找出可能違反政策的內容。
2.  **分類** — 判斷違反哪項政策，以及嚴重程度。
3.  **處置** — 移除、設定年齡限制、取消營利、標記以供人工審查，或不採取任何行動。
多數審核失敗發生在第三步，而非第一步。團隊建立偵測器，直接連接自動下架機制，接著發現大型平台 5% 的誤判率代表每天有數千則貼文遭到錯誤移除，還會累積無人手處理的申訴。
一個實用的思考方式是：審核系統的工作不是做決定，而是把決策送到適當的地方；大部分由自動化處理，部分由人工處理，少數則涉及尚無人解答的政策問題。
## AI 內容審核的 6 種類型
這六種類型會出現在所有成熟的審核架構中。多數平台會同時執行其中三到四種，並套用在不同內容層級。
### 1. 事前審核
內容在上線前先經過審查。通過審核前，任何內容都不會發布。
這是最安全但也最慢的做法，因此適用於漏判代價極高、內容量又少的情境：兒童平台、醫療社群、受監管的金融內容、交友個人檔案照片。這確實會造成阻力——使用者會注意到發布延遲——因此事前審核通常只適用於部分內容類型，而非所有內容。
### 2. 事後審核
內容立即發布，之後再進行審查，通常在幾分鐘內完成。偵測到違規後便會移除內容。
這是多數社群和 UGC 平台的預設方式。它保留使用者期待的即時體驗，並接受短暫暴露的代價。工程上的問題在於，這段暴露時間究竟能縮短到多短；對音訊和影片而言，完全取決於轉錄速度。
### 3. 檢舉式審核
除非有使用者檢舉，否則不審查任何內容。由社群負責偵測。
這種方式成本低、易於擴展，但在結構上存在偏差——在小型社群、使用者多數不會說的語言，以及會傷害到不在場、無法檢舉者的內容中，檢舉式審核都容易系統性漏掉違規。如今沒有人只採用這種方式，但它仍是自動偵測的重要訊號來源，因為人工檢舉能揭露模型從未受訓去尋找的問題。
### 4. 分散式或社群審核
由可信任的使用者、志工審核者，或依聲譽加權的投票做出判斷。可以想想 subreddit 版主或社群備註。
這種方式在文化層面容易擴展，因為套用規範的人正是認同這些規範的人；但在法律層面則難以擴展——志工不等於合規計畫。它最適合當作大型系統中的一個環節，而不是整套系統。
### 5. 自動化審核
模型負責偵測，對於信心度高的案例也會執行處置。本文主要探討的就是這一層。
自動化審核涵蓋文字分類、圖片和影片分類、已知不良媒體的雜湊比對，以及日益重要的音訊審核。音訊處理流程是多數團隊尚未建立的部分：語音轉文字會將口語內容轉成文字，接著由內容安全模型依主題和嚴重程度分類，再透過實體偵測與個人識別資訊遮蔽處理隱私問題。
### 6. 混合式審核
模型負責分流，人工判斷棘手案例。成熟的平台實際上採用的就是這種方式；它與其說是獨立類型，不如說是其他五種類型的正確組合。
混合式審核的設計問題在於門檻應設在哪裡。門檻太嚴格，人工待審佇列就會塞滿明顯不違規的內容；太寬鬆，違規內容就會通過自動核准。設定合適門檻需要持續衡量，而不是在上線時決定一次就好——因此以下的準確度章節，比 API 比較更重要。
大規模審核音訊與影片
將口語內容轉成已分類、可供審查的文字，並內建內容安全偵測功能。免費開始，並使用自己的媒體進行測試。
## 自動化內容審核的運作方式
自動化審核流程在幕後分為四個階段。了解這些階段，就能看出購買內容審核 API 與建置內容審核系統之間的差異。
**第一階段：擷取與正規化。** 內容會以使用者產生的各種格式送達——JPEG、MP4、30 秒語音訊息、兩小時直播。正規化是將每種模態轉換成模型可以評分的形式。對音訊和影片而言，這代表必須先進行語音轉文字。大部分延遲都發生在這個階段，也有大部分的準確度在此流失，因為後續所有步驟讀取的是轉錄文字，而非音訊。
**第二階段：分類。** 一個或多個模型會依據政策分類體系為正規化後的內容評分——仇恨言論、騷擾、自我傷害、暴力、色情內容、武器、毒品、賭博等——並為每項分類提供信心度分數。優良的分類體系採用階層式架構，因此你可以對新聞片段中的「暴力」和威脅中的「暴力」採取不同處置。
**第三階段：決策。** 分數會送至政策引擎，由引擎套用門檻、內容類型規則、使用者聲譽和司法管轄區規則。這是團隊最常建置不足的一層。單一的全域門檻幾乎從來都不合適：兒童應用程式留言的標準和遊戲論壇留言的標準不同；它們應該是設定中不同的數值，而不是不同的模型。
**第四階段：處置與記錄。** 執行處置並留下稽核軌跡。如果你在 EU 營運，稽核軌跡不可或缺；它也能讓申訴處理更可行。請儲存分數、模型版本、適用門檻及最後採取的行動。
### 為什麼音訊是最難處理的模態
文字審核可以直接取得內容。音訊審核則必須先取得內容，而自動語音辨識層的所有錯誤都會一路傳遞下去。
以下三種失誤模式反覆出現：
**漏掉否定詞和短詞。** 如果「我不會傷害你」中的「不」被漏掉，就會憑空製造出威脅。雜訊音訊中的弱模型，最容易漏掉的正是這些短功能詞。
**實體辨識錯誤。** 在違規檢舉中，姓名、地點和數字承載了大部分意義。模型若把被指名的對象轉錄錯誤，騷擾案例就會變成無法比對的字串。
**說話者混淆。** 在多位說話者的錄音中，如果沒有可靠的說話者分離，審核系統就無法告訴你是誰說了那句話。對於有主持人和來電者的直播，或語音代理對話，這就是整個問題的核心。
實際結果是：音訊審核的準確度受限於轉錄準確度，無論如何調整分類器，都無法提高這個上限。直到事件檢討時才發現這件事的團隊，通常會在那時才恍然大悟。
## 如何大規模衡量審核準確度
這個章節能區分持續改進的團隊，與只發布儀表板並寄望一切順利的團隊。
**停止使用整體準確率。** 在任何實際平台上，大部分內容都沒有問題，因此一個全部核准的模型也能取得 97% 準確率，卻毫無用處。請依政策類別使用精確率和召回率，並分別追蹤。
**根據成本不對稱性設定門檻，而不是依據 F1 分數。** 對於兒童安全內容，假陰性後果嚴重，而假陽性只會耗費審查者 30 秒——因此應大幅偏重召回率。對於政治言論類別，假陽性會造成公關事件——因此應偏重精確率。這些數值各不相同，應放在設定中，並每季審查。
**建立黃金標準資料集，並持續更新。** 數千筆由人工依據實際政策標記的項目，並隨內容組成變化持續更新。沒有這個資料集，你就無法判斷模型更新是否有幫助。有了它，評估只需一小時，而不用花一季爭論。
**將轉錄結果與分類器分開衡量。** 這是幾乎所有人都會略過的音訊專屬步驟。違規內容漏網時，請判斷是語音模型漏掉了詞語，還是分類器漏掉了含義。兩者需要完全不同的修正——改善轉錄設定，或調整門檻與分類體系——若不分開處理，就會花上好幾個月調整錯誤的層。如何評估語音辨識模型中的技巧在此也同樣適用。
**追蹤審查者間的一致性。** 如果兩位人工審查者對佇列中 20% 的案例意見不一，沒有任何模型能針對這組標籤達到 95% 精確率——上限取決於政策的模糊程度，而非模型能力。審查者間一致性偏低，是被回報為模型問題的政策問題。
**留意申訴改判率。** 這是你掌握最明確的實際精確率訊號，因為提出申訴的人最有動機找出誤判。
## 常見問題
### 什麼是 AI 內容審核？
AI 內容審核是運用機器學習模型，自動偵測、分類並處理違反平台政策或法律義務的內容，涵蓋文字、圖片、影片和音訊。與比對禁用詞或雜湊的規則式篩選不同，AI 審核會評估上下文，因此能分辨侮辱詞是用來攻擊他人，還是在新聞報導中被引用。多數正式環境中的系統會將自動分類與人工審查難以判定的案例結合。
### 內容審核是什麼意思？
內容審核是依據一組規則審查使用者生成的內容，並決定如何處理：發布、移除、設定年齡限制、取消營利，或送交人工審查。它涵蓋偵測、分類和處置三項操作，並適用於平台接受的所有模態。目前 AI 在分類步驟中發揮最大作用；而處置步驟則是多數平台最常犯錯的地方，因為單一全域門檻很少能適用於所有內容類型。
### 內容審核的 6 種類型是什麼？
六種類型分別是事前審核（發布前審查）、事後審核（先發布，再立即審查）、檢舉式審核（僅在使用者檢舉時審查）、分散式或社群審核（由可信任的使用者決定）、自動化審核（由模型偵測並執行處置），以及混合式審核（由模型分流，再由人工判斷棘手案例）。多數成熟平台會同時採用多種類型，依不同內容層級和風險程度套用不同方式。
### 語音轉文字 API 能偵測音訊中的髒話和不安全內容嗎？
可以。AssemblyAI 表示，透過其 Guardrails and Speech Understanding API，在同一個轉錄請求中即可回傳內容安全標籤、髒話過濾、涵蓋 50 多種類型的實體偵測、主題分類，以及文字和音訊中的個人識別資訊遮蔽。標籤會附上時間戳記，因此審查者會直接前往重要的 90 秒，而不必檢視 50 分鐘的檔案。同樣的功能也可透過串流 WebSocket 用於即時音訊，進行即時審核。
### 最佳的內容審核 API 是什麼？
這取決於你實際需要涵蓋哪些模態。純文字平台可使用專用的文字審核端點；視覺內容平台需要圖片和影片分類；一般安全平台則會將兩者與政策工具整合。對音訊和影片平台來說，決定因素是供應商是否同時負責轉錄和分類——分類他人提供的轉錄文字會帶來兩個準確度問題，而且無法從頭到尾偵錯漏網案例。
### 如何衡量內容審核是否有效？
請依政策類別追蹤精確率和召回率，而非整體準確率；當大多數內容都符合規範時，整體準確率毫無意義。維護由人工標記、並隨內容組成變化而更新的黃金標準資料集；依各類別中假陽性與假陰性的成本差異設定門檻；並將申訴改判率視為實際精確率的訊號。針對音訊，務必將轉錄結果與分類器分開衡量——因轉錄錯誤而漏掉的違規，需要完全不同的修正方法。
