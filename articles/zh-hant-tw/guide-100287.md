# 什麼是 LLM 路由器？

> 了解 LLM 路由器如何依據成本、延遲、機密性與品質選擇模型，以及路由與閘道和備援機制之間的關係。



> <strong>定義：</strong>LLM 路由器是位於應用程式與多個 AI 模型之間的控制平面層，會根據成本、延遲、品質與機密性，將每個請求送往最合適的模型。它能降低支出、消除對單一供應商的依賴，並提供自動故障切換。

LLM 路由器（也稱為 *AI 閘道*、*模型路由器*或*LLM 仲介*）是位於應用程式與多個模型之間的層。應用程式不必針對單一供應商的 API 撰寫程式，而是呼叫路由器，由它為每個請求挑選最佳模型，並提供統一介面。

- 分析每個請求（任務類型、複雜度、敏感度）
- 選擇最佳模型（簡單任務使用低成本模型，困難任務使用前沿模型）
- 處理供應商之間的負載平衡與故障切換
- 所選模型符合品質要求時，路由可降低成本。

## LLM 路由器與 AI 閘道有什麼差異？

兩者的功能有所重疊。**路由器**著重於逐一請求選擇模型；**AI 閘道**則加入驗證、治理與可觀測性；**仲介**著重於在多個供應商之間提供不受供應商限制的協調服務。穩健的解決方案會涵蓋這三者。

## LLM 路由如何運作？

路由器會依據四項準則評估每個請求：

- **成本** — 簡單任務交給低成本模型，只在必要時使用昂貴模型。
- **延遲** — 時效性要求高的請求交給快速、小型的模型。
- **機密性／保護等級** — 含敏感資料的請求只送往核准的服務與處理地點。
- **品質** — 複雜任務交給前沿模型。

路由方式可以是**靜態**（規則）、**動態**（評分／模型）、**混合式**或**學習式（RL）**。

## LLM 路由能省下多少成本？（證據）

- **RouteLLM**（UC Berkeley/LMSYS，arXiv 2406.18665）：作者報告指出，在 MT Bench 上，相較於每筆請求都使用 GPT-4，成本約低 85%，分數約為 GPT-4 的 95% \[R1\]。
- <strong>AWS Bedrock Intelligent Prompt Routing：</strong>AWS 估計，在同一模型家族的不同模型之間路由，可節省最多 30% 的成本 [\[R2\]](https://aws.amazon.com/bedrock/intelligent-prompt-routing/)。
- <strong>成本差距：</strong>費率因模型與供應商而異。選擇模型時，請比較目前輸入與輸出 token 的費率。


## 不受供應商限制的路由：如何終結供應商鎖定

使用供應商自有的路由器，只會在更高一層被鎖定。**不受供應商限制**的仲介會將不同供應商（OpenAI、Anthropic、Google、Mistral、開放權重模型）抽象化，因此切換模型只需修改設定，不必改動程式碼。這是直接解決 AI 供應商鎖定的方法。

## 符合歐盟主權要求與地端部署的 LLM 路由

路由器可以將含敏感資料的請求限定在歐盟境內或自有環境中執行的核准模型，並在允許的情況下，將涉及公開資料的請求送往成本較低的雲端模型。請依照適用要求，查核各服務如何處理與儲存資料。

## 自建還是採購

總持有成本，以及是否必須內建保護等級與歐盟主權要求，會決定該如何選擇。

## 常見問題

**什麼是 LLM 路由器？**

LLM 路由器是位於應用程式與多個 AI 模型之間的軟體層，會依據成本、延遲、品質與機密性，將每個請求路由至最合適的模型，並提供統一的 API。

**LLM 路由如何運作？**

它會評估每個請求，並使用靜態規則、動態評分或學習式政策選擇模型，將簡單任務交給低成本模型，並將困難任務交給前沿模型。

**LLM 路由器和 AI 閘道是同一回事嗎？**

不完全相同。路由器著重於逐一請求選擇模型；閘道則加入驗證、治理與可觀測性。穩健的平台會結合兩者，並提供不受供應商限制的仲介服務。

**LLM 路由器能省下多少成本？**

RouteLLM 作者報告指出，在 MT Bench 上，相較於每筆請求都使用 GPT-4，成本約低 85%，分數約為 GPT-4 的 95%。AWS 估計，在同一模型家族的不同模型之間路由，可節省最多 30% 的成本。實際節省幅度會因工作負載而異。

**路由會降低回答品質嗎？**

品質取決於任務、模型與路由規則。請用能代表實際工作負載的請求測試規則。

**我可以在地端／歐盟境內執行 LLM 路由器嗎？**

可以，前提是路由器與模型都支援這種部署。請指定哪些服務可處理含敏感資料的請求，並確認適用的資料處理要求。
