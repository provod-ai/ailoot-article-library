# LLM 推論成本：哪些因素會影響成本，以及如何降低成本

> 了解 LLM 推論成本背後的主要因素，以及管理 Token 使用量、模型選擇、上下文與基礎架構的實用方法。



LLM 推論是受過訓練的模型在執行階段執行任務：在昂貴的加速器硬體上，逐一產生 Token，將你的提示轉換成回應。訓練會建立一次模型。推論則會一直執行模型，每次請求都執行，每位使用者都如此。

「一直」是預算的關鍵。訓練是一次性的資本支出，你會在新聞標題中看到它。推論成本則是會隨著成功而擴大的營運支出：更多使用者、更多功能、更多代理程式、更多支出。成功產品累積的推論帳單會超過訓練帳單，而且差距只會越來越大。

計費單位是 Token，約相當於四分之三個英文單字。所有推論定價都可換算為每百萬 Token 的費率，輸入（你的提示與上下文）和輸出（模型產生的內容）分開計價。每個 Token 的成本很低，但用量絕不低。你在推論上花的每一元，都是依照這個計量單位計算出來的。

## LLM 推論的每 Token 成本，實際上代表什麼？

LLM 推論的每 Token 成本不是單一數字。任何模型至少涉及四個數字，而它們之間的差距，正是決定正式環境帳單的關鍵：

### 標準輸入與輸出費率

如上所述，輸出費率約為輸入的 5x。請依各使用情境設定 Token 數上限，並指示模型簡潔作答。比例雖小，但每次呼叫都會發生，而且會一直累積。

### 推理 Token

回答前會先思考的模型，會將思考過程算作輸出費用；輸出是較昂貴的計價類別，而且使用者看不到這些內容。如果用量沒有增加，帳單卻突然變高，請檢查預設設定是否悄悄切換成推理模式。有時候，這樣的推理深度值得付出成本；但很多時候，根本沒人確認過。

4.  **輸出沒有上限。** 冗長的預設設定、未設定的最大 Token 數限制，以及在簡單任務中仍保持啟用的推理模式，都會增加計量中較昂貴的一側。這筆支出不會有人一次核准，因為它是隨著一個個冗長回答逐步產生的；也正因如此，它會在無人監控下持續累積。

## 如何降低 LLM 推論成本？

LLM 成本最佳化可歸納為八種方法，以下依投入心力與節省效果排序：

2.  **同時依據成本、延遲與品質進行路由。** 優秀的路由器會評估這三項指標；只看品質的路由方式會耗盡預算。即使是兩層式路由器，先使用便宜的模型，信心不足時再升級，也能掌握大部分效益，而且工程實作只需一個週末。

4.  **要求輸出簡潔。** 依使用情境設定最大 Token 數上限、指示模型簡潔作答，並避免為客套話支付輸出費率。

8.  **開始最佳化前，先按功能衡量成本。** 這點可能令人不太舒服。若不知道是哪個產品、功能或客戶產生支出，就無法有目標地運用上述七種方法。沒有成本分攤資訊就最佳化 LLM 推論，只是在自信地猜測；而它總是讓人調整看得見的聊天機器人，卻放任背景處理流程消耗 80% 的預算。

## 自行託管能降低推論成本嗎？

**只有在你能讓硬體持續忙碌時才行。** 自行託管會把每 Token 計費改成每小時計費，整個商業效益都取決於使用率。在繁忙的叢集上處理持續、可預測的大量流量，成本會明顯低於 API 費率。若流量不穩定或規模不大，GPU 卻閒置，自行託管每次都會比 API 更貴；你還得額外組建一支維運團隊，聊以安慰。

**接著，誠實地進行效能測試：** 已公開的 LLM 推論基準測試資料，會依照你實際的批次大小和上下文長度，測量每張 GPU 每秒能處理的 Token 數。這就是計畫與希望之間的差別。AI 推論的經濟效益在這裡指向一個平實的答案。如果用量不確定，或工程團隊的投入意願不高，就繼續使用 API，把心力花在上述八種方法上。

## 如何在產品層級追蹤 LLM 推論成本？

先從任何供應商的儀表板都無法回答的問題開始：是哪個功能、團隊或客戶產生這筆支出？這筆支出值得嗎？API 控制台會按金鑰列出總額。但到了星期四，CFO 要求你用數字說明新 AI 功能對利潤率的影響時，總額就派不上用場了。

**要得到答案，需要三個層次。** 依功能和環境標記使用量，讓用量有明確負責人。將不同供應商的資料標準化並整合到同一個檢視畫面，因為多模型架構已是常態，而各家廠商的報表方式都不同。接著將成本分攤到單位經濟效益：每個功能、每位客戶、每筆交易的推論支出，也就是企業實際運作時採用的分母。
