# 保護模型路由：最便宜的路徑何時會挑選防護措施

> 模型路由如何影響成本、安全性與安全控管，以及為何應在每條路由上套用防護措施。






## 模型路由究竟是什麼

模型路由器會為請求選擇模型或供應商。視設計而定，它可能使用固定規則、可用性、請求屬性或分類器。選項可以包括較弱或較強的模型、通用或專用模型、供應商 A 或 B，以及雲端或本機部署。優點與風險取決於系統設計。

以下幾種路由方式有助於理解系統的定位：

- **成本／品質路由** — 在較強與較弱的模型之間分派請求。
- **語意或能力路由** — 將數學問題交給數學專用模型，依照各請求的類別，配對經過相應調校的模型。
- **閘道器路由** — LLM 閘道器或自架代理伺服器透過單一 API 連接多家供應商，並提供故障切換與成本追蹤。
- **模型內部路由** — 混合專家模型（Mixture-of-Experts）中，*模型內部的*路由器會選擇負責處理各個 token 的專家。攻擊是否會轉移到這一層，取決於模型與威脅情境。

當路由使用提示詞內容時，使用者可以影響路由決策的輸入。固定路由或依據中繼資料的路由具有不同的攻擊面。

## 優點

路由能在四個面向發揮作用。系統規模擴大時，這些效益可能讓路由值得考慮。

**成本。** 路由只將部分查詢送往較強、成本較高的模型，因此能降低成本。其經濟效益在於，正式環境中的流量往往包含簡單查詢；若每個查詢都支付頂尖模型的費用，可能不符合成本效益。實際結果取決於工作負載與評估方式；基準測試數據不代表普遍適用的節省保證。

**延遲。** 設計良好的路由器可以很輕量。語意快取也能針對與既有查詢相似的請求，直接回傳已儲存的答案，降低延遲與後端負載。

**品質。** 路由的作用不只是在需要省錢時改用較弱的模型。它也能將每個請求配對到適合的模型，例如將數學問題交給專門調校過的數學模型。相較於只用一個通用模型，路由後的品質可能更高。

**韌性。** 連接多家供應商的閘道器，能在某家供應商限流或服務中斷時進行故障切換，也能提供單一控制平面，統一管理驗證、速率限制、可觀測性與成本追蹤。串流開始前進行透明的故障切換，流程通常很順暢；若串流途中發生故障，仍須由應用程式程式碼處理。

這些優點不代表可以忽略路由風險。

## 路由特有的威脅類型

路由操弄不同於針對模型的提示詞注入。一般的注入攻擊目標是模型輸出；路由操弄則是要影響模型選擇。攻擊者可能試圖左右由哪個模型回答請求，以及採用哪一套防護措施。

在查詢前加上對抗性觸發詞，可能是為了達成以下目標：

**推高成本。** 迫使路由器每次都選擇昂貴的模型，造成預算耗盡風險。這會影響預算與服務可用性。

**劫持品質。** 迫使路由器選擇較弱的模型，暗中降低對手輸出的品質。這種情況可能難以察覺；凡是以輸出品質作為產品價值的地方，都可能因此受到損害。

**繞過安全防護。** 有害請求可能被導向防護較弱的路徑，藉此繞過另一條路徑上的較強檢查。

即使沒有攻擊者，也可能發生故障。某些路由器設計可能容易受到這類影響。以偏好為基礎的路由器可能受類別影響而做出不理想的決策，並在無意間將越獄嘗試導向較弱的模型。即使還沒有人嘗試利用它，這種弱點也可能已經存在。

## 為何這會破壞防護假設

最根本的問題在於結構：某些架構讓安全性*取決於路由輸出*，而非成為*所有路由共同遵守的不變條件*。

成本最佳化器與對手都能推動同一個控制桿。營運者會調整強弱模型之間的分界，以節省成本。攻擊者則可能讓查詢看起來比較不難，試圖使它跨過這條分界。

成本最佳化可能在設計上助長較弱的路由。系統越是為了節省成本而調校，就越可能將流量送入攻擊者想要影響的範圍。

缺少的制衡措施，是「強模型的防護措施能保護整個系統」這項假設。它無法保護被送往弱模型的查詢：由於強模型已不在處理路徑中，其防護措施便在設計上遭到繞過。

單純收緊路由器、拒絕轉往弱模型，可能會削弱成本效益，同時仍讓對手有機會偽造難度。雙方都在推動同一個控制桿。

安全防護的涵蓋範圍可以獨立於分派決策：無論由哪個模型處理，都對每個請求執行防護檢查與內容分類。以嵌入向量為基礎的偵測和自適應閾值調整，都是防護系統採用的方法。架構上的做法，是將檢查放在整個模型群之前，而不是放在路由之後。若所有路徑都正確執行安全檢查，可降低僅透過路由略過檢查的風險；檢查本身仍可能失敗，或透過其他途徑被繞過。另外還有兩項措施可提供幫助：將低得不合理的難度估計視為可疑訊號，並把安全檢查結果回饋至路由閾值，讓系統學習自己在哪些地方受到操控。

## 另一種暴露風險：作為瓶頸的路由器

另一種暴露風險來自路由層本身。視架構與設定而定，閘道器或代理伺服器可能存取傳輸中的提示詞、回應、憑證或工具呼叫。這種存取可能允許讀取、保留或修改資訊，因此應檢查實際權限與資料流。



- 每新增一家供應商，都可能多出一個司法管轄區、一套資料保留政策或一個次級處理者。閘道器可以依照各供應商的資料保留狀況進行路由，因此在傳送敏感資訊前，請先確認相關政策。
- 代管式閘道器可能提供零資料保留路由與 EU 區域鎖定等控制功能。有資料落地要求的團隊，應確認哪些控制適用於其路由所使用的供應商。

依據風險採取相應的緩解措施：在資料送出前移除個人識別資訊，將敏感工作負載路由至自架或本機模型，固定閘道器版本並進行稽核，且將它視為關鍵基礎設施。

## 進行路由時，讓防護措施隨流量同行

模型路由既是成本調節工具，也可能成為攻擊面。節省成本與暴露風險共用同一個控制點。

挑選一項經常使用的路由工作負載，並確認：安全檢查會套用至所有流量，還是只套用至路由器送往較強模型的流量？如果是後者，這就是一處缺口。

問題不在於存在低成本路由，而在於安全性可能變成路由的函數。讓安全性成為所有路由共同遵守的不變條件，節省成本就不必以讓部分流量缺乏防護為代價。
