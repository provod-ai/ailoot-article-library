# Gemini API 工具功能更新：脈絡傳遞、工具組合與 Gemini 3 地圖接地

> 開發者可以在單一 Gemini API 呼叫中，將函式呼叫與 Google 搜尋等內建工具結合，在不同工具呼叫與回合之間傳遞脈絡，並在 Gemini 3 模型中使用 Google 地圖接地功能。



2026 年 3 月 17 日


Google 目前的文件將工具組合標示為 Gemini 3 與 Gemini 4 模型的 preview 功能；正式導入前請確認所選模型是否可用。
## 工具組合帶來哪些改變

[Google 在 2026 年 3 月 17 日的公告](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-api-tooling-updates/)介紹了 Gemini API 的更新：同一個請求可同時傳入 Google 搜尋或 Google 地圖等內建工具，以及應用程式自訂函式。模型可以先取得公開資訊，再依流程需要呼叫應用程式後端，減少開發者在不同協調步驟間手動切換。實際延遲是否改善仍取決於工作流程，應以自己的情境測量。

這種做法適合需要把公開來源與應用程式資料或操作串接的代理流程。請分清 Google 工具提供的內容與自訂函式的回應，並在後端驗證權限及輸入資料。

## 脈絡與呼叫識別碼

多步驟任務中，後續工具可能需要前一個工具的結果。Google 說明的脈絡傳遞會在互動中保留工具呼叫及回應，供後續步驟使用。例如，內建工具取得天氣資訊後，自訂函式可用這些資料執行下一項操作。

`function_call` 步驟中的 `id` 會在 `function_result` 步驟中以 `call_id` 傳回，藉此將呼叫與結果配對。用戶端應保留此關聯，尤其是模型要求多個函式平行執行時。格式詳見 [Google 函式呼叫文件](https://ai.google.dev/gemini-api/docs/function-calling)。

## Gemini 3 的 Google 地圖工具

Google 也宣布 Gemini 3 模型系列支援 Grounding with Google Maps。應用程式可啟用地圖工具，讓回答參考空間資料、當地商家、通勤時間及地點資訊。當位置會影響結果時，這項能力便有用，例如尋找附近服務。資料涵蓋範圍與時效性取決於可用結果及設定；模型回答不能取代獨立查證。

## 選擇 API 與後續檢查

Google 表示這些功能也支援 generateContent API，並建議此類工作流程使用 Interactions API，以運用伺服器端狀態管理和統一的互動追蹤。選擇前請查看[工具組合文件](https://ai.google.dev/gemini-api/docs/tool-combination)、[Grounding with Google Maps](https://ai.google.dev/gemini-api/docs/maps-grounding)及 [Interactions API](https://ai.google.dev/gemini-api/docs/interactions)。接著用自己的案例測量呼叫次數、延遲和錯誤處理方式。

這項更新讓多工具流程更容易編排，但仍須設計存取控制、處理失敗的工具呼叫，並進行端對端測試。
