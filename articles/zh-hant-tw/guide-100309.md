# Claude API 初學者入門：實用開始指南

> Claude API 初學者指南，涵蓋設定、第一個請求、模型選擇、核心功能與正式環境實務。



開發者進行第一次 Claude API 呼叫所需的內容：金鑰、Messages API、模型選擇，以及從第一次請求走向正式環境的核心概念。

## Claude API 是什麼

Claude API 是 Anthropic 的開發者平台。透過 Messages API，它可程式化存取 Claude 模型，並支援系統提示、工具使用、串流、視覺輸入與結構化輸出。

Messages API 是無狀態 HTTP 端點。你傳送使用者和助理訊息清單、模型 ID 與 token 上限，Claude 就會傳回結構化回應。其他支援端點包括批次、檔案和 token 計數。

- **無狀態：** API 不會保留記憶。每次呼叫都要重新傳送對話記錄。
- **選擇模型：** 更換模型通常只需更改模型 ID。
- **SDK：** 官方 Python（anthropic）和 TypeScript（@anthropic-ai/sdk）程式庫使用各自對應的請求格式。

了解這種架構，有助於避免初學者常犯的錯誤：以為 API 會記得先前的請求。

## 步驟 1：取得金鑰並設定 Console

前往 **console.anthropic.com**，建立帳戶或團隊組織，再到設定區產生 API 金鑰。請像保護密碼一樣保管金鑰：將它存放在環境變數中，絕不要放進原始碼管理。

直接發送 HTTP 請求時，需使用 **x-api-key** 標頭與 **anthropic-version** 標頭。SDK 會自動讀取環境中的 **ANTHROPIC_API_KEY**，因此大多數程式碼不會直接處理金鑰。

- 為開發、測試與正式環境建立不同的金鑰。
- 使用工作區隔離團隊專案與支出。
- 在向更多團隊成員提供金鑰前，先於 Console 設定使用上限。

## 步驟 2：進行第一次 Messages API 呼叫

使用 **pip install anthropic** 安裝 SDK，匯出金鑰後執行：

```
import anthropic

client = anthropic.Anthropic()
msg = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Explain REST in one paragraph."}],
)
for block in msg.content:
    if block.type == "text":
        print(block.text)
```

必填參數有三個：**model**、輸出上限 **max_tokens**，以及 **messages**。回應包含內容區塊清單。工具使用與思考可能產生其他區塊類型，因此不要假設所有區塊都是純文字；請逐一檢查區塊型別。**usage** 物件會回報輸入和輸出 token，可作為成本追蹤資料。

## 步驟 3：選擇模型

以下是 Anthropic 目前的 Claude 模型及其 API ID。

- **Claude Haiku 5.5**（**claude-haiku-5-5**）— 被描述為快速、低成本，適合分類和大量簡單任務。
- **Claude Sonnet 5.5**（**claude-sonnet-5-5**）— 是適合正式環境的均衡選擇，也適用於程式開發。
- **Claude Opus 5.5**（**claude-opus-5-5**）— 被描述為適合複雜推理和長時間代理任務。
- **Claude Fable 5.2**（**claude-fable-5-2**）— 被描述為處理高難度推理任務的旗艦模型。

先從 Opus 5.5 開始。在速度與品質之間需要取得平衡時，試用 Sonnet 5.5。大量簡單任務可試用 Haiku 5.5，複雜推理則可試用 Fable 5.2。最新費率請參閱 Anthropic 價格頁面。

## 接下來要學的五個概念

第一次請求成功後，下列功能可支援許多應用需求：

- **系統提示：** 頂層 **system** 參數，用來設定角色、語氣和規則，與使用者訊息分開。
- **多輪對話：** 將每次助理回覆附加到 messages 陣列並重新傳送；第一則訊息必須是使用者回合。
- **串流：** 伺服器傳送事件會在 token 產生時逐一傳送，對聊天介面和長輸出很有幫助。
- **視覺輸入：** 將圖片以 base64 或 URL 內容區塊與文字一起傳入。
- **工具使用：** 以 JSON 結構描述定義函式；Claude 可決定何時呼叫，程式碼則負責執行函式並傳回結果。

若成本很重要，可考慮 **提示快取** 和 **批次處理**；若下游程式需要解析回應，則可使用 **結構化輸出**。

## 從教學範例邁向正式環境

要將可運作的腳本整合到正式環境，需要遵循工程紀律：

- **錯誤處理：** 分別處理速率限制（429）和伺服器錯誤。來源指出 SDK 會自動以退避機制重試；請查看相關 SDK 文件確認目前行為。
- **成本可視性：** 將每次回應的 **usage** 記錄到指標系統。
- **提示版本管理：** 像管理程式碼一樣檢視與管理提示版本，並使用小型評估資料集測試。
- **固定模型版本：** 從設定中引用模型 ID，讓升級經過計畫和測試。

### 重點整理

- Messages API 無狀態；每次呼叫都要重新傳送對話記錄。
- 直接 HTTP 驗證使用 x-api-key 標頭；SDK 可從環境變數讀取 ANTHROPIC_API_KEY。
- 必填請求參數是 model、max_tokens 和 messages。
- 先從 Opus 5.5 開始，再用自己的資料比較其他選項。
- 系統提示、串流、視覺輸入、工具使用和多輪歷史記錄可支援許多應用模式。
- 記錄 token 使用量，以追蹤成本並規劃容量。

## 常見問題

### 使用 Claude API 需要懂機器學習嗎？

不需要。Claude API 是 REST API，並提供官方 Python 和 TypeScript SDK。只要能呼叫 HTTP 端點並解析 JSON，就能使用 Claude 開發。提示設計、錯誤處理和成本管理是有用的工程技能；開始第一次 API 呼叫不需要機器學習理論。

### 初學者應該從哪個 Claude 模型開始？

Anthropic 建議大多數工作從 Claude Opus 5.5（API ID `claude-opus-5-5`）開始。等提示詞穩定後，再用自己的資料比較其他模型。

### Claude API 會記得先前的對話嗎？

不會。Messages API 無狀態。你的應用程式負責儲存對話，並在每次請求時重新傳送完整訊息記錄。這讓你能控制上下文、刪減或摘要較早的回合，也能搭配 提示快取 使用。
