# 設計 AI 代理工具：Claude Code 工作流程的經驗

> 定義及測試 AI 代理工具的實用指南，並以程式開發工作流程為例。



AI 代理需要的不只是好模型，還需要能在任務範圍內選擇、理解和使用的工具。本指南以程式開發工作流程為實例，說明如何設計這些介面。

## 從可觀察的工作開始

決定要提供哪些工具之前，先描述代理應完成什麼。對程式庫相關問題而言，任務可能是找出設定在哪裡被讀取，並指出相關檔案。適當的工具組可以讓代理列出檔案、搜尋文字並讀取選定檔案；回答這個問題不需要部署權限。

記錄預期結果和不在範圍內的動作。當工具的輸入與輸出能協助代理作出下一個決策，且應用程式能檢查動作是否獲准時，該工具才有用。

## 為每個工具訂立清楚的契約

工具說明應指出其功能、必要輸入和結果格式。用途相近的工具應使用容易區分的名稱與參數說明。如果操作有重要限制，也要說明：例如搜尋工具可能回傳數量有限的符合路徑，而非所有檔案的內容。

文字搜尋工具的示例請求可以包含查詢和目錄，結果則可包含路徑與符合的行號。應用程式應驗證目錄，並明確處理路徑不存在或搜尋失敗的情況。請求格式正確並不能證明找到的答案正確。

## 平衡彈性與控制

通用命令列可以支援許多任務，但也開放廣泛的操作。範圍較窄的工具可以讓常見操作更容易理解，並限制其執行的動作。適當選擇取決於任務、環境與可用權限；工具更多不會自動帶來更好的結果。

初始工具組應小到容易查找。當觀察到的失敗或重複工作足以說明需求時，再加入專用工具。如果工具能修改資料或聯繫外部服務，請在說明中明示這些影響，並由應用程式強制執行相關權限。

## 在適當時機詢問缺少的資訊

代理不應自行編造缺少的決策。如果任務確實依賴它無法找到的資訊，可以用結構化問題列出相關選項並解釋後果。等待回答時，工作流程可以繼續執行已就緒的獨立工作。

問題應具體。例如，報告需要但未提供日期範圍時，就詢問日期範圍，而不是要求使用者重述整項任務。提問不能取代檢查既有上下文。

## 一起測試工具與代理

建立一小組具代表性的任務：一般請求、模糊輸入、無法取得的檔案，以及嘗試在預定範圍外使用工具的情況。檢查選用了哪個工具、傳入的參數、回傳結果及最終回答。API 呼叫成功仍可能回傳不完整資料，因此應根據原始證據核對回答。

調查反覆出現的失敗時，每次只修改介面的一個部分。記錄工具說明版本並重複相關測試。對有副作用的動作，重試前先核對不確定的結果；重試可能再次執行已成功的動作。

## 將這些想法應用於程式開發流程

Claude Code 支援結合工具與可重複使用指示的工作流程。API 契約請參閱最新的 [Claude 工具使用文件](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview)，可重複使用指示的組織方式則請參閱 [Claude Code 技能文件](https://code.claude.com/docs/en/skills)。可用性及確切介面可能改變，因此請查閱所用版本的文件。

相同的設計問題適用於各種代理框架：任務需要什麼、代理能觀察什麼、每個工具能改變什麼，以及如何驗證結果？
