# OpenAI Moderation API 定價：免費、速率限制與替代方案

> OpenAI 的內容審核模型免費。了解定價、各使用層級的速率限制、Python 範例，以及何時選擇與 OpenAI 相容的替代方案更合適。




OpenAI 的 Moderation 端點對 OpenAI API 使用者免費。選擇正式環境的工作流程時，請確認支援的輸入類型與類別、帳戶的速率限制，以及這個端點如何融入你的審查流程。

本指南將官方定價說明與實務工程決策分開討論。

## 摘要

- 根據 OpenAI 說明中心，**OpenAI 的 Moderation 端點對 OpenAI API 使用者免費**。
- 根據 OpenAI 官方模型頁面，OpenAI 的 `omni-moderation-latest` 模型專為偵測有害內容而設計，並接受文字與圖片作為輸入。
- 免費定價不會消除工作流程成本，例如記錄、審查佇列、政策對應、重試、備援行為，以及應用程式專屬的決策。
- 如果你已直接使用 OpenAI，且你的內容審核工作流程符合其類別和回應格式，就選擇 OpenAI 的免費端點。
- 如果你已使用 EvoLink，並想在同一套工作流程中進行多模態檢查、取得風險摘要及採用按次計費，可考慮 EvoLink Moderation 1.0。

## OpenAI Moderation API 免費嗎？

是。OpenAI 官方說明中心指出，Moderation 端點對 OpenAI API 使用者免費，而且使用此工具不計入每月使用量上限。

來源：[OpenAI 說明中心：Moderation 端點是否免費使用？](https://help.openai.com/en/articles/4936833-is-the-moderation-endpoint-free-to-use)

這是定價方面的答案。接下來要考慮的是實際運作：

**免費的內容審核端點足以支援你的正式環境工作流程嗎？**

對於原型、內部工具和以文字為主的簡單內容審核，它可能足以勝任。對於處理使用者生成內容、圖片上傳、AI 代理程式或審查佇列的應用程式來說，API 呼叫只是系統的一部分。

## OpenAI 內容審核涵蓋哪些範圍？

OpenAI 將 `omni-moderation-latest` 文件化為一種內容審核模型，旨在識別文字和圖片中可能有害的內容。官方模型頁面將其描述為 OpenAI 能力最強的內容審核模型，並列出對文字輸入／輸出及圖片輸入的支援。來源：[OpenAI 的 omni-moderation-latest 模型頁面](https://platform.openai.com/docs/models/omni-moderation-latest) OpenAI 的內容審核指南也說明了內容分類類別，並指出部分類別僅支援文字。如果你只將圖片傳送給 `omni-moderation-latest`，不支援圖片輸入的類別會回傳 0 分。來源：[OpenAI 內容審核指南](https://developers.openai.com/api/docs/guides/moderation)

這表示團隊在假設每個文字類別都能直接對應至圖片審核之前，應仔細閱讀類別表。

## 真正的成本在於工作流程，而不只是 API 定價

Moderation 端點可能免費，但正式環境的內容審核系統仍需決定：

- 在何時執行檢查：模型呼叫前、模型回應後，或兩者皆執行
- 如何將類別對應至允許、審查或封鎖的決策
- 如何記錄內容審核結果，同時避免不必要地儲存敏感內容
- 如何處理誤判和申訴
- 如何將圖片上傳與文字輸入分開審核
- 如何監控延遲、錯誤和速率限制
- 如何在產品各介面維持一致的政策行為

這些都是工程與營運成本。它們不會出現在定價頁面上，卻決定了內容審核層是否真的易於維護。

典型的工作流程會先檢查提示詞再送給模型，並在交付之前檢查模型輸出。將無法判定的結果送交審查，只保留必要的決策紀錄，並規劃重試和申訴流程。

## OpenAI 的免費端點適用時機

在以下情況，OpenAI 的免費 Moderation 端點通常是很好的首選：

- 你已直接使用 OpenAI
- 你的應用程式主要以文字為主
- 你只需要 OpenAI 文件記載的內容審核類別
- 你可以自行建置審查和升級處理流程
- 你的團隊願意負責解析回應、設定閾值和管理記錄

在這種情況下，很難找到不選擇免費端點的理由。先從這裡開始，使用真實內容進行測試，並在將正式流量導入之前，衡量誤判和漏判的情況。

## 適合採用與 OpenAI 相容的替代方案時機

EvoLink Moderation 1.0 是一項付費替代方案，提供與 OpenAI 相容的 `/v1/moderations` 路徑。EvoLink 每次請求最多接受一張圖片。

- 透過單一端點執行純文字、純圖片，以及文字加圖片的檢查
- 13 種有害類別，並提供各類別的分數
- 包含 `risk_level`、`flagged`、`violations`、`max_score` 和 `max_category` 的 `evolink_summary` 物件
- 每次呼叫採固定價格，而非依 token 數計算
- 回應格式更容易對應至允許、審查或封鎖的邏輯

## 如何使用 Python 呼叫 OpenAI Moderation API

如果你已使用 OpenAI SDK，基本的文字審核呼叫如下：

```
from openai import OpenAI

client = OpenAI()

response = client.moderations.create(
    model="omni-moderation-latest",
    input="user text here"
)

print(response.results[0].flagged)
print(response.results[0].categories)
```

使用 EvoLink 時，請將 `EVOLINK_API_KEY` 設為你的 EvoLink API 金鑰，並將 `EVOLINK_BASE_URL` 設為 EvoLink API 設定中以 `/v1` 結尾的 HTTPS API 基底網址。回應另含 `evolink_summary` 物件。

```python
import os

from openai import OpenAI

# EVOLINK_API_KEY=YOUR_EVOLINK_API_KEY
client = OpenAI(
    api_key=os.environ["EVOLINK_API_KEY"],
    base_url=os.environ["EVOLINK_BASE_URL"],
)

response = client.moderations.create(
    model="evolink-moderation-1.0",
    input=[{"type": "text", "text": "user text here"}],
)

summary = response.model_extra["evolink_summary"]
print(summary["risk_level"])
print(summary["violations"])
```

## OpenAI 與 EvoLink 的定價和工作流程比較

| 比較項目 | OpenAI Moderation API | EvoLink Moderation 1.0 |
|----|----|----|
| 計費方式 | 對 OpenAI API 使用者免費 | 每次呼叫收取固定費用 |
| 主要端點格式 | `/v1/moderations` | 與 OpenAI 相容的 `/v1/moderations` |
| 文字審核 | 支援 | 支援 |

## 實務建議

如果你的應用程式已採用 OpenAI 原生架構，而且你的內容審核政策能直接對應至其文件記載的類別，請使用 OpenAI 的免費 Moderation 端點。

如果你的團隊已使用 EvoLink，請評估每次呼叫的成本，並將 `evolink_summary.risk_level` 作為應用程式判定允許、審查或封鎖的依據之一。

如果你的應用程式有自訂政策需求，需要品牌規範、人工審查、申訴或任何單一內容審核 API 無法涵蓋的合規流程，請使用多層式內容審核系統。

## 常見問題

### OpenAI Moderation API 免費嗎？

是。OpenAI 說明中心指出，Moderation 端點對 OpenAI API 使用者免費，而且不計入每月使用量上限。

### OpenAI 內容審核支援圖片嗎？

是，根據 OpenAI 官方模型頁面，`omni-moderation-latest` 接受圖片作為輸入。不過，OpenAI 的內容審核指南指出，部分類別僅支援文字，因此團隊在依賴純圖片審核之前，應先確認各類別支援的輸入類型。

### EvoLink Moderation 比 OpenAI Moderation 便宜嗎？

OpenAI 的 Moderation 端點對 OpenAI API 使用者免費。EvoLink 每次呼叫收取固定費用。請比較完整工作流程的成本，包括審查與維護。

### 可以用 EvoLink 取代 OpenAI Moderation API 嗎？

可以。請使用你的 EvoLink API 金鑰和 `evolink-moderation-1.0` 模型，透過 EvoLink 提供且與 OpenAI 相容的 `/v1/moderations` 路徑發出請求。請調整回應處理邏輯，以處理 EvoLink 另外提供的 `evolink_summary` 物件。

### 我應該審核提示、輸出，還是兩者都審核？

在正式環境的 AI 應用程式中，許多團隊會同時審核輸入和輸出。輸入審核可在不安全的請求送達模型之前加以攔截。輸出審核則可在不安全的生成回應送達使用者之前將其偵測出來。

### omni-moderation-latest 是什麼？

這是 OpenAI 用來審核文字和圖片的模型。請讀取 `results` 中的 `flagged`、`categories` 和 `category_scores`，並套用你自己的內容審核政策。

### OpenAI Moderation API 的速率限制是多少？

免費使用指的是計費方式。請求數和 token 數仍受限制。[模型參考文件](https://developers.openai.com/api/docs/models/omni-moderation-latest)中的 RPM 指每分鐘請求數，RPD（若有列出）指每日請求數，TPM 指每分鐘 token 數。

OpenAI Moderation API 的速率限制會因帳戶層級而異，也可能隨時間變動。規劃正式環境的處理量之前，請查看 [OpenAI 速率限制文件](https://platform.openai.com/docs/guides/rate-limits)和帳戶的[使用量上限頁面](https://platform.openai.com/settings/organization/limits)。

### 如何使用 Python 呼叫 OpenAI Moderation API？

安裝 `openai` 套件，設定 `OPENAI_API_KEY`，然後呼叫 `client.moderations.create()`，指定 `omni-moderation-latest` 模型並傳入要審核的文字。若要審核圖片，請依照下方 OpenAI API 參考文件的範例，在 `input` 中傳入物件陣列。每個圖片項目都要指定 `type: "image_url"`，並在 `image_url` 物件中放入 `url`。
