說明閘道、路由、快取與模型服務如何互動，以及請求情境如何在這些層之間傳遞。

請求情境可以經由閘道和路由器傳遞至模型服務。這個情境會將模型選擇、快取重用與執行，連結到呼叫端的身分及每次嘗試的成本。忽略快取狀態的路由器，可能會抵銷相鄰層所節省的成本。

共用情境需要投入整合工作，而會讀取快取狀態的路由器也較難替換。將情境隨請求一併傳送，同時讓產品彼此獨立，團隊就能在另一家供應商的執行環境上使用閘道與路由器。路由器接著會根據該供應商提供的資訊做決策。

## 較便宜的路由可能花費更多

以一個說明用的文件擷取服務為例：每次請求都有一段很長的固定指示，以及一份簡短文件。前綴快取和路由看起來都很有吸引力，但兩者可能互相抵銷效益。快取的前綴是由單一模型計算出的鍵值狀態，因此，路由到另一個模型的請求會從頭讀取指示。

Anthropic 公布的五分鐘快取價格是：寫入費用為基本輸入價格的 1.25 倍，讀取費用為 0.1 倍，但各模型可能有例外（[公告](https://www.anthropic.com/news/prompt-caching)、[文件](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)）。相較於這個暖快取，未快取的替代方案必須將輸入價格降到現行模型的十分之一以下，才能在共用前綴上勝出。快取部分的一次寫入和一次命中，成本相當於 1.35 次輸入處理；不使用快取則是兩次。若後續請求都沒有讀取某次寫入，該次寫入的成本就是 1.25。

比較牌價的路由器可能會看到某個模型的輸入價格只有一半，於是切換過去，卻為前綴付出至少五倍的費用。明確宣告的路由規則會指出哪些模型可以互相替代；共用情境則能顯示每次替代的成本。

## 重用答案需要呼叫端的身分

重用必須遵守模型、提示、結構描述和新鮮度需求。

</figure>

答案快取會傳回已儲存的輸出；語意快取還會判斷兩個不同請求是否適合共用同一個答案。[GPTCache](https://github.com/zilliztech/GPTCache) 會根據嵌入相似度判斷命中，而其 README 警告「快取命中時可能出現誤判」。

在資料擷取中，誤判可能會傳回錯誤的帳戶號碼：同一供應商範本的兩張發票，在嵌入空間中可能彼此接近，快取便可能將第一張發票的帳戶號碼交給第二張發票。沒有應用程式身分資訊的語意快取可能造成正確性錯誤，而其命中率儀表板卻會把每個錯誤答案都算成節省。

Anthropic 會隔離不同組織之間的提示快取，並在自家 API 上按工作區隔離；不過，前綴快取不會交還已儲存的答案。答案快取至少需要相同的隔離界線。應用程式可以宣告任務是否允許重用相似輸入的結果，也可以將呼叫端、該呼叫端可讀取的資料，以及任務版本納入重用鍵值。

資料擷取可以採用完全相符時才重用，或完全不重用；遇到未知鍵值時則重新計算。這項規則會降低命中率，也會讓原本可由較寬鬆快取省下的工作仍需付費。預設規則可能過於嚴格：對大型公開常見問題集而言，遇到未知鍵值就重新計算的成本，可能高於它所避免的罕見錯誤答案成本。

## 先追查故障，再選擇修正方式

假設較便宜的模型傳回無效欄位，再由較大型的模型修正，於是該文件的費用和延遲都增加了。成本可以按照符合所需延遲的正確擷取結果來計算；第一次呼叫的 token 價格只是其中一項因素。

柏克萊對複合式 AI 系統的分析主張，應整體最佳化彼此互動的元件。追蹤資料必須區分模型故障、過時的重用、緩慢的工具或錯誤的路由，因為每一種情況都指向不同層的修正方式。掌控執行流程有助於找出成本來源，而較快的執行環境也可能把浪費轉移到周邊決策中。將追蹤資料連結到正式環境流量的評估，可以驗證變更是否改善任務，包括復原路徑。

操作人員可以利用追蹤資料來修改發生故障的層。將請求紀錄、評估案例和部署選擇保留在客戶的應用程式中，能讓改善建立在該應用程式本身累積的經驗上。
