# 推出 Gemini API 中的代管代理

> Gemini API 代管代理實用指南：選擇任務、審查結果，並規劃成本、隱私及失敗處理。



對語言模型的請求通常會產生一個回答；代理也能為了達成結果執行中間步驟。例如，它可以檢查資料、撰寫並執行程式碼，然後回傳報告。Google 的代管代理透過 Gemini API 為這類任務提供託管工作環境。這項功能目前為預覽版，因此在納入正式工作流程前，請先確認最新文件及可用性。

本指南說明如何選擇第一項任務、評估結果，以及規劃使用代管代理時的操作工作。Google 的 [Gemini API 文件](https://ai.google.dev/gemini-api/docs)提供最新請求範例及支援的代理識別碼。

## 供應商管理哪些部分？

在代管代理模式中，供應商負責執行代理環境並提供代理可用的工具。Google 描述了一個遠端沙箱，其 Antigravity 代理可在其中處理檔案、執行程式碼並使用網路。您的應用程式仍須定義目標、提供適當輸入，並判斷回傳結果是否可接受。

當任務需要多個步驟和中間工作空間時，託管環境很有用。它不能取代應用程式的授權、審查或資料處理決策。依賴這些功能之前，請先確認您的專案和版本可使用哪些工具與環境設定。

## 選擇範圍明確的第一項任務

從不必相信代理的解釋也能驗證結果的任務開始。小型 CSV 摘要就是一個好例子：提供不含敏感資訊的樣本、要求產生總計表，並指定輸出格式。獨立計算幾個總計，與結果比較。

實用的任務描述應包含：

- 輸入資料及每個欄位的意義。
- 預期輸出，例如摘要與 CSV 檔案。
- 缺漏或無效值的處理規則。
- 代理可使用的資料和工具範圍。
- 接收者使用結果前可執行的檢查。

例如：「依月份和幣別彙整這份銷售 CSV 樣本。不要合併不同幣別。將缺少日期的資料列另行列出，並提供每個總計所使用的計算。」初次測試時，避免要求代理傳送訊息、修改正式環境資料或執行其他外部動作。

## 執行並檢查互動

使用 Google 的[入門指南](https://ai.google.dev/gemini-api/docs/get-started)設定 SDK 和憑證，再依照其中的代管代理範例操作。範例提供代理識別碼、輸入和遠端環境。請使用 Google 目前文件列出的識別碼，不要假設舊的預覽版識別碼仍然可用。

不要只檢查最後一段。請檢查回傳狀態、輸出以及您打算使用的任何檔案。資料任務應將數字與來源比較；產生的指令碼則應在受控環境中審查並測試。如果任務依賴網路資訊，請開啟引用來源並確認其支持相關主張。即使結果表達流暢，也可能包含錯誤。

如果工作跨多次互動延續，請遵循 Google 文件所述的環境與互動生命週期。將相關識別碼保存在應用程式的任務紀錄中，並明確處理到期或失敗；不要假設工作空間會無限期保留。

## 為自訂代理提供清楚指示

Google 也記錄了向代管代理提供自訂指示、技能和資料的方法。請用這些功能描述工作和輸出要求，不要在文件中放入機密。對報告任務而言，指示可以定義資料分組方式、如何標示不確定性，以及無法完成計算時該怎麼做。

將指示檔案納入版本控制，像審查應用程式程式碼一樣審查變更。以少量具代表性的輸入測試新版本，包括空檔案、非預期值和超出預定範圍的請求。記錄每次評估使用的版本與輸入，以便調查輸出變化。

## 規劃成本、隱私與失敗處理

多步驟代理在回傳結果前可能多次呼叫模型或使用工具。試用前請查看 Google 的[價格頁面](https://ai.google.dev/gemini-api/docs/pricing)及專案限制；費用與預覽版條款可能改變。測量代表性任務的用量，並在應用程式層級設定符合工作負載的預算。

只傳送工作流程獲准處理的資料。將擷取的網頁和上傳的檔案視為不受信任的輸入，並在沙箱外執行產生的程式碼之前加以審查。事先定義任務逾時、工具失敗或代理回傳不完整結果時的處理方式。重試有副作用的任務可能再次造成相同效果，因此再次嘗試前應先核對原始操作。

## 何時應使用代管代理？

對範圍明確的研究、分析或檔案產生任務，如果多個工具步驟有幫助，且人員或自動檢查能驗證輸出，就值得評估代管代理。若只是單一、可預測的轉換，直接請求模型或使用一般應用程式程式碼可能更容易維運。請依照您的使用情境，比較各方式的品質、延遲、成本及所需審查量。
