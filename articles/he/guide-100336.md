# הצגת סוכנים מנוהלים ב-Gemini API

> מדריך מעשי לסוכנים מנוהלים ב-Gemini API: בחירת משימות, בדיקת תוצאות ותכנון עלויות, פרטיות וכשלים.



בקשה למודל שפה מפיקה בדרך כלל תשובה; סוכן יכול גם לבצע שלבי ביניים בדרך לתוצאה. למשל, הוא עשוי לבדוק נתונים, לכתוב קוד, להריץ אותו ולהחזיר דוח. הסוכנים המנוהלים של Google מספקים סביבת עבודה מתארחת למשימות כאלה דרך Gemini API. התכונה נמצאת בתצוגה מקדימה, לכן בדקו את התיעוד העדכני ואת הזמינות לפני שילובה בתהליך ייצור.

מדריך זה מסביר כיצד לבחור משימה ראשונה, להעריך את התוצאה ולתכנן את העבודה התפעולית סביב סוכן מנוהל. [תיעוד Gemini API של Google](https://ai.google.dev/gemini-api/docs) כולל דוגמאות בקשה ומזהי סוכנים נתמכים ועדכניים.

## מה הספק מנהל?

בגישת הסוכן המנוהל, הספק מפעיל את סביבת הסוכן ומספק לו כלים. Google מתארת סביבת sandbox מרוחקת שבה סוכן Antigravity יכול לעבוד עם קבצים, להריץ קוד ולהשתמש ברשת. האפליקציה שלכם עדיין צריכה להגדיר את המטרה, לספק קלט מתאים ולהחליט אם התוצאה המוחזרת קבילה.

סביבה מתארחת שימושית כשמשימה דורשת כמה שלבים וסביבת עבודה ביניים. היא אינה מחליפה החלטות של האפליקציה בנוגע להרשאות, לבדיקה או לטיפול בנתונים. בדקו אילו כלים והגדרות סביבה זמינים לפרויקט ולגרסה שלכם לפני שתסתמכו עליהם.

## בחרו משימה ראשונה מוגדרת

התחילו במשימה שאפשר לבדוק את תוצאתה בלי להסתמך על הסבר הסוכן. סיכום CSV קטן הוא דוגמה טובה: ספקו מדגם שאינו רגיש, בקשו טבלת סיכומים והגדירו את פורמט הפלט. חשבו כמה סכומים באופן עצמאי והשוו אותם לתוצאה.

תיאור משימה שימושי כולל:

- את הקלט ואת משמעות כל שדה.
- את הפלט הרצוי, כגון סיכום וקובץ CSV.
- כללים לערכים חסרים או לא תקינים.
- גבול לנתונים ולכלים שהסוכן רשאי להשתמש בהם.
- בדיקות שהמקבל יכול לבצע לפני השימוש בתוצאה.

למשל: „סכם את מדגם המכירות הזה ב-CSV לפי חודש ומטבע. אל תאחד מטבעות. הצג בנפרד שורות שחסר בהן תאריך וספק את החישובים ששימשו לכל סיכום.” בבדיקה הראשונה הימנעו מבקשות לשלוח הודעות, לשנות נתוני ייצור או לבצע פעולות חיצוניות אחרות.

## הריצו אינטראקציה ובדקו אותה

השתמשו ב[מדריך ההתחלה של Google](https://ai.google.dev/gemini-api/docs/get-started) כדי להגדיר את ה-SDK ואת פרטי האימות, ואז פעלו לפי דוגמת הסוכן המנוהל. הדוגמה מספקת מזהה סוכן, קלט וסביבה מרוחקת. השתמשו במזהה המתועד כעת ב-Google במקום להניח שמזהה ישן מתצוגה מקדימה עדיין זמין.

בדקו יותר מהפסקה האחרונה. בדקו את המצב שהוחזר, את הפלט ואת כל הקבצים שאתם מתכוונים להשתמש בהם. במשימת נתונים השוו את המספרים למקור; אם נוצר סקריפט, בדקו והריצו אותו בסביבה מבוקרת. אם המשימה תלויה במידע מהרשת, פתחו את המקורות המצוטטים ובדקו שהם תומכים בטענות. גם תוצאה מלוטשת עשויה להכיל שגיאה.

אם אתם ממשיכים עבודה בין אינטראקציות, פעלו לפי מחזור החיים של הסביבה והאינטראקציה כפי שמתועד ב-Google. שמרו את המזהים הרלוונטיים ברשומת המשימה באפליקציה וטפלו במפורש בתפוגה או בכשל; אל תניחו שסביבת העבודה תישמר ללא הגבלת זמן.

## ספקו לסוכן מותאם אישית הוראות ברורות

Google מתעדת גם דרכים לספק הוראות מותאמות, מיומנויות ונתונים לסוכנים מנוהלים. השתמשו בהן לתיאור המשימה ודרישות הפלט, ולא להטמעת סודות במסמך. במשימת דיווח ההוראות יכולות להגדיר כיצד לקבץ נתונים, לסמן אי-ודאות ומה לעשות כשלא ניתן להשלים חישוב.

שמרו קובצי הוראות בבקרת גרסאות ובדקו שינויים כמו קוד אפליקציה. בדקו גרסה חדשה על קבוצה קטנה של קלטים מייצגים, כולל קבצים ריקים, ערכים לא צפויים ובקשה מחוץ לתחום המיועד. תעדו את הגרסה והקלט ששימשו לכל הערכה כדי שניתן יהיה לחקור שינוי בפלט.

## תכננו עלות, פרטיות וכשל

סוכן רב-שלבי עשוי לבצע כמה קריאות למודל או להשתמש בכלים לפני החזרת תוצאה. עיינו ב[דף התמחור של Google](https://ai.google.dev/gemini-api/docs/pricing) ובמגבלות הפרויקט לפני ניסיון; החיובים ותנאי התצוגה המקדימה עשויים להשתנות. מדדו שימוש במשימות מייצגות והגדירו תקציב ברמת האפליקציה המתאים לעומס העבודה.

שלחו רק נתונים שמותר לתהליך לעבד. התייחסו לדפים שאוחזרו ולקבצים שהועלו כקלט לא מהימן, ובדקו קוד שנוצר לפני הרצתו מחוץ ל-sandbox. הגדירו מה קורה כאשר משימה חורגת מהזמן, כלי נכשל או הסוכן מחזיר תוצאה חלקית. ניסיון חוזר במשימה עם תופעות לוואי עלול לחזור עליהן, לכן בררו את מצב הפעולה המקורית לפני ניסיון נוסף.

## מתי להשתמש בסוכן מנוהל?

כדאי לבחון סוכן מנוהל למשימות מחקר, ניתוח או יצירת קבצים מוגדרות, כאשר כמה שלבי כלים מועילים ואדם או בדיקה אוטומטית יכולים לאמת את הפלט. בקשה ישירה למודל או קוד אפליקציה רגיל עשויים להיות קלים יותר לתפעול בהמרה יחידה וצפויה. השוו את הגישות לפי איכות, זמן תגובה, עלות והיקף הבדיקה הנדרש למקרה שלכם.

תהליך הסוכן המנוהל שתואר לעיל משתמש ב-Gemini API של Google. Ailoot מציעה API משלה לגישה למודלי AI.
