# Claude API למתחילים: מדריך מעשי לתחילת העבודה

> מדריך Claude API למתחילים: הגדרה, בקשה ראשונה, בחירת מודל, תכונות מרכזיות ושיטות עבודה לייצור.



כל מה שמפתח צריך כדי לבצע קריאת Claude API ראשונה: מפתחות, Messages API, בחירת מודל ומושגי יסוד למעבר מבקשה ראשונה לסביבת ייצור.

## מהי Claude API

Claude API היא פלטפורמת המפתחים של Anthropic. היא מספקת גישה תכנותית למודלים של Claude דרך Messages API, עם system prompts, שימוש בכלים, הזרמה, ראייה ופלט מובנה.

Messages API היא נקודת קצה של HTTP חסרת מצב. שולחים רשימת הודעות של משתמש ועוזר, מזהה מודל ומגבלת טוקנים; Claude מחזיר תשובה מובנית. נקודות קצה תומכות כוללות אצוות, קבצים וספירת טוקנים.

- **חסרת מצב:** ה-API אינו שומר זיכרון. יש לשלוח מחדש את היסטוריית השיחה בכל קריאה.
- **בחירת מודל:** מעבר בין מודלים כרוך בדרך כלל בשינוי מזהה המודל.
- **ערכות SDK:** הספריות הרשמיות ל-Python ‏(anthropic) ול-TypeScript ‏(@anthropic-ai/sdk) משתמשות במבני בקשות תואמים.

הבנת הארכיטקטורה הזו עוזרת להימנע מטעות נפוצה של מתחילים: ציפייה שה-API יזכור בקשה קודמת.

## שלב 1: קבלת מפתח והגדרת המסוף

עברו אל **console.anthropic.com**, צרו חשבון או ארגון לצוות שלכם והפיקו מפתח API באזור ההגדרות. התייחסו למפתח כמו לסיסמה: שמרו אותו במשתנה סביבה ולעולם אל תכניסו אותו לניהול קוד המקור.

קריאות HTTP ישירות משתמשות בכותרת **x-api-key** ובכותרת **anthropic-version**. ערכות ה-SDK קוראות אוטומטית את **ANTHROPIC_API_KEY** מהסביבה, ולכן רוב הקוד אינו מטפל במפתח ישירות.

- צרו מפתחות נפרדים לפיתוח, staging וייצור.
- השתמשו בסביבות עבודה כדי לבודד פרויקטים והוצאות של הצוות.
- הגדירו מגבלות שימוש במסוף לפני מסירת מפתחות לצוות רחב יותר.

## שלב 2: ביצוע קריאת Messages API ראשונה

התקינו את ה-SDK באמצעות **pip install anthropic**, ייצאו את המפתח והפעילו:

```
import anthropic

client = anthropic.Anthropic()
msg = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Explain REST in one paragraph."}],
)
for block in msg.content:
    if block.type == "text":
        print(block.text)
```

נדרשים שלושה פרמטרים: **model**, **max_tokens** (תקרת הפלט) ו-**messages**. התשובה מכילה רשימה של בלוקי תוכן. בדקו את הסוג של כל בלוק במקום להניח שמדובר בטקסט פשוט, כי שימוש בכלים ותהליך חשיבה עשויים להוסיף סוגי בלוקים אחרים. האובייקט **usage** מדווח על טוקני הקלט והפלט ויכול לשמש כטלמטריית עלויות.

## שלב 3: בחירת מודל

אלה דגמי Claude העדכניים של Anthropic ומזהי ה-API שלהם.

- **Claude Haiku 5.5** (**claude-haiku-5-5**) — מתואר כמהיר ובעלות נמוכה, לסיווג ולמשימות פשוטות בהיקף גדול.
- **Claude Sonnet 5.5** (**claude-sonnet-5-5**) — מתואר כאפשרות מאוזנת לעומסי עבודה בסביבת ייצור, כולל תכנות.
- **Claude Opus 5.5** (**claude-opus-5-5**) — מתואר למשימות חשיבה קשות ולעבודה סוכנית ארוכת טווח.
- **Claude Fable 5.2** (**claude-fable-5-2**) — מתואר כדגם הדגל למשימות חשיבה תובעניות.

התחילו עם Opus 5.5. נסו את Sonnet 5.5 לאיזון בין מהירות לאיכות, את Haiku 5.5 למשימות פשוטות בהיקף גדול ואת Fable 5.2 לחשיבה מורכבת. לעיון בתעריפים העדכניים, פנו לדף התמחור של Anthropic.

## חמשת המושגים הבאים שכדאי ללמוד

לאחר שהבקשה הראשונה פועלת, התכונות הבאות מכסות צרכים רבים של יישומים:

- **System prompts** — פרמטר **system** ברמה העליונה קובע תפקיד, סגנון וכללים, בנפרד מהודעות המשתמש.
- **שיחות מרובות תורות** — מוסיפים כל תשובת עוזר למערך messages ושולחים אותו מחדש; ההודעה הראשונה חייבת להיות תור של משתמש.
- **הזרמה** — אירועים הנשלחים מהשרת מוסרים טוקנים בזמן יצירתם, מה שיכול לעזור בממשקי צ'אט ובפלטים ארוכים.
- **ראייה** — מעבירים תמונות כבלוקי תוכן מסוג base64 או URL לצד טקסט.
- **שימוש בכלים** — מגדירים פונקציות באמצעות סכמות JSON; Claude יכול להחליט מתי לקרוא להן, בעוד שהקוד שלכם מבצע אותן ומחזיר תוצאות.

כשעלות חשובה, שקלו **שמירת prompts במטמון** ו**עיבוד באצוות**; כשקוד בהמשך צריך לנתח תשובה, שקלו **פלט מובנה**.

## ממדריך הפעלה לייצור

מעבר מסקריפט פועל לאינטגרציה בסביבת ייצור דורש משמעת הנדסית:

- **טיפול בשגיאות:** טפלו בנפרד בשגיאות הגבלת קצב (429) ובשגיאות שרת. המקור מציין שערכות ה-SDK מנסות לבצע אותן מחדש באופן אוטומטי עם השהיה מדורגת; בדקו את ההתנהגות הנוכחית בתיעוד של ה-SDK הרלוונטי.
- **נראות עלויות:** תעדו את **usage** מכל תשובה במערכת המדדים שלכם.
- **ניהול גרסאות של prompts:** התייחסו ל-prompts כמו לקוד: סקרו ונהלו להם גרסאות, ובדקו אותם מול מערך הערכה קטן.
- **קיבוע מודל:** הפנו למזהי מודלים מתוך התצורה כדי ששדרוגים יהיו מכוונים ונבדקים.

### נקודות עיקריות

- Messages API חסרת מצב; שלחו מחדש את היסטוריית השיחה בכל קריאה.
- אימות HTTP ישיר משתמש בכותרת x-api-key; ערכות SDK יכולות לקרוא את ANTHROPIC_API_KEY מהסביבה.
- שלושת פרמטרי הבקשה הנדרשים הם model, max_tokens ו-messages.
- התחילו עם Opus 5.5 והשוו בין החלופות על סמך הנתונים שלכם.
- System prompts, הזרמה, ראייה, שימוש בכלים והיסטוריה מרובת תורות תומכים בדפוסי יישום רבים.
- תעדו שימוש בטוקנים לצורך נראות עלויות ותכנון קיבולת.

## שאלות נפוצות

### האם צריך לדעת למידת מכונה כדי להשתמש ב-Claude API?

לא. Claude API היא REST API עם ערכות SDK רשמיות ל-Python ול-TypeScript. אם אתם יודעים לקרוא לנקודת קצה של HTTP ולנתח JSON, תוכלו לבנות עם Claude. תכנון prompts, טיפול בשגיאות וניהול עלויות הם כישורי הנדסה שימושיים; לא נדרשת תורת למידת מכונה כדי לבצע קריאת API ראשונה.

### באיזה מודל Claude כדאי למתחיל להתחיל?

Anthropic ממליצה להתחיל עם Claude Opus 5.5 (מזהה API ‏`claude-opus-5-5`) לרוב עומסי העבודה. אחרי שההנחיות שלכם מתייצבות, השוו את שאר המודלים על סמך הנתונים שלכם.

### האם Claude API זוכרת שיחות קודמות?

לא. Messages API חסרת מצב. היישום שלכם שומר את השיחה ושולח מחדש את כל היסטוריית ההודעות בכל בקשה. כך יש לכם שליטה בהקשר, אפשר לקצר או לסכם תורות ישנים ולשלב שמירת prompts במטמון.
