# LLM-as-a-Judge: Using AI to Evaluate AI (Reliably)

> How to use language models to evaluate AI outputs, account for judge bias, design rubrics, and calibrate automated scores against human judgments.



An LLM judge applies a written rubric to another AI response. It can help teams review large sets of answers, but its verdicts must be checked against examples assessed by people.

## Start with a task and a rubric

Choose one task, such as answering support questions from a supplied policy. Describe the expected behavior in observable terms. For example, check whether an answer follows the policy, addresses the question and avoids unsupported claims. A rubric should also say what to do when the evidence is missing.

Use separate criteria before producing an overall result. A response may be concise but inaccurate; a single score can hide that distinction. Keep the rubric and the judge model version alongside the results so that later comparisons have context.

## Choose a way to compare

For a pass/fail check, give the judge the question, the available evidence and one response. Ask for a decision on each criterion and a short explanation grounded in the supplied material. This works best when the criteria are specific enough for reviewers to apply consistently.

For a comparison, give the judge two responses to the same question and ask which better meets the rubric, allowing a tie. Run the comparison again with their order reversed. If the winner changes, flag the item for review rather than treating either result as settled. Remove unnecessary labels that reveal which system produced an answer.

A reference answer can help on a question with a known answer. For open-ended tasks, treat a reference as an example of acceptable quality, not as the only valid wording.

## Make results usable

Request a structured result with a decision and a short reason for each criterion. For example:

```json
{"policy_supported":{"result":"pass","reason":"The answer cites the supplied cancellation rule."},"addresses_question":{"result":"fail","reason":"It does not say how to cancel."}}
```

This is an illustration of a possible response, not evidence that a judge checked a real case. Validate the output before using it in a report; retry or send malformed results for review according to your workflow. A model's explanation is itself an output to inspect, not proof that its verdict is correct.

## Calibrate with people

Build a representative sample that includes straightforward cases, edge cases and known failures. Have reviewers apply the same rubric independently to an overlapping subset, discuss disagreements and record the decisions. Then compare the judge's results with those human labels, inspect where it disagrees and revise the rubric or workflow before relying on the metric.

Pay special attention to order, length and style. A polished or longer answer is not necessarily more accurate. Include concise correct answers and plausible incorrect ones in the sample. For pairwise tests, measure how often swapping the order changes the decision.

## Use the judge as one layer

Run deterministic checks first when they fit: for example, validate JSON or check a required field. Use the judge for criteria that require interpretation, and retain human review for uncertain or consequential cases. Track aggregate results on a stable dataset, but inspect individual failures too.

Recheck calibration when the model, rubric, task or input distribution changes. A higher score by itself does not establish an improvement: examine the responses and keep a separate evaluation set when the same automated metric is used to optimize a system.

## Practical checklist

1. Define the task, available evidence and criteria.
2. Collect examples and agree on human labels.
3. Select single-response or pairwise evaluation and specify a tie or uncertainty outcome.
4. Validate structured results and review disagreements.
5. Track versions and recalibrate after material changes.

For further guidance, see [OpenAI's evaluation best practices](https://platform.openai.com/docs/guides/evaluation-best-practices).
