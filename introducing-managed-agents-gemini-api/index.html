Présentation des agents gérés dans l’API Gemini

Une requête à un modèle de langage produit généralement une réponse ; un agent peut aussi effectuer des étapes intermédiaires pour atteindre un résultat. Il peut par exemple examiner des données, écrire et exécuter du code, puis produire un rapport. Les agents gérés de Google fournissent un espace de travail hébergé pour ce type de tâche via l'API Gemini. La fonctionnalité est en préversion : vérifiez la documentation et sa disponibilité actuelles avant de l'intégrer à un processus de production.

Ce guide explique comment choisir une première tâche, évaluer le résultat et prévoir les opérations nécessaires autour d'un agent géré. La documentation de l'API Gemini de Google présente les exemples de requêtes et les identifiants d'agents pris en charge actuellement.

Que gère le fournisseur ?

Dans cette approche, le fournisseur exploite l'environnement de l'agent et fournit les outils qu'il peut utiliser. Google décrit un bac à sable distant dans lequel son agent Antigravity peut manipuler des fichiers, exécuter du code et utiliser le Web. Votre application doit toujours définir l'objectif, fournir des entrées appropriées et décider si le résultat est acceptable.

Un environnement hébergé est utile lorsqu'une tâche nécessite plusieurs étapes et un espace de travail intermédiaire. Il ne remplace pas les décisions de votre application concernant les autorisations, la révision ou le traitement des données. Vérifiez les outils et paramètres disponibles pour votre projet et votre version avant de compter dessus.

Choisir une première tâche délimitée

Commencez par une tâche dont le résultat peut être vérifié sans se fier à l'explication de l'agent. Un petit résumé CSV est un bon exemple : fournissez un échantillon non sensible, demandez un tableau de totaux et précisez le format de sortie. Calculez quelques totaux indépendamment et comparez-les au résultat.

Une description utile comprend :

  • Les données d'entrée et le sens de chaque champ.
  • Le résultat attendu, par exemple un résumé et un fichier CSV.
  • Les règles applicables aux valeurs manquantes ou invalides.
  • Les limites des données et des outils accessibles à l'agent.
  • Les vérifications que le destinataire peut effectuer avant d'utiliser le résultat.

Par exemple : « Résume cet échantillon CSV de ventes par mois et par devise. Ne mélange pas les devises. Liste séparément les lignes sans date et fournis les calculs utilisés pour chaque total. » Lors du premier essai, évitez de lui demander d'envoyer des messages, de modifier des données de production ou d'effectuer d'autres actions externes.

Exécuter et examiner une interaction

Utilisez le guide de démarrage de Google pour configurer le SDK et les identifiants, puis suivez son exemple d'agent géré. Celui-ci fournit un identifiant d'agent, une entrée et un environnement distant. Utilisez l'identifiant documenté actuellement par Google sans supposer qu'un ancien identifiant de préversion est encore disponible.

Examinez davantage que le dernier paragraphe : vérifiez l'état renvoyé, la sortie et les fichiers que vous comptez utiliser. Pour une tâche de données, comparez les chiffres à la source ; pour un script généré, relisez-le et testez-le dans un environnement contrôlé. Si la tâche dépend d'informations du Web, ouvrez les sources citées et vérifiez qu'elles étayent les affirmations. Un résultat soigné peut tout de même contenir une erreur.

Si le travail se poursuit sur plusieurs interactions, suivez le cycle de vie des environnements et interactions documenté par Google. Conservez les identifiants utiles dans l'enregistrement de la tâche de votre application et gérez explicitement l'expiration ou l'échec ; ne supposez pas qu'un espace de travail persistera indéfiniment.

Donner des instructions claires à un agent personnalisé

Google documente aussi des moyens de fournir aux agents gérés des instructions, des compétences et des données personnalisées. Utilisez-les pour décrire la tâche et les exigences de sortie, sans incorporer de secrets dans un document. Pour un rapport, les instructions peuvent préciser comment regrouper les données, signaler l'incertitude et agir lorsqu'un calcul ne peut être terminé.

Placez les fichiers d'instructions sous gestion de versions et examinez leurs modifications comme du code applicatif. Testez une nouvelle version sur un petit ensemble d'entrées représentatives, dont des fichiers vides, des valeurs inattendues et une demande hors du périmètre prévu. Notez la version et l'entrée de chaque évaluation afin de pouvoir comprendre une modification du résultat.

Prévoir les coûts, la confidentialité et les échecs

Un agent à plusieurs étapes peut effectuer plusieurs appels au modèle ou utiliser des outils avant de renvoyer un résultat. Consultez la page des tarifs de Google et les limites de votre projet avant un essai : les frais et conditions de préversion peuvent changer. Mesurez l'utilisation sur des tâches représentatives et fixez un budget au niveau de l'application adapté à votre charge.

N'envoyez que les données dont le traitement est autorisé dans ce processus. Considérez les pages récupérées et les fichiers envoyés comme des entrées non fiables et examinez le code généré avant de l'exécuter hors du bac à sable. Définissez la conduite à tenir en cas de délai dépassé, d'échec d'un outil ou de résultat incomplet. Réessayer une tâche ayant des effets externes peut les répéter : vérifiez donc l'opération initiale avant une nouvelle tentative.

Quand utiliser un agent géré ?

Un agent géré mérite d'être évalué pour des recherches, analyses ou créations de fichiers bien délimitées, lorsque plusieurs étapes avec des outils sont utiles et qu'une personne ou un contrôle automatique peut vérifier le résultat. Une requête directe au modèle ou du code applicatif ordinaire peut être plus simple à exploiter pour une transformation unique et prévisible. Comparez les approches selon la qualité, la latence, le coût et le travail de vérification requis.
